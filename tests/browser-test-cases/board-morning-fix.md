# ブラウザテストケース: 盤の朝の固定（#767）

対象: SPA `web/src/routes/RaceBoard.tsx`（ルート `/races/:raceId/board`）。
API は `GET /api/races/{race_id}/board` の `fixed_selection`（朝の選定で固定した軸・相手・混戦と朝の時刻）。

検証環境: golden を複製した隔離 DB に #767 の migration を適用し、`morning_selections` に
2026-10-03 の朝の選定（`paddock-analyze reconstruct-slips` の朝の選定＝本番と同じ `pick_selection`）を入れた。
api-server をソースから `:8081` で隔離 DB に向け、vite（`PADDOCK_API_TARGET`）を `:5174` で起動し、
puppeteer-core（headless Chrome）で描画を検証した。

### 画面では確かめず見送ったもの

- オッズが無く朝の固定だけがあるとき: 到達しにくい（`race_odds` が空で朝の単勝のスナップショットだけある状態）
- 記録◎ だけの固定で記録◎ がライブの首位でないとき（#804）: 実データに例が無い（記録◎ はどれも 1 番人気）。隔離 DB に pad を 1 件入れれば作れるが、表示側の部品（頭数 null の非表示・「（朝）」の付かない混戦ラベル・記録軸チップ）は既存の経路なので画面では見送り、◎・◎勝率・頭数 null・書評を api-server の結合テスト `board_marks_the_recorded_axis_without_a_morning_selection` で確かめた
- オッズが無いとき（#804）: 朝の固定・記録◎ だけのどちらでも ◎ が固定の軸に付くことを結合テスト `board_marks_the_fixed_axis_without_odds` で確かめた。朝の軸が取消のときの ◎（ライブの首位へ戻る）は `board_comment_marks_scratched_morning_axis` に足した
