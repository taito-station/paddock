# ブラウザテストケース: 盤の手動ハンデ精査材料（#628）

対象: SPA `web/src/routes/board/HorseCard.tsx` / `HorseDetailPanel.tsx`（ルート `/races/:raceId/board`）。
API は `GET /api/races/{race_id}/board` の `group_venues` と `horses[].handicap`（[rest-api-read.md](../../docs/specifications/rest-api-read.md)）。

検証環境は Playwright MCP 不在のため **headless Chrome + puppeteer-core** で代替する（`reference_browser_test_fallback`）。
読み取り専用の検証なので隔離 DB は不要（共有 DB を read のみで参照する）。

**前提となる規律**: ここに出るのはすべて **decision-support の事実**であって go/no-go サインではない
（ADR 0055 / 0060 / 0076 / 0079）。バッジが「買い」を意味するように見えていないか、を毎ケースで見る。

---

### TC-01: 条件別実績が全頭カードに出る（最優先要件）
| 項目 | 内容 |
|------|------|
| 前提 | 適性が支配的な条件のレース。基準データ: 2026-08-16 新潟6R 稲妻S（`2026-2-niigata-8-6R`・芝1000＝千直） |
| 画面 | `/races/2026-2-niigata-8-6R/board?date=2026-08-16` |
| 操作 | 画面を開き、全 13 頭のカードを横に見る |
| 期待結果 | 各カードに `N走 着順列` の 1 行が出る。⑧カウスリップ=`2走 3,3着` / ⑥ベイビーキッス=`6走 12,9,1,4,3着…` / ⑩クールベイビー=`9走 1,16,2,14,3着…` / ⑪モーデン=`該当なし` |
| 確認ポイント | **0 走が空欄でなく「該当なし」**であること（空欄は「まだ引いていない」に見える）。着順は新しい順。5 件超は `…` で省略され、**走数は省略されない**（母数が消えない） |

### TC-02: 着順列が折り返してもカードがガタつかない
| 項目 | 内容 |
|------|------|
| 前提 | TC-01 と同じレース（③スコーピオン 7 走・⑩クールベイビー 9 走が 2 行に折り返す） |
| 画面 | 同上 |
| 操作 | カード帯のスクリーンショットを撮り、各カードの「書評」チップの縦位置を比べる |
| 期待結果 | 条件別実績が 1 行の馬も 2 行の馬も、下段のバッジ行（間隔◯日 / 書評）の縦位置が揃う |
| 確認ポイント | `.cond-record` の `min-height` で 2 行ぶんを常に確保していること。横並び比較が崩れると本機能の目的（人気馬同士の条件実績を見比べる）が果たせない |

### TC-03: 差pt と戦績欠損フラグが並んで読める
| 項目 | 内容 |
|------|------|
| 前提 | 過去走が 0 件の馬（地方所属の初 JRA 参戦馬など）を含むレース。基準: 2026-08-15 札幌9R コスモス賞 ④キャトルブランシュ（純モデル 10.4% vs 市場 1.1%） |
| 画面 | 当該レースの盤 |
| 操作 | 該当馬のカードの `差` 行とバッジ行を見る |
| 期待結果 | `差 +9.3pt`（`市勝` の直下）と、赤系の `戦績なし` チップが同じカードに出る |
| 確認ポイント | **差pt だけを見て妙味と誤読できない配置**であること。`戦績なし` チップが妙味チップ（黄系）と別色で、取り違えないこと。市場 implied 未取得（単勝未発売）の馬は `差 -` になる |

### TC-03b: モデル列を畳んでも戦績欠損フラグは消えない
| 項目 | 内容 |
|------|------|
| 前提 | TC-03 と同じレース |
| 画面 | 当該レースの盤 |
| 操作 | 「モデル値（純 α=1.0）を表示」のチェックを外す |
| 期待結果 | `モ勝`/`モ連`/`モ複` と `差` 行は畳まれるが、`戦績なし` チップは**残る** |
| 確認ポイント | 欠損はモデル列の表示可否と直交する事実。トグル操作だけで「この馬の確率は欠損由来」という警告が消えてはいけない |

### TC-04: 前提が壊れているサインは上位人気だけに出る
| 項目 | 内容 |
|------|------|
| 前提 | 休養明けが長い / 今回距離が未経験 / 今回の芝ダが未経験 の馬を含むレース（例: 2026-08-16 中京記念 ⑫サトノシャイニング＝10ヶ月半の休養明け・マイル未経験） |
| 画面 | 当該レースの盤 |
| 操作 | 1〜3 番人気のカードと、4 番人気以下のカードを見比べる |
| 期待結果 | `間隔◯日` / `距離初` / `芝ダ初` のチップが **1〜3 番人気にだけ**出る。4 番人気以下には出ない |
| 確認ポイント | **日数がそのまま出ており「久々」等の判定語になっていない**こと（10ヶ月半と 4ヶ月半は質が違い、読み分けは人間がやる）。単勝未取得で人気が付かない馬には出ないこと |

### TC-05: 書評パネルに内訳が出る
| 項目 | 内容 |
|------|------|
| 前提 | TC-01 と同じレース |
| 画面 | 同上 |
| 操作 | ⑥ベイビーキッスのカードをクリックして書評パネルを開く |
| 期待結果 | 既存の根拠 bullet の下に `新潟芝1000m` 見出しと過去走が `YYYY-MM-DD N着 レース名` で全件（省略なし）並ぶ。`2026-05-24 12着 韋駄天S(OP)` が含まれる。続いて `前走からの間隔 29日`、`今回条件の経験 今回距離の経験あり / 今回の芝ダの経験あり` |
| 確認ポイント | カードは 5 件で省略されるが**パネルは全件**であること。レース名が無い過去走（PDF 経路）は日付と着順だけで表示が壊れないこと |

### TC-06: 洋芝（札幌⇄函館）は別ラベルで併記される
| 項目 | 内容 |
|------|------|
| 前提 | 札幌または函館の芝レース。基準: 2026-08-16 札幌7R（`2026-1-sapporo-8-7R`・芝2000）。⑦は当場 0 走／洋芝 3 走 |
| 画面 | `/races/2026-1-sapporo-8-7R/board?date=2026-08-16` |
| 操作 | ⑦のカードをクリックして書評パネルを開く |
| 期待結果 | パネルに 2 ブロックが出る: `札幌芝2000m` → `該当なし`、`洋芝(札幌/函館)芝2000m` → 該当 3 走 |
| 確認ポイント | **完全一致と洋芝を黙って混ぜていない**（事実が違うので行を分ける）。カードの 1 行要約は完全一致（`該当なし`）のままで、洋芝で水増しされないこと |

### TC-07: 洋芝以外の場ではグループ行を出さない
| 項目 | 内容 |
|------|------|
| 前提 | 新潟・東京など洋芝以外の場のレース（TC-01 と同じ） |
| 画面 | 同上 |
| 操作 | 任意の馬の書評パネルを開く |
| 期待結果 | 条件ブロックは `新潟芝1000m` の 1 本だけ。グループ行は出ない |
| 確認ポイント | API の `group_venues` が空配列であること（グループが当場のみ＝完全一致と同じ集合なので 2 行目に情報が無い） |

### TC-07b: ダート戦では洋芝グループを出さない
| 項目 | 内容 |
|------|------|
| 前提 | 札幌または函館の**ダート**レース。基準: 2026-08-16 札幌8R（`2026-1-sapporo-8-8R`・ダ1700） |
| 画面 | `/races/2026-1-sapporo-8-8R/board?date=2026-08-16` |
| 操作 | 任意の馬の書評パネルを開き、API の `group_venues` も確認する |
| 期待結果 | 条件ブロックは `札幌ダ1700m` の 1 本だけ。`洋芝(札幌/函館)ダ1700m` は**出ない**。`group_venues` は空配列 |
| 確認ポイント | 洋芝の根拠は「**芝の**適性が通じる」なので、同じ 2 場でもダートでは束ねない。実測では gate 前、当該開催のダート 23 頭中 11 頭で偽のグループ行が出ていた |

### TC-07c: 「書評」チップは書評のある馬だけに出る
| 項目 | 内容 |
|------|------|
| 前提 | 任意のレースの盤 |
| 画面 | 同上 |
| 操作 | 全頭カードのバッジ行を見る |
| 期待結果 | `書評` チップは人手短評または根拠 bullet を持つ馬にだけ出る（全頭には出ない）。一方、条件別実績しか無い馬も**クリックで詳細パネルは開ける** |
| 確認ポイント | パネルを開ける条件（材料の有無）とチップの意味（書評の有無）が別物であること。チップまで全頭に出すと「書評がある」という信号が消える |

### TC-08: 凡例に記号の意味が載っている
| 項目 | 内容 |
|------|------|
| 前提 | 任意のレースの盤 |
| 画面 | 盤下部の「記号の凡例」 |
| 操作 | 折りたたみを開く |
| 期待結果 | `差 / 近走なし`、`{条件ラベル} の行`、`間隔◯日 / 距離初 / 芝ダ初` の 3 項目が追加されている |
| 確認ポイント | 凡例が**「事実であって go/no-go ではない」旨を明記**していること（タッチ端末は title が読めないため凡例が唯一の説明経路）。洋芝場のときだけグループ行の説明が出ること |

### TC-09: 画面エラーが出ない
| 項目 | 内容 |
|------|------|
| 前提 | 上記いずれのレースでも |
| 画面 | 盤 |
| 操作 | ページ読み込み〜パネル開閉まで console と HTTP を監視 |

| 確認ポイント | `/api/races/{id}/board` が 200 で `group_venues` と `horses[].handicap` を含むこと |
