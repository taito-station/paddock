# #745 馬場不明のレースを良として数えない修正の実測ログ（2026-09-30）

`scripts/harness/pl_features.py` が、馬場（`races.track_condition`）の空なレースを良として数えていた問題の修正（#745）について、
dev 窓で測った記録（一次資料）。
蒸留先: `knowledge/learned-model-harness.md`（決定ログ #745）。方針の確認は `qa/QA-unknown-going-745.md`。

## 調査時点の所見（修正前のコード）

- `_going_heavy(cond)` は `cond in {"稍重", "重", "不良"}` だった。空の馬場（抽出 SQL の `COALESCE(r.track_condition, '')`）は
  `False`＝良になる。影響するのは次の 3 か所。
  - 当日レースの `going_apt`
  - 過去走の重馬場フラグ（適性の条件）
  - 走破タイムの基準（コース × 馬場）の細かいキー
- 共有 DB の `races.track_condition` の内訳（2026-09-30・読み取り専用）: 良 3,626 / 稍重 844 / 重 284 / 不良 72 / NULL 683。
  - test 窓（2026-01-01〜08-31）の NULL は 621R。うち 439R は #721 で取り込んだ 2026-06〜08 のレース
    （取り込んだ 457R は全て 2026-06〜09 で、馬場は NULL）。

## 修正

- `_going_heavy` は、重なら True・良なら False・それ以外（空）なら None（馬場不明）を返す。
- 当日の馬場が不明なら、`going_apt` は 0（データなしと同じ中立値）にする。
- 馬場不明の過去走は、良・重どちらの適性の条件にも入れない。
- 走破タイムの基準では、馬場不明の走は細かいキー（馬場別）に入れず、馬場を区別しない粗いキー（コース）にだけ入れる。
  馬場不明の過去走の速度 z は、粗いキーの基準で測る。
- 基準の集計は日付だけで並べる（細かいキーに None が入るので、タプル全体の比較をやめた）。

## テスト（RED → GREEN・変異）

- 追加したテスト（`scripts/harness/test_pl_features.py`）: 当日不明なら中立 / 不明の過去走を良の適性に数えない /
  不明の走破タイムを良の基準に混ぜない（同日に並ぶ場合を含む）/ 不明の走は馬場を区別しない基準で測る（別コースの不明どうしを
  1 つの基準にまとめない）。
- 修正前のコードで 4 本とも失敗（RED）。修正後、CI と同じピンの venv で `test_pl_features.py`・`test_train_pl_topk.py` の 40 本が通過。
- 変異 5 本（中立化を外す・不明を良に戻す・基準の None 除外を外す・修正前の `fine[:3]` に戻す・並べ替えをタプル比較に戻す）は
  全てテストが検出した。
