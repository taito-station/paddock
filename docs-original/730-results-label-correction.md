# #730 results の着順を netkeiba で補正した実測ログ（2026-09-27〜29）

`results`（2025-01-01〜2026-08-31・5,052R）の着順を netkeiba のレース結果で補正したときの実測ログ（一次資料）。
蒸留先: `knowledge/race-result-ingestion.md`（決定ログ #730）・`knowledge/feature-resolution-diagnosis.md`（ADR 0091 からの相互参照）。

## 背景

- ADR 0091（#663）で、PDF の着順は EdiF フォントの欠落で +1〜+5 着ずれていると分かり、特徴量の読み出しだけを
  netkeiba 優先に倒した。`results` テーブルの着順自体はずれたまま残っていた。
- #720 の着手前調査（2026-09-27）で、この汚れが dump の正解ラベル・馬の成績集計・#719 の ledger 基準値に入っていると判明した。

## 手順

1. 退避: Lima VM 内のコンテナの pg_dump で `~/paddock-backups/paddock-20260927-200254-pre730.dump`（58MB・TABLE DATA 20 件を確認）。
   日次バックアップはこの時点で 8/27 から止まっていた（#731 で修正）。
2. `paddock-fetch-results --from 2025-01-01 --to 2026-08-31 --interval 3000` で既存行を netkeiba の値で UPDATE
   （途中でディスク残量不足により 1 回停止し、最初から再実行）。結果: 成功 5,052 / 失敗 0・更新 70,176 行。
   netkeiba の馬番が DB に無く一部だけ更新されたレースが 16 本（警告ログ）。
3. 着順の重複が 2 → 235 レースに増えたので調べた。原因は 2 つ。
   - **PDF 由来のゴミ行**（馬名が `―1：57.7 374.4�` のような化けた文字列）が 967 行あり、netkeiba の結果に無い馬番の行は
     上書きされず PDF 時代の着順が残って重複していた。
   - 残りは**本物の同着**（「3 着・3 着・5 着」のように、同着の後で着順が飛ぶ JRA の表記どおり）。PDF は同着を表せていなかった。
4. ゴミ行 967 行を含む 556 レースの結果ページを netkeiba から取得し、馬番で突き合わせて分類した。
   - **rename 833 行**: netkeiba に同じ馬番がある＝実在馬の名前が化けた行。着順は手順 2 で netkeiba の値になっており、
     全行で netkeiba の着順と一致した。馬名を netkeiba の名前に直した。
   - **scratch 134 行**: netkeiba に同じ馬番が無い＝余分な行。`status='scratched'`・着順を空にした（行は消さない）。
   - 分類時の落とし穴: 結果ページには馬名の無い行が混ざり、馬番の列を誤読して本物の行（勝ち馬など）を上書きしていた。
     馬名のある行だけを使うように直してから分類した。
   - 更新 SQL は「race_id・馬番・今の化けた馬名が一致する行」だけを対象にした（1 トランザクション）。

## 本番構成の backtest（`--blend-alpha 0.2 --shrinkage-m 10 --win-power 1.25 --place-show-power 2.0 --impute-missing-factors`・5,052R）

| 指標 | 補正前（dac050e） | 補正後（76ab764） |
|---|---|---|
| 単勝 Brier / LogLoss | 0.0545 / 0.1960 | 0.0575 / 0.2045 |
| 連対 Brier / LogLoss | 0.1043 / 0.3529 | 0.1082 / 0.3623 |
| 複勝 Brier / LogLoss | 0.1449 / 0.4574 | 0.1493 / 0.4675 |
| 単勝・連対・複勝の的中率 | 31.4% / 51.0% / 64.0% | 32.9% / 52.8% / 65.6% |
| 想定回収率 | 82.1% | 84.4% |

- 全レースでの Brier の悪化は、主に**正解ラベルの変化による見かけの差**。補正前は勝ち馬のいないレースが 297 本あり、
  そこは全馬 y=0 で採点されて Brier が低く出ていた（補正後は 0 本）。
- 両方で勝ち馬が一意の共通 4,749 レース（勝ち馬が同じ 4,745 本）で比べると、単勝 Brier 0.05759 → 0.05784、
  **ΔBrier = +0.000249（95% CI [+0.000135, +0.000373]・レース単位ブートストラップ 1,000 回）**、1 着的中 33.4% → 33.1%。
  ラベルはほぼ同じなので、この差は予測側（馬の成績集計が正しいデータになった・化けた馬名の 833 頭の履歴がつながった）から来る。
  有意だが小さい（相対 0.4%）。

## #719 ledger（v1）

補正後の dump で baseline を取り直した（`docs-original/719-prob-ledger.md` の「v1 baseline」）。
test 窓（2026-01〜08）の馬連 NLL 4.206（v0.2 と同じ）・連対 log-loss 0.386（v0.2 は 0.390）・単勝 NLL 2.475。
券種別の除外は「着順欠落」が 0 になり、同着が数件（単勝 1 / 馬連・連対 5 / ワイド・3連複 10）と頭数不足 12 だけになった。

## 残る事項

- 行数が馬番の最大値より少ないレース（dev 81R・test 91R）は、取消・除外の馬が `results` に行を持たないためと考えられる（未確認）。
- dump に 1 頭分しか行が無いレース 12 本（2026-07-18 / 08-02 / 08-09）は残っている（頭数不足で評価から除外）。
- 2025 年より前の `results` は無い。
