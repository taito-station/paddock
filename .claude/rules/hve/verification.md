# 検証必須

成果物は検証を経て初めて完了とする。自己申告ではなく、実行結果で証明する。

## 5 段階検証パイプライン

コードを伴う成果物には以下を順に適用する:

1. **Build**: 構文エラー・コンパイルエラーがないこと
2. **Lint**: 静的解析で警告がないこと
3. **Test**: テストが全て通ること
4. **Security**: 秘密情報（鍵・トークン・個人情報・内部 URL）が含まれていないこと
5. **Diff**: 変更差分が意図通りであること

## 設計成果物の検証

設計ドキュメントの場合:

- ID の一意性（UC-*, APP-*, SVC-* 等が重複していないか）
- 参照整合性（他カタログへの ID 参照が実在するか）
- 必須セクションの充足（テンプレートで定義されたセクションが全て存在するか）
- 出典の実在性（引用元ファイル・見出しが存在するか）

## TDD の RED/GREEN

- RED（失敗）と GREEN（成功）は実際のコマンド出力で証明する
- 恒真式アサーション（`count >= 0` のような常に真の主張）は禁止
- 「利用可能」と「実在」を混同しない
