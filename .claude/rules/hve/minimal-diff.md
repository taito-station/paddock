# 最小差分原則

変更は目的達成に直接必要な最小範囲に限定する。

## ルール

- 無関係なフォーマット変更・一括リファクタ・コメント追加をしない
- 対象外のファイルを触らない
- 既存の構造・命名を維持する（改善が目的でない限り）
- 変更前に `git diff --stat` 相当でスコープを確認し、無関係な変更を検出する

## 設計成果物への適用

- 既存の成果物を更新する際は差分マージ（全面書き換えしない）
- カタログの既存行を不要に並び替えない
- 他ステップの成果物を勝手に修正しない

## 優先順位

捏造禁止 > オーバーエンジニアリング禁止 > **最小差分原則**
