# 実装フロー規約

実装タスク（feat / fix / refactor）に適用するゲートベースのフロー。
コードを書く前に探索・ギャップ分析・テスト設計を義務化し、実装後に knowledge 同期を行う。

CLAUDE.md の「進め方」「knowledge 参照・更新の規律」を構造化・強制する上位規約。

## 適用条件

以下のいずれかに該当するタスク:
- 新機能の追加
- バグ修正
- リファクタリング
- 既存機能の改修

以下は対象外:
- ドキュメントのみの変更
- 設定変更のみ
- 依存更新のみ

## ゲートフロー

```
Step 1: 探索
  ├─ 棄却済み案と衝突 → STOP: 人間に報告
  ├─ 既存実装と矛盾 → STOP: 人間に報告
  └─ OK → Step 2

Step 2: ギャップ分析
  ├─ ブロッキングな不明点あり → Step 3
  ├─ 軽微な不明点のみ → 前提を明示して Step 4 へ
  └─ ギャップなし → Step 4

Step 3: 質問票 → 人間回答
  ├─ 回答がアプローチを変える → Step 1 に戻る（最大 2 周）
  ├─ 回答で新たな不明点 → Step 2 に戻る
  └─ 解消 → Step 4

Step 4: テスト設計
  ├─ 受入基準不明確 → Step 3 に戻る（最大 2 周）
  └─ OK → Step 5

Step 5: 実装
  ├─ テスト失敗 × 3 回 → STOP: アプローチ破綻を人間に報告
  ├─ 影響範囲が想定超 → STOP: impl-sonnet → メインループ引き取り
  └─ テスト通過 → Step 6

Step 6: AKM 同期
  ├─ knowledge 更新で矛盾 → STOP: Conflict 宣言、人間判断
  └─ OK → 完了（→ create-pr で PR 作成）
```

## 各ゲートの義務

### Step 1: 探索（コードを書く前に）

- 関連する knowledge / specifications / 決定ログを検索する
- 関連するコードの構造・依存関係を把握する
- 棄却済みの代替案（決定ログの「却下した代替案」）と衝突しないか確認する
- 検索ツールはプロジェクトの探索規律に従う（mdq / cq / serena 等）

### Step 2: ギャップ分析

- Step 1 の探索結果を踏まえ、実装に必要だが不足している情報を特定する
- 不明点を「ブロッキング」（回答なしでは進めない）と「軽微」（前提を置いて進める）に分類する

### Step 3: 質問票

- ブロッキングな不明点を質問票としてユーザーに提示する
- 各質問に推奨解と理由を添える（CLAUDE.md「進め方」準拠）
- 回答がアプローチを根本的に変える場合は Step 1 に戻る（最大 2 周）

### Step 4: テスト設計

- 受入基準を明確にしてからテストを書く（テストファースト）
- 受入基準が不明確な場合は Step 3 に戻る（最大 2 周）

### Step 5: 実装

- テストを通すことで実装の正しさを証明する
- 同一テストが 3 回連続失敗したら STOP しアプローチの破綻を報告する
- 影響範囲が当初の想定を超えた場合は STOP し報告する
- impl-sonnet 委譲中に影響範囲超過が判明した場合はメインループが引き取る（モデル使い分け規約に準ず）

### Step 6: AKM 同期

- 実装で確定知の前提が変わったら knowledge を同じ PR で更新する
- 決定を伴う変更は決定ログに同じ PR で append する
- knowledge 更新で矛盾が生じたら `status: Conflict` を宣言し人間に報告する

### PR 作成

- create-pr スキルを使って PR を作成する

## ループ制限

| ループ | 上限 | 超過時 |
|---|---|---|
| Step 1 → Step 3 | 2 周 | STOP: 探索しても解消しない不明点がある旨を報告 |
| Step 3 → Step 2 | 回答ごとに 1 回 | 新たな不明点が連鎖する場合は STOP |
| Step 4 → Step 3 | 2 周 | STOP: 受入基準が策定できない旨を報告 |
| Step 5 テスト失敗 | 同一テスト 3 回 | STOP: アプローチの破綻を報告 |

## STOP 時の報告

STOP に到達した場合、以下を明示して停止する（黙って続行しない）:

1. どのゲートで停止したか
2. 停止理由（衝突内容・不明点・失敗内容）
3. 試みたこと
4. 推奨する次のアクション
