# Step 3.3: ユースケースカタログ統合（join）

## このステップの目的

Step 3.2 の全 fan-out 子タスクの出力（各ユースケースの詳細仕様）を統合し、
最終成果物である **ユースケースカタログ** を生成する。

## 入力

- `docs/usecase/*-detail.md`（Step 3.2 の全 fan-out 子出力を **すべて** 読む）
- `docs/catalog/use-case-skeleton.md`（Step 3.1 出力。ID 順序の根拠とする）

## 出力

- `docs/catalog/use-case-catalog.md`

## 実行手順

1. `docs/usecase/*-detail.md` を全件読み込む。
2. `docs/catalog/use-case-skeleton.md` の並び順を根拠に、全 UC を ID 順に統合する。
3. 優先度別（P0/P1/P2）の件数集計を行う。
4. 「主要アクター × 主要トリガー」のカバレッジを簡易チェックし、空白（未カバー）があれば明記する。
5. 統合時に発見した重複・矛盾・粒度の揺れがあれば、統合レポート上で指摘する（元の per-UC ファイルは変更しない）。

## 出力フォーマット

`docs/catalog/use-case-catalog.md` に以下を含める。

1. **Use Case Catalog** — 全 UC を ID 順に統合した表（Step 3.2 の詳細項目 1〜8 を列として保持）
2. **優先度別集計** — P0/P1/P2 の件数
3. **Coverage Check（簡易）** — 主要アクター × 主要トリガーの一覧と対応 UC-ID、未カバー項目の明記

不明・推論項目は `TBD` / `要確認` と明示する。

## 重要な注意事項

- 全 `UC-*` のエントリを網羅すること。
- **捏造禁止**: ID・URL・固有名・数値・事実を根拠なく作らない。不明・未確認は `TBD` / `要確認` と明示する。
- **オーバーエンジニアリング禁止**: 指示・要件にない汎用化・抽象化・将来拡張の先回りを行わない。YAGNI に従う。
