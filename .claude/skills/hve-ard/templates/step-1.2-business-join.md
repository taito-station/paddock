# Step 1.2: 事業分析統合（join）

## このステップの目的

Step 1.1 の全 fan-out 子タスクの出力（各事業候補の深掘り分析）を統合し、
経営陣向けの **企業全体の事業要件文書** を作成する。本ステップで初めて、全社レベルの
As-Is / To-Be / Gap / Strategic Recommendations を含む完全なレポートを出力する。

## 入力

- `docs/business/*-analysis.md`（Step 1.1 の全 fan-out 子出力を **すべて** 読む）
- `docs/company-business-recommendation.md`（Step 1 出力）

## 出力

- `docs/company-business-requirement.md`

## 実行手順

1. `docs/business/*-analysis.md` を全件読み込み、各事業（`BIZ-NN`）の分析結果を把握する。
2. 事業横断のシナジー・コンフリクトを分析する。
3. 企業全体として、以下の章立てでレポートを作成する（各章冒頭で「実施目的」「主なインプット」を 1 行で明示する）。
4. 事実・分析・示唆・仮説を明確に分ける。都合のよい記述だけでなく構造的課題・競争劣位・リスクも明記する。
5. 不明な点は推測で埋めず、`TBD` / `要確認` と明示する。

## 出力フォーマット

`docs/company-business-requirement.md` を以下の章立てで作成する。

1. **Executive Summary** — 分析目的と背景、主要示唆（3〜7 点、根拠付き表形式）、戦略方向性オプション概要（短期・中期・長期）
2. **Company Overview** — 企業基本情報（表）、事業領域と主要製品・サービス、経営理念・ビジョン、過去 `{survey_period_years}` 年間の事業変遷
3. **As-Is Analysis** — 外部環境分析（PEST / Porter's 5 Forces）、内部環境分析（リソース・ケイパビリティ / 財務分析）、各 `BIZ-NN` を含む事業ポートフォリオ分析、競合分析、SWOT 分析、主要課題（3〜7 点、優先度付き表形式）
4. **To-Be Vision** — 中長期的な成長ビジョン、戦略的方向性（表）、今後深掘りすべき有望事業領域
5. **Gap Analysis** — As-Is と To-Be の差分（領域別テーブル）
6. **Strategic Recommendations** — 推奨戦略（3〜5 個、根拠付き）、実行ロードマップ（短期/中期/長期）、KPI とモニタリング体制
7. **Appendix** — 使用データソース、分析上の制約、使用フレームワーク

各 `BIZ-NN` のサマリーをレポート中に含め、根拠不足の場合は件数を水増ししない。
不明・推論項目は `TBD` / `要確認` と明示する。

## 重要な注意事項

- 全 `BIZ-NN` のサマリーを網羅すること。
- **捏造禁止**: ID・URL・固有名・数値・事実を根拠なく作らない。不明・未確認は `TBD` / `要確認` と明示する。
- **オーバーエンジニアリング禁止**: 指示・要件にない汎用化・抽象化・将来拡張の先回りを行わない。YAGNI に従う。
