# Step 2: ターゲット事業分析

## このステップの目的

対象事業・業務があらかじめ指定されている前提で、その事業・業務に限定した
As-Is / To-Be / Gap / Strategic Recommendations の分析を行い、経営層が意思決定に使える
水準の事業・業務分析レポートを作成する。

`target_business` が指定されている場合、Step 1 / 1.1 / 1.2 を実行せず本ステップから開始してよい。

## 入力

- 対象企業名: `{company_name}`（任意。Step 1 系を実行しない場合は未指定でもよい）
- 分析対象事業・業務名: `{target_business}`（必須。文章での説明、または対象資料のフォルダ/ファイルパス）
- 分析対象の範囲: `{target_region}`（任意。例: `国内事業のみ`, `海外含む`, `営業プロセス全体`）
- 分析期間: `{survey_period_years}` 年（任意）
- 分析目的: `{analysis_purpose}`（任意。例: `収益性改善`, `新規事業検討`）
- 添付資料: `{attached_docs}`（任意。**指定がある場合は一次情報として最優先で参照する**）
- `docs/company-business-requirement.md`（任意・参考。Step 1.2 が先行実行されている場合のみ補助コンテキストとして参照する。添付資料・指定資料を一次情報として優先する）

## 出力

- `docs/business-requirement.md`（Step 1.2 出力 `docs/company-business-requirement.md` とは別ファイル）

## 実行手順

トップティア戦略コンサルティングファームのシニアパートナーとして、対象事業・業務 `{target_business}`
（企業: `{company_name}`）を分析する。

1. 添付資料・指定資料がある場合は一次情報として最優先で参照する。記載のある事実は必ずその内容を優先し、
   記載が無い情報は「資料上確認できる事実」「外部情報に基づく補足」「合理的な仮説」「追加確認が必要な論点」
   のいずれかに分類する。不明な情報を断定しない。
2. 対象事業・業務の定義（目的・提供価値・顧客/利用者・主要プロセス・関連部門）を整理する。
3. As-Is 分析: 外部環境（PEST / Porter's 5 Forces、対象が特定業務の場合は一般論に広げすぎず絞り込む）、
   内部環境（業務プロセス・組織・人材・IT/データ・財務・KPI 管理）、SWOT 分析。
4. 課題抽出: 現象ではなく根本原因まで掘り下げ、優先度（高/中/低、理由付き）を付ける。
5. To-Be Vision: 中長期的に目指す姿を、抽象論に留めず経営・業務上の意思決定に使える具体性で定義する。
6. Gap 分析: As-Is と To-Be の差分を領域別に整理する。
7. 戦略オプションを複数提示し、期待効果・実行難易度・必要投資・リスク・優先度で評価する。
8. Strategic Recommendations: 推奨戦略・理由・解決する課題・期待価値・実行ステップ（短期/中期/長期）・
   必要リソース・主要 KPI・リスクと対応策を記述する。

## 出力フォーマット

`docs/business-requirement.md` を以下の章立てで作成する。

1. **Executive Summary** — 分析対象と目的、主要な結論、最重要課題、推奨アクション、期待されるビジネス価値
2. **Analysis Scope and Methodology** — 分析対象の定義、使用資料・データ、分析範囲、分析アプローチ、前提条件・制約
3. **Business / Operation Overview** — 概要、企業内での位置づけ、顧客/利用者、提供価値、主要プロセス
4. **As-Is Analysis** — 外部環境分析、内部環境分析、競合・ベンチマーク分析、SWOT 分析
5. **Key Issues** — 主要課題一覧、根本原因分析、影響、優先順位
6. **To-Be Vision** — あるべき姿、戦略的方向性、目指す業務・組織・システム像
7. **Gap Analysis** — As-Is と To-Be の差分、原因、必要な変革テーマ、優先度
8. **Strategic Options** — 戦略オプションと評価、推奨オプションの選定理由
9. **Strategic Recommendations** — 推奨戦略、実行ロードマップ（短期/中期/長期の表）、必要リソース、KPI、
   ガバナンス体制、リスクと対応策
10. **Appendix** — 使用データ・資料、分析上の前提、追加確認が必要な論点、使用フレームワークの説明

重要な示唆は太字で強調する。事実・解釈・仮説を明確に区別する。一般論ではなく `{target_business}` に
即した分析にする。最後に「追加で確認すべき情報」を箇条書きで提示する。

## 重要な注意事項

- As-Is・課題・To-Be・Gap・施策が論理的につながっていること。
- 課題は表層的でなく根本原因まで掘り下げること。
- **捏造禁止**: ID・URL・固有名・数値・事実を根拠なく作らない。不明・未確認は `TBD` / `要確認` と明示する。
- **オーバーエンジニアリング禁止**: 指示・要件にない汎用化・抽象化・将来拡張の先回りを行わない。YAGNI に従う。
