# Step 4.1: アプリケーションリスト作成

## このステップの目的

ユースケースカタログから、実装手段（新規アプリ導入／既存アプリ拡張／連携／業務改革／組織改革）を仕分け、
複数 UC を束ねて実装できる「アプリケーションリスト（アーキタイプ単位）」と、P0 を優先した
最小ポートフォリオ（MVP）を選出する。**製品名（ベンダ/OSS）の推薦は行わない**（アーキタイプ止まり）。

## 入力

- `docs/catalog/use-case-catalog.md`
- `docs/recommended-kpi-okr.md`（Step 2.1 出力。**任意**。存在する場合のみ APP と KPI/OKR の紐付けを行う）

## 出力

- `docs/catalog/app-catalog.md`

## 用語

- **SoR (System of Record)**: データの正の記録を持つシステム
- **アーキタイプ**: 製品名ではないアプリ種別（例: CDP、ロイヤルティ台帳、iPaaS、監査ログ基盤 等）
- **実装手段（A〜E）**
  - A: 新規アプリ導入（Buy/Build 含む）
  - B: 既存アプリ拡張（設定・軽微開発）
  - C: 連携（外部 SoR 責務が主で「つなぐ」）
  - D: 業務改革（プロセス／ルールが本体）
  - E: 組織改革（体制／役割／スキルが本体）
- **カバレッジ（R/S/N）**: R = Primary 責務（原則 1 つ）、S = Secondary（補助・連携）、N = 対象外

## 実行手順（順序固定）

1. **Ingest**: `docs/catalog/use-case-catalog.md` から UC を抽出・構造化する。
2. **QC**: Out of Scope の混入・粒度・重複・欠損・優先度を整流する（削除せずフラグ化）。
3. **A〜E 分類**: 各 UC に実装手段・根拠・仮定・リスクを付与する。D/E はアプリリストから除外し
   「業務・組織バックログ」へ回す。
4. **Capability 化**: UC を動詞命名の Capability にまとめる（各 UC に Primary 必須、Secondary 任意。
   目安として Capability 数は UC 数の 1/3〜1/2）。
5. **SoR/境界定義**: 各 Capability の SoR、書込権限、同期方式（event/api/batch/TBD）を定義する。
   SoR は安易に増やさない（二重台帳回避）。
6. **アプリクラスタリング**: Capability を束ねてアプリ（アーキタイプ）を定義する。
   - 束ねる条件: 同一 SoR / 同一オーナー / 近い SLA / 同一監査境界
   - 分離する条件: PII/同意/監査の独立保全、会計/BI 境界、極端な遅延差
7. **カバレッジ行列**: UC × アプリ候補を R/S/N で整理する（各 UC の R は原則 1 つ）。
8. **MVP 選出**: P0 を全カバーする最小集合を、P0 優先 → 追加コスト最小 → 依存最小の順で導出する。
   未確定 P0 は暫定 MVP ＋確定条件を示す。
9. **横断 NFR/ガバナンス**: 同意・監査・権限・可観測性・AI 利用・連携失敗時処理を必須チェック化する。

## 出力フォーマット

`docs/catalog/app-catalog.md` に以下の表を含める。

**アプリカード**

```markdown
| APP-ID | アーキタイプ名 | 主責務 | 所有SoR | カバーUC（Primary） | カバーUC（Secondary） | 主要連携 | キーNFR | 対応KPI/OKR | 留意点/TBD |
|---|---|---|---|---|---|---|---|---|---|
```

`docs/recommended-kpi-okr.md` が存在しない場合は「対応 KPI/OKR」列を空欄とする。

その他、必要に応じて以下を含める。

- UC 実装手段表（UC-ID / 名称 / 優先度 / 実装手段(A〜E) / 根拠 / Primary Capability / SoR候補）
- カバレッジ行列（UC × APP を R/S/N で表現。UC 数が多い場合は要点のみ本文に残し、詳細は別ファイルに分割してよい）
- MVP（P0 全カバーの最小アプリ集合、確定条件）
- 業務・組織バックログ（D/E 分類の UC）
- Decision Log（束ね/分離判断、暫定値、未確定事項）

## 重要な注意事項

- 全ての UC に A〜E が付与されていること。D/E がアプリリストに混入していないこと。
- 各 UC に Primary Capability が必ず 1 つあること。カバレッジ行列で各 UC の R が原則 1 つであること。
- MVP が P0 を全てカバーしていること（未確定 P0 は暫定 MVP ＋確定条件で明示）。
- **捏造禁止**: ID・URL・固有名・数値・事実を根拠なく作らない。不明・未確認は `TBD` / `要確認` と明示する。
- **オーバーエンジニアリング禁止**: 指示・要件にない汎用化・抽象化・将来拡張の先回りを行わない。YAGNI に従う。
