# Step 2.1: KPI/OKR 定義（任意ステップ）

> **任意ステップ**: 本ステップはパラメータ `include_kpi_okr=true` が明示された場合のみ実行する（既定 `false`）。

## このステップの目的

事業要件文書の戦略的記述（To-Be ビジョン / 戦略的方向性 / 戦略的アクションプラン / 主要 KPI に相当する記述）
を根拠に、KPI/OKR、計測データ定義、目的志向のデータ収集設計を作成する。

## 入力

一次情報（存在するものを優先順に使用）:
- `docs/business-requirement.md`（Step 2 出力。存在する場合はこちらを優先）
- `docs/company-business-requirement.md`（Step 1.2 出力。Step 2 がスキップされた経路でのフォールバック）

参考（任意）:
- `docs/business/*-analysis.md`

パラメータ:
- 対象企業名: `{company_name}`（任意）
- 分析対象事業・業務名: `{target_business}`（任意）
- 調査期間年数: `{survey_period_years}` 年（任意）
- 対象地域: `{target_region}`（任意）
- 分析目的: `{analysis_purpose}`（任意）

## 出力

- `docs/recommended-kpi-okr.md`

## 実行手順

1. 一次情報の戦略的記述（To-Be ビジョン・戦略的方向性・KPI に相当する記述）から戦略目標を抽出する。
2. 戦略目標を KPI/OKR にマッピングし、各項目に信頼度区分（資料上確認できる事実 / 外部情報補足 / 合理的仮説 /
   追加確認必要論点）を付与する。一次情報に記載のない目標値は「合理的仮説」または「追加確認必要論点」に分類する。
3. 各 KPI/OKR について計測データ（イベント名・属性スキーマ）と収集手段（アプリケーションログ・分析基盤等）を設計する。
4. 命名規約に従い ID を採番する。

## 出力フォーマット

`docs/recommended-kpi-okr.md` を以下の章立てで作成する。

1. **Executive Summary**
2. **戦略目標マッピング** — 戦略目標と `ST-*` ID
3. **KPI 定義** — `KPI-*` ID、定義、算出方法、目標値（信頼度区分付き）
4. **OKR 定義** — `OKR-*` / `KR-*-*` ID、Objective、Key Results
5. **計測データ定義** — `DAT-*` ID、イベント名、属性スキーマ
6. **データ収集設計** — 各 `DAT-*` の計測実装手段（アプリケーションログ・分析基盤・API 連携等）
7. **ID 命名規約と引き継ぎ** — 後続ステップ（Step 3.1 / 3.2 / 4.1）への引き継ぎ方法

ID 命名規約: `ST-*`, `KPI-*`, `OKR-*`, `KR-*-*`, `DAT-*`。

## 後続工程での参照

- Step 3.1（ユースケース骨格）/ Step 3.2（ユースケース詳細）が**任意参照**する。各 UC が満たす KPI/OKR ID を紐付ける。
- Step 4.1（アプリケーションリスト作成）が**任意参照**し、`docs/catalog/app-catalog.md` の対応 KPI/OKR 列に紐付ける。
- 参照元が本ファイルの不在を検知した場合、当該紐付け項目は省略する（捏造しない）。

## 重要な注意事項

- 全ての KPI/OKR 項目に信頼度区分を付与すること。
- **捏造禁止**: ID・URL・固有名・数値・事実を根拠なく作らない。不明・未確認は `TBD` / `要確認` と明示する。
- **オーバーエンジニアリング禁止**: 指示・要件にない汎用化・抽象化・将来拡張の先回りを行わない。YAGNI に従う。
