# Step 2.2: サービス識別

## 目的

ユースケース文書とドメイン分析結果を根拠に、サービス一覧を抽出する。
Web アプリのオンラインサービスに加え、データフロー型アプリのバッチサービス/ジョブも同一カタログに含める。

## 入力

- `docs/catalog/use-case-catalog.md`（必須）
- `docs/catalog/domain-analytics.md`（必須）
- `docs/catalog/app-catalog.md`（必須）

## 出力

- `docs/catalog/service-catalog.md`

## 実行手順

1. ドメイン分析の各コンテキスト・集約からサービス候補を抽出する
2. 各サービスに SVC-* ID を採番する
3. 各サービスに APP-ID との紐付け（N:N）を行う
4. データフロー型 APP-ID がある場合、バッチサービス/ジョブも含める
   - 種別: `オンライン` / `バッチ` / `ストリーミング` を明記する

## 出力フォーマット

```markdown
# サービスカタログ

| SVC-ID | サービス名 | 種別 | 責務 | 所属コンテキスト | 関連 APP-ID | 出典 |
|---|---|---|---|---|---|---|
| SVC-001 | [名称] | オンライン/バッチ | [責務] | [コンテキスト名] | APP-001, APP-002 | [出典] |
```

## 制約

- APP-ID 横断の SoT として、サービスの重複定義を防ぐ
- 不明な項目は推測せず TBD と明記する
- 捏造禁止 / オーバーエンジニアリング禁止
