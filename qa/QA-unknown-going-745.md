# QA: 馬場不明のレースの扱い（#745・2026-09-30）

#722（Benter 型の α 判定）の計画時に見つかった、独立確率の入力データの欠損についての確認。
一次資料: `docs-original/745-unknown-going.md`。蒸留先: `knowledge/learned-model-harness.md`（決定ログ #745）。

## Q1: test 窓に馬場が NULL のレースが 621R ある。作り直しの前にどう扱うか

- 背景: `pl_features.py` は空の馬場を良として読む。うち 439R は #721 で取り込んだ 2026-06〜08 のレース。
- 選択肢:
  - **不明扱いに直す**（推奨）: 別の小さな PR を先に出す。空の馬場を良にも重にも数えない。dev で ledger を確認する。DB への書き込みも、外部からの取得もしない。
  - 補完取得を先に行う: netkeiba から馬場を取る（約 35 分）。共有 DB の更新になる。
  - 良扱いのまま、既知の制約として書く。
- 回答: **不明扱いに直す**。

## Q2: 不明をどこまで「不明」として扱うか（作業中の判断・計画の敵対的レビューの指摘を反映）

- 回答:
  - 当日の馬場が不明なら、`going_apt` は中立（データなしと同じ 0）にする。
  - 過去走の適性の条件と、走破タイムの基準の馬場別キーでは、不明の走を良・重どちらにも入れない。
  - 不明の走の速度 z は、馬場を区別しないコースの基準で測る。
- 馬場の補完取得は別の問いとして、ここでは扱わない。
