# QA: 対話の predict の買い目と朝の固定（🔒）の関係（#776・2026-10-25）

#767 で predict-watch と盤の買い目を朝の選定で固定した後に残っていた、対話の `paddock-predict` の記録との関係の確認。
蒸留先: `knowledge/ev-kelly-bet-selection.md`（REQ-D23-007・決定ログ #776）、`knowledge/predict-session.md`（決定ログ #776）。

## 前提（調査で確かめた事実）

- `predict_bets` に書く経路は web の盤・desktop の盤・CLI の predict の 3 つで、固定を通っていないのは CLI の predict だけ。
- `morning_selections` を書くのは predict-watch だけで、predict の記録は固定の入力にならない（循環しない）。
- `/recommendations` を呼んでいる画面は web にも desktop にも無い。

## Q1: 対話の predict の買い目を、朝の固定とどうそろえるか

- 選択肢:
  - **(a) 盤と同じ固定で組む**（推奨）: 盤と同じ規則（朝の選定 → 記録◎ → なし）を use-case に切り出して共有する。記録の 3 経路が同じ定義になる。
  - (b) 運用で吸収する: コードは変えず、🔒 で買うときは盤から記録すると書く。CLI の `y` で記録すると母集団が混ざり続ける。
- 回答: **(a)**。

## Q2: `--overview` と `--skip-all` の表示も固定済みにするか

- 選択肢: **すべて固定済みにする**（推奨・表示の経路が 1 つ）／記録する対話だけ固定する。
- 回答: **すべて固定済みにする**。

## Q3: 各レースの表示に、固定の出所を 1 行出すか

- 選択肢: **出す**（推奨・predict-watch のログと同じ形。朝の選定ができる前に組んだことに気づける）／出さない。
- 回答: **出す**。

## Q4: どの画面からも使われていない `/recommendations` をどうするか

- 選択肢: **そのまま（固定しない）**（推奨・呼び出し元が無いので触らず、決定ログに残す）／固定にそろえる。
- 回答: **そのまま（固定しない）**。

## Q5: 計画の敵対的レビューで出た、運用の順番の問題をどう扱うか（計画の承認で確定）

- 背景: keiba-start は predict（Step 2）を predict-watch の起動（Step 5）より先に回すので、手順どおりだと predict の時点で朝の選定が無く、固定が効かない。
- 回答: keiba-start に Step 1.7 を足し、predict-watch の起動を predict より前に移す。朝の選定ができたことをログで確かめてから predict を回す。

## Q6: 記録◎（人手の ◎）と、predict-watch を先に起動する順番の循環をどう扱うか（PR のセルフレビュー後・2026-10-31）

- 背景: predict-watch を先に起動すると、窓の前の全レースの朝の選定が最初のスイープで保存される。その後に取り込んだ記録◎ は固定に入らない（#767 の規則）。
- 選択肢: **(a) 文書化だけ**（推奨・記録◎ の経路は実地で未使用）／(b) 記録◎ の取り込みを Step 1.7 の前に置く工程を足す。
- 回答: **(a)**。「記録◎ を効かせるなら Step 1.7 の前に取り込む。後から入れた記録◎ は固定に入らない」と書く。

## Q7: 朝の選定がまだ無いレースが残っているとき、predict をどう運用するか（同上）

- 選択肢: **固定なしで回し、記録だけ後で**（推奨・予想の作業を止めない）／確定まで predict を待つ。
- 回答: **固定なしで回し、記録だけ後で**。出所が `朝 HH:MM` でないレースは predict では記録せず、朝の選定ができてから盤の執行パネルで記録する。
