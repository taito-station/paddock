## Q1: test 窓に馬場が NULL のレースが 621R ある。作り直しの前にどう扱うか

## Q2: 3連複は、確定後も票が入っていない組合せ（877R・7,009 組）の市場確率が 0 になる。どう扱うか

- 選択肢: **下限を置く＋感度分析**（推奨）/ 除外して正規化。
- 回答: **下限を置く**。そのレースで売れた組合せの最小 π の半分を置き、レース内で正規化し直す。
  「除外して正規化」は dev 窓で感度分析として並べる。的中が無投票の組合せだったレースは件数を数える。

## Q3: ワイドは的中が 3 組・オッズが帯。尤度と市場確率をどう取るか

- 選択肢: **複合尤度＋中点**（推奨）/ ペアごとの二値ロジスティック。
- 回答: **的中 3 組の複合尤度＋中点オッズの正規化**（W=3 と同じ）。CI はレース単位ブートストラップだけ
  （複合尤度なので Hessian SE は分散を過小に見積もる）。下限オッズでの π は dev 窓の感度分析。

## Q4: 窓（計画の開発ルール監査で是正）

  fit = dev 窓 2025-07-01〜12-31（α・β の推定と定義の調整はここだけ）、eval = test 窓 2026-01-01〜08-31（1 回だけ測る）。

## Q5: 判定基準（test 窓を測る前に固定・作業中の判断）

- issue の文言「eval で α の 95% CI が 0 を跨がないか、ΔR² と log-loss 差の CI」を、次の 4 条件の AND にした。
  1. fit 窓で推定した α̂ の 95% CI（レース単位ブートストラップ 1000 回）が 0 より上
  2. eval 窓で α を測り直しても 95% CI が 0 より上（確認のための再推定。調整には使わない）
  3. eval 窓で、fit 窓の (α̂, β̂) の合成の擬似 R² が市場単独より高い（対応ありの差の CI が 0 より上）
  4. 同じく、的中 1 組あたりの NLL 差（合成 − 市場）の CI が 0 より下
- 理由: 1 は推定値そのものの有意性、2 は時期が変わっても情報が残るかの確認、3・4 は市場を固定した上乗せの有無。
  どれか 1 つでも欠けたら「エッジなし」とする（保守側）。
- ROI は参考値だけを出す。p·O > 1 の組を 1 単位ずつ買った実現回収率で、ワイドの払戻は帯の下限で近似する。
  判定には使わない（Benter 1994 表 3/4）。
