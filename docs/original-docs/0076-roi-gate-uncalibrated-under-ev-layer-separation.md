# 0076. EV 層分離後の参考ROIは ROI ゲート 100% の判定指標として使えない（182R 実測・知見）

## ステータス

知見（CLAUDE.md のライブ買い方ルールと `predict-watch` の実装は本 ADR では変更しない。
資金直結のため、ゲートの実変更は追検証とユーザー承認を前提に別 issue で行う。ADR 0044 / 0045 と同じ扱い）

## コンテキスト

ADR 0055（EV 層分離・循環断ち）以降、`predict-watch` / `predict --overview` の参考ROIは
**軸/相手は blended（α=0.2）で選び、EV は pure（α=1.0）× 市場オッズで評価する** 2 系統構成になった。
これは市場オッズと独立な確率で EV を coherent に計算するための意図的な設計で、その点は妥当。

問題は、**その指標に対して張る/見送りのゲートが 100% に置かれたまま**で、現行定義での較正が
一度も測られていないことだった（#571）。ADR 0044 / 0045 の 71R 検証は**分離前**の EV 定義
（blended α=0.2 の確率・ワイド抜き・確率重み配分）を測ったもので、現行定義には適用できない。

`live_ev_snapshots`（`predict-watch` が各スイープで記録した判定ROIと買い目伝票）を確認すると、
疑いは #571 本文より強い形で裏づけられた: **182 レース / 839 スイープ / 8 開催日のすべてで ROI < 100%**
（範囲 7.5〜82.1%）。記録が始まって以来ゲートは一度も発火していない。

## 検証設計

`scripts/predict-check/gate_calibration.py`（新規）:

- **母集団**: `live_ev_snapshots` の 182 レース（2026-07-11〜08-09・8 開催日）。この窓は EV 層分離
  （`4b93679` 2026-06-30）と混戦ボックス（`c6ec8d0` 2026-07-07）の後で、全期間が現行ロジック。
- **代表スイープ**: 発走前の最終（`captured_at ≤ post_time`）。182/182 で採れた。
- **買い目**: Rust `build_portfolio` が組んだ伝票（`slip`）そのもの。Python で組み直さない
  （ADR 0064 が警告する買い方ロジックの second source を作らない）。
- **循環回避**: 判定に使った盤面オッズと、清算に使う netkeiba 確定払戻を分離する（ADR 0041 / 0044 と同方針）。
- **市場整合ROI**: 各券種の全組オッズから `q_i = (1/O_i) × W / Σ_j(1/O_j)`（W = 的中組数。
  馬連/3連複=1・ワイド=3）で market-implied 確率を作り、**同じ伝票**を評価する。この正規化なら
  どんな買い方でも `W/Σ(1/O)` ＝ 1−控除率 に一致するので、`判定ROI ÷ 市場整合ROI` が
  「pure モデルが選ばれた脚を市場の何倍で値付けしているか」を直接与える。
  実データで馬連 77.2% / ワイド 77.5% / 3連複 74.9% と JRA 公称控除率を再現しており、測定器自体が検算できている。
- **判定基準**: ADR 0045 の定義を踏襲。逆予測性の解消 = `Spearman(判定, 実現) ≥ 0` かつ
  上位帯の実現ROI ≥ 全体平均。

## 決定（知見）

**現行定義の参考ROIは、レースを選別するゲート指標として使えない。**

1. **スケールのズレは閾値のズレではなく定義の不整合**。判定ROI は市場整合ROI の 0.30 倍。
   買い目の脚は blended（市場優位）で選ばれるのに、EV は市場情報を捨てた pure 確率で値付けされる。
   pure は本命をフラットにしか出せない（ADR 0058 / 0059）ので、**選ばれた脚が構造的に低く出る**。
2. **#571 要件の (a) 閾値較正は成立しない**。「実現 100% に相当する判定ROI 値」が存在しない。
   θ を下げても実現ROIは 100% に届かず（θ=30% で 37 鞍・80.7% が最良）、閾値表は非単調。
   n が小さい帯（θ≥60% で n=4、θ≥70% で n=2）が 100% を超えるのはノイズ。
3. **(b) 較正済みROI の併記も支持されない**。写像は単調な関係を前提とするが `Spearman = +0.002`＝
   関係が無い。定数倍で水準だけ合わせても順位付けの力は生まれず、実質 1−控除率 を再導出するに等しい。
4. **(c)「現行のまま＝滅多に発火しないのは仕様」も採らない**。「滅多に」ではなく**構造的に到達不能**で、
   CLAUDE.md / REQ-D01-001 の「ROI ≥ 100% のレースだけ張る」は現状**満たしようのない運用指示**になっている。

**この窓にモデルの実証エッジは無い**。無ゲート 69.5% は市場整合 77.0% と bootstrap CI 内で区別がつかず、
ポートフォリオは「市場から控除率ぶん負けるだけのふつうの賭け」と同じ挙動をしている
（ADR 0044 の 71R 窓の無ゲート 75.5% と同水準）。

## 理由

- **逆予測ではなく無情報**。ADR 0044 / 0045（分離前定義）は Spearman −0.167 で**逆予測的**だった。
  分離後は +0.002 で、判定ROIは実現ROIを正しくも誤ってもランク付けしない。EV 層分離は
  「高い EV ほど当たらない」病理は取り除いたが、**選別力を与えてはいない**。
- **控除率の壁**。ゲート 100% は「市場を 30% 上回る」ことを要求する。純モデルの resolution は
  天井に達しており（ADR 0058 / 0059・`project_resolution_data_ceiling`）、市場の動的情報も
  クロージングに吸収される（ADR 0067）。この要求を満たす材料は現時点で存在しない。
- **ゲートを下げる方向は既に棄却済み**（ADR 0040）。本測定も θ を下げて張る本数を増やす方向を支持しない。
- 結論は ADR 0055 決定 4（predict-watch を decision-support 化＝自動の張る/見送り判定を出さない）と
  ADR 0060（エッジは "当てる精度" でなく買い方＝執行の規律に置く）と整合する。本 ADR はその方針を
  **実測で裏づけた**ものであり、新しい方向を提案するものではない。

## 却下した案

- **ゲート閾値を実現 100% 相当へ較正する（#571 (a)）** — 該当する判定ROI 値が存在しない。
- **較正済みROI を併記しゲートをそちらに掛ける（#571 (b)）** — Spearman ≈ 0 で写像の前提が無い。
- **ゲートを下げて張る本数を増やす** — ADR 0040 で棄却済み。本測定でも θ=30% で 80.7%（<100%）。
- **母集団を 559R へ広げてから判断する** — 判定ROIが記録されていないレースは `build_portfolio` を
  リークなしに再生成する経路（`analyze backtest` への新設）が要る。182R で符号と大きさが明確に出たため、
  本 ADR では 182R で結論を出し、拡張は必要が生じたときの follow-up とする。

## 検証上の留保

- **単一窓 n=182**（2026-07-11〜08-09・夏開催）。ADR 0045 が 71R に付けた過学習の留保は緩むが消えない。
  ただし「判定ROIが 100% に一度も届かない」「判定ROI ÷ 市場整合ROI ≈ 0.30」は分散でなく構造の話で、
  標本数に対して頑健。
- **実現ROI は外れ値に強く依存する**。上位 5 鞍を除くと 69.5% → 60.7%。点推定だけを読まない。
- **8 開催日のうち 07-26 は n=2** と極端に薄い（監視が短時間しか回っていない日）。日別の解釈に使わない。
- 本測定は `predict-watch` の記録に基づくので、**監視が回らなかったレースは母集団に入らない**。
  スリープ等で記録が飛んだ区間（#568）は測れていない。

## 影響

- **CLAUDE.md・`predict-watch` の実装・本番定数はいずれも本 ADR では変更しない。**
- `scripts/predict-check/gate_calibration.py` と `test_gate_calibration.py`（19 件）を追加。
  以後の開催が増えるたび、同じコマンドで n を増やして測り直せる。
- [product-goals.md](../knowledge/product-goals.md) REQ-D01-001 の記述を実測に合わせる。
- [betting-rule-history.md](../specifications/betting-rule-history.md) に棄却記録⑪として追記。
- #249（予測ROI vs 実現ROI のバケット較正）は本測定に畳んで close。
- 測定中に見つかった**別件の欠陥 2 件**は別 issue に切る（いずれも ROI＝比を動かさないので本 ADR の
  結論には影響しない）:
  1. **予算執行率 80%** — `PortfolioConfig::default().alloc = (1,1,1)` が CLAUDE.md / REQ-D23 の
     3:3:4（ワイド1500 / 馬連1500 / 3連複2000）と食い違い、券種予算と脚単価の 2 段階 100 円切り捨てで
     ¥5,000 のうち ¥4,000 しか張られない。
  2. **軸フリップ 18%** — 発走前に 2 スイープ以上あった 154 レースのうち 28 レースで軸が入れ替わる。
     軸は `rank_probs`（市場ブレンド）で選ぶため市場と一緒に動く。REQ-D01-003 / ADR 0060 の軸ロック違反。
     #388 は同じ無言フリップを盤面（SPA）側でのみ `forced_axis` で塞いでおり、`predict-watch` は未対応。

```sh
  --payouts-dir /tmp/payouts --from 2026-07-11 --to 2026-08-09

python3 scripts/predict-check/test_gate_calibration.py
```
