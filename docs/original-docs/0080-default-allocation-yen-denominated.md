# 0080. 既定の券種配分を円建て 1500:1500:2000 にする（ADR 0019 の 1:1:1 を supersede・採用）

## ステータス

採用（`PortfolioConfig::default().alloc` を変更する。**[ADR 0019](0019-portfolio-generator.md) の
「既定値（相手 5 頭・配分 1:1:1）」のうち配分だけを supersede する**。相手 5 頭は変えない）

## コンテキスト

ADR 0076（#571）の較正測定の副産物として、**¥5,000 の予算に対し実賭金が ¥4,000 しか無い**ことが
判明した（#600）。`live_ev_snapshots` の 839 スイープ中 **835 本が ¥4,000**（残り 4 本は ¥4,200）。

原因は既定配分 `(1, 1, 1)` と 2 段の 100 円 floor:

| 段 | 計算 | 損失 |
|---|---|---|
| 券種予算 | `5000 × 1/3 = 1666 → 1600`（×3 券種） | ¥200 |
| 馬連・ワイドの脚単価 | `1600 / 5 = 320 → 300`（×5 点） | ¥100 × 2 |
| 3 連複の脚単価 | `1600 / 10 = 160 → 100`（×10 点） | ¥600 |
| | **合計** | **¥1,000** |

一方 `CLAUDE.md`「予算・配分（既定）」と REQ-D23-003 は **ワイド ¥1,500 / 馬連 ¥1,500 /
3 連複 ¥2,000**（= 3:3:4）と書いており、doc と実装が食い違っていた。

**ただし「doc が正しい」と単純には言えない。** ADR 0019 は
「既定値（相手 5 頭・**配分 1:1:1**）は固定だが、PR1 の `strategy_eval.py` で相手頭数・配分の
感度を…」と明記しており、**実装は自分の ADR に従っていた**。CLAUDE.md の 3:3:4 に ADR の裏づけは
無く、由来はバックテスト baseline の金額（馬連 ¥1,500 ＋ 3 連複 ¥2,000・ワイド除外。ADR 0041 /
0044 / 0046 の検証土俵）。つまり doc↔ADR↔実装の三つ巴だった。

## 検証設計

`scripts/predict-check/gate_calibration.py` に `--compare-alloc` を追加した。
**記録済みの脚（どの組番を買ったか）はそのままに、金額だけ再配分**して確定払戻で再精算する。
配分は脚の選定に影響しないので、この再計算は正当（脚を組み直さないので
ADR 0064 の警告する買い方ロジックの second source にもならない）。

`distribute` は Rust `portfolio::distribute` の 2 段 floor を鏡映する。**旧既定 `(1,1,1)` を
渡すと「記録どおり」と完全一致する**ので、鏡映の忠実性は実データで自己検証できる。

母集団は ADR 0076 と同じ 182 レース（2026-07-11〜08-09）。混戦レースは `KONSEN_ALLOC`（4 レイヤー）で
組まれており 3 要素の alloc では再現できないため対象外（当該窓の発走前最終スイープには混戦 0 件）。

## 測定結果（182R・脚は固定・金額のみ入れ替え）

| 配分 (馬連,ワイド,3連複) | 賭金 | 払戻 | 実現ROI | 1R 平均 |
|---|---|---|---|---|
| 記録どおり | ¥728,000 | ¥505,690 | **69.5%** | ¥4,000 |
| 1,1,1（旧既定） | ¥728,000 | ¥505,690 | 69.5% | ¥4,000 |
| **1500,1500,2000** | ¥910,000 | ¥621,440 | **68.3%** | **¥5,000** |

差は 3 連複の重みが倍（¥1,000 → ¥2,000）になるぶんだけで、この窓では 3 連複が最弱（63.6%）
なので 1.2pt 下がる。ADR 0076 の bootstrap 95% CI は 56.6〜83.2% なのでノイズの範囲。

## 決定

**既定配分を円建ての `(1500, 1500, 2000)` にする**（`(連系ペア, ワイド, 三連複)` の順）。
`race_budget` にスケールする相対重みなので、¥5,000 では CLAUDE.md の金額にそのまま一致する。

## 理由

- **¥5,000 を 100 円単位で割り切れる配分は 3:3:4 だけ。** 相手 5 頭なら脚数は 5 + 5 + 10 = 20 で、
  `1500/5 = 300`・`2000/10 = 200` はいずれも 100 円単位に乗る。1:1:1 では
  `5000/3` が 100 円単位に乗らず、どう floor しても ¥4,000 にしかならない
  ——**「予算ちょうどに収める」（CLAUDE.md 表記規約）は 3:3:4 でしか成立しない**。
- **ROI 差 1.2pt は判断材料にならない。** ADR 0076 が測ったとおりこの窓にエッジは無く
  （無ゲート 69.5% vs 市場整合 77.0%）、両方とも 100% を大きく下回る負け配分同士の比較。
  ノイズで優劣を決めるより、**運用者が読む正本（CLAUDE.md）と実装を一致させる**ほうが価値が高い。
- **ADR 0019 の 1:1:1 は測定の産物ではない。** 同 ADR 自身が「既定値は…`strategy_eval.py` で
  後追い検証・調整する」と書いており、暫定値であることを認めている。今回それを測った。
- **表現も揃う。** `KONSEN_ALLOC = (1000, 1000, 1500, 1500)` は既に円建てなので、
  非混戦だけ無次元の 1:1:1 という不揃いが解消する。

## 却下した案

- **doc を実装（1:1:1）に寄せる** — ADR 0065（ワイド top3 → top5）の「有意差が無ければ最小変更で
  実装側に寄せる」先例にはのる。だが**¥5,000 の 20% が不執行という状態を仕様として追認する**ことになり、
  CLAUDE.md の「¥5,000/レース」「予算ちょうどに収める」を両方書き換える必要がある。
  ADR 0065 の対象（相手の頭数）と違い、こちらは**予算の執行という運用の根幹**なので同列に扱わない。
- **1:1:1 のまま端数だけ配り切る** — **不可能**。¥5,000 を 3 券種へ 100 円単位で等分できない
  （`1700/1700/1600` にしても 3 連複が `1600/10 = 160 → 100` で潰れ、やはり ¥4,000）。
  20 点へ ¥5,000 を 100 円単位で配る解は実質 300×5 + 300×5 + 200×10 ＝ 3:3:4 に帰着する。
- **確率重み配分にして端数を吸収する** — ADR 0046 が 71R の実 ROI 悪化で棄却済み。均等割りは維持する。
- **他の窓で測ってから決める** — 両方とも 100% を大きく下回る負け配分同士の比較なので、
  測っても「どちらが良いか」は決まらない見込み（ADR 0076）。決め手は実行可能性（割り切れるか）。

## 影響

- `src/domain/src/portfolio/mod.rs`: `PortfolioConfig::default().alloc` を `(1500, 1500, 2000)` へ。
  既定を変えるだけで `predict` / `predict-watch` / `board` / `recommend` すべてに効く
  （いずれも `..PortfolioConfig::default()` 経由）。
- **混戦時は不変**。`KONSEN_ALLOC` を使う経路は `config.alloc` を参照しない
  （旧既定との突き合わせで回帰テストに固定した）。
- **1 レースあたりの賭金が ¥4,000 → ¥5,000 に増える**。ADR 0076 のとおり現時点でエッジは無いので、
  **この窓の水準（実現 69.5%）が続くなら 1 レースあたりの期待損失は ¥1,220 → ¥1,585 に増える**。
  これは「¥5,000/レースで張る」というルールを実際に執行する以上避けられない帰結で、
  賭金水準そのものを見直すなら別の議論（本 ADR は doc↔実装の乖離解消のみを扱う）。
- `scripts/predict-check/gate_calibration.py`: `--compare-alloc` を追加。
- REQ-D23-003 と [betting-rule-history.md](../specifications/betting-rule-history.md) を更新。

## 検証上の留保

- **測定は 182R・単一窓**（2026-07-11〜08-09）。ただし決め手は ROI ではなく
  「100 円単位で予算を割り切れるか」という構造条件なので、窓に依存しない。
- **相手が 5 頭でない盤面では端数が残りうる**。例えば 5 頭立て（相手 4 頭）だと
  馬連 4・ワイド 4・3 連複 6 点で `1500/4 = 375 → 300`、`2000/6 = 333 → 300` となり
  合計 ¥4,200。**「予算ちょうど」が保証されるのは相手 5 頭の標準構成**で、
  少頭数レースでは従来どおり端数が出る（CLAUDE.md も「全点に ¥100 を置けない端数時のみ下回る」と書いている）。
- **実地確認は次の開催日待ち**。`gate_calibration.py` の「予算執行率」が 80.0% → 100% になることを確認する。

## 再現方法

```sh
# 配分比較（脚は記録どおり・金額のみ再計算）
python3 scripts/predict-check/gate_calibration.py \
  --payouts-dir <dir> --from 2026-07-11 --to 2026-08-09 \
  --compare-alloc 1,1,1 --compare-alloc 1500,1500,2000

# 既定配分が予算を張り切ること
cargo test -p paddock-domain default_alloc_spends_the_whole_budget
# 混戦が config.alloc を見ないこと
cargo test -p paddock-domain konsen_alloc_is_unaffected_by_default_alloc_change
# 鏡映の忠実性（旧既定で「記録どおり」を再現）
python3 scripts/predict-check/test_gate_calibration.py
```
