# 571 — ROI ゲート較正の測定（生資料）

`predict-watch` / `predict --overview` の参考ROIと ROI ゲート 100% が整合していない疑い（#571）を
実データで測った生資料。issue 本文は [gh issue view 571](https://github.com/taito-station/paddock/issues/571)。

蒸留先: ADR 0076 / [product-goals.md](../knowledge/product-goals.md) REQ-D01-001 /
[betting-rule-history.md](../specifications/betting-rule-history.md) 棄却記録⑪。

## 母集団

`live_ev_snapshots`（`predict-watch` が各スイープで記録した判定ROIと買い目伝票）の
**182 レース / 839 スイープ / 8 開催日（2026-07-11〜08-09）**。

- 窓は EV 層分離（ADR 0055・`4b93679` 2026-06-30）と混戦ボックス（`c6ec8d0` 2026-07-07）の**後**なので、
  全期間が現行ロジック。
- レース単位の代表値は**発走前の最終スイープ**（`captured_at ≤ post_time`）。182/182 で採れた。
- 買い目は Rust `build_portfolio` が組んだ伝票そのものを使い、Python で組み直していない
  （ADR 0064 が警告する買い方ロジックの second source を作らない）。
- 精算は netkeiba 確定払戻への組番一致（判定に使った盤面オッズとは分離＝循環回避。ADR 0041 / 0044 と同方針）。

## 市場整合ROI の妥当性（測定器そのものの検算）

`q_i = (1/O_i) × W / Σ_j(1/O_j)`（W = 的中組数。馬連/3連複=1・ワイド=3）で正規化すると、
市場整合ROI はどんな買い方でも `W / Σ_j(1/O_j)` ＝ 1−控除率 になる。実データで確認:

| 券種 | 組数 | Σ(1/O) | W/Σ(1/O) | JRA 公称控除率 |
|---|---|---|---|---|
| 馬連 | 120 | 1.2946 | 77.2% | 22.5% → 77.5% |
| ワイド | 120 | 3.8698 | 77.5% | 22.5% → 77.5% |
| 3連複 | 560 | 1.3354 | 74.9% | 25.0% → 75.0% |

（2026-2-chukyo-6-12R の最終スナップショット。全 182R で 76.5〜81.0%・平均 77.0% に収まる）

| 確認 | 結果 |

| #571 本文の手集計 12 鞍の再現 | 12/12 一致、うち 11 鞍は判定ROI・実回収とも完全一致 |

**#571 の 12 鞍との差分**: 合計は本測定 ¥48,000 → ¥39,100（81.5%）に対し issue 本文は ¥43,360（90.3%）。
差は 2026-08-01 札幌7R の 1 鞍のみ。issue 本文は同日 14:38 のスリープを理由に**朝 11:52 のスイープ**を
使っており、そのとき軸は ③（ROI 68.0%）だった。本測定は**発走前の最終スイープ**（13:15・発走 13:20・軸 ⑥・ROI 31.8%）を
採るため、伝票そのものが違う。**発走直前で判定するのが CLAUDE.md の規律なので本測定の値を採る。**
なおこの 1 鞍は下記「軸フリップ」の実例でもある。

## 再現方法

```sh
# 1. 対象 8 日の確定払戻を netkeiba から取得（fetch_payouts.py は 0.8s ペーシング済み）
#    07-11/07-12/07-18/07-19 は 福島03・函館02・小倉10、07-26 は 中京07・新潟04、
#    08-01/08-02/08-09 は 中京07・新潟04・札幌01
python3 scripts/predict-check/fetch_payouts.py 20260809 07 04 01 > /tmp/payouts/payouts_20260809.json

# 2. 較正測定（live_ev_snapshots の伝票を払戻で精算し、較正バケット・Spearman・
#    閾値表・券種別・市場整合ROI・軸安定性を出す）
python3 scripts/predict-check/gate_calibration.py \
  --payouts-dir /tmp/payouts --from 2026-07-11 --to 2026-08-09 \
  --dump-races /tmp/races_final.tsv

# 3. 単体テスト（DB・netkeiba に触らない）
python3 scripts/predict-check/test_gate_calibration.py
```

## 付随して見つかった 2 つの欠陥（#571 の範囲外・別 issue）

1. **予算執行率 80%**。`PortfolioConfig::default().alloc = (1, 1, 1)`（均等三等分）で、CLAUDE.md /
   REQ-D23 の「ワイド ¥1,500 / 馬連 ¥1,500 / 3連複 ¥2,000」（= 3:3:4）と食い違う。さらに券種予算と
   脚単価の 2 段階 100 円切り捨てで、¥5,000 の予算に対し実賭金は 835/839 スイープで ¥4,000
   （ワイド 1,500 / 馬連 1,500 / 3連複 1,000）。ROI は比なので本測定の結論には効かないが、
   CLAUDE.md「各レース予算ちょうどに収める」に反する。
2. **軸フリップ 18%**。発走前に 2 スイープ以上あった 154 レースのうち 28 レースで、スイープ間に軸が
   入れ替わっている。軸は `rank_probs`（市場ブレンド α=0.2）で選ぶため市場と一緒に動く。
   CLAUDE.md 軸ロック（REQ-D01-003 / ADR 0060）は「直前オッズで軸を動かさない」と定めており、
   `predict-watch` はこれを守っていない。#388 は同じ無言フリップを**盤面（SPA）側でのみ**
   `forced_axis` で塞いでおり、`predict-watch` 経路は塞がれていない。
