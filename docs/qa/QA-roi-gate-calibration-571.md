# QA — ROI ゲート較正の測定（#571 / #249 統合）

一次資料: [docs/original-docs/571-roi-gate-calibration.md](../original-docs/571-roi-gate-calibration.md)

## Q1: 測定の母集団をどこまで広げるか

- 観測/根拠: 連系 3 券種のオッズ履歴があるのは `race_odds` で 559 レース、`race_odds_snapshots` で
  432 レース。一方、**判定ROIと買い目伝票が記録されているのは `live_ev_snapshots` の 182 レース**
  （2026-07-11〜08-09）だけ。判定ROIが記録されていないレースで測るには、過去オッズから
  `build_portfolio` をリークなしに再生成する経路（`analyze backtest` への新設）が要る。
- 回答: **確定。182R に限る。** production が実際に出した判定と伝票をそのまま精算するので、
  買い方ロジックの second source（ADR 0064）を作らずに済み、`analyze predict` の as_of リーク
  （`project_alpha_sign_and_predict_leak`）も構造的に起きない。182R は ADR 0044/0045 の 71R の 2.5 倍で、
  開催のたび自動で増える。559R への拡張が要るなら follow-up issue に切る。
- 反映先: ADR 0076

## Q2: #249（予測ROI vs 実現ROI のバケット較正）はどう扱うか

- 観測/根拠: #249 の要件（予測ROIのバケットごとに実現ROIを並べ較正曲線を描く）は本測定の出力そのもの。
  ただし #249 本文は `scripts/predict-check/live_ev.py` の期待ROIを基準にしており、これは
  **確率重み＋最低¥100 の最大剰余法**という本番と別方式（ADR 0064 が警告する second source）。
  本番の張り方は `build_portfolio` の均等割り。
- 回答: **確定。#571 に畳んで #249 を close する。** 残すと同じデータで同じ集計を 2 回組むうえ、
  #249 の手順は誤った配分を指してしまう。較正曲線は本測定が持つ。
- 反映先: #249 を close（理由をコメントで残す）/ ADR 0076

## Q3: ゲートの実変更まで今回やるか

- 観測/根拠: ADR 0044 / 0045 はいずれも「知見。CLAUDE.md の実ルール変更は本 ADR では行わない」と
  明記して保留している（資金直結・要追検証のため）。
- 回答: **確定。測定と ADR で止める。** ゲートの実装変更は別 PR / 別 issue。
- 反映先: ADR 0076

## Q4: 参考ROIが実現ROIより体系的に低いのは、閾値のズレか定義の不整合か

- 観測/根拠: 判定ROI 平均 23.2% に対し実現ROI 69.5%、市場整合ROI（＝1−控除率）77.0%。
  **判定ROI ÷ 市場整合ROI = 0.30**。ADR 0055 で EV は pure（α=1.0）確率で評価するが、
  買い目の脚は blended（α=0.2）で選ばれる。pure は本命をフラットにしか出せない（ADR 0058/0059）。
- 回答: **確定。定義の不整合。** 市場優位な脚を、市場情報を捨てた確率で値付けしているので、
  選ばれた脚が構造的に低く出る。閾値をいじって直せる類ではない。
- 反映先: ADR 0076 / product-goals.md REQ-D01-001

## Q5: 較正すればゲートは救えるか（#571 要件の (a) 閾値較正 / (b) 較正済みROI 併記）

- 観測/根拠: `Spearman(判定ROI, レース毎実現ROI) = +0.002`。閾値表は非単調
  （θ=0%→69.5% / 30%→80.7% / 50%→63.6% / 60%→111.2%〈n=4〉/ 70%→78.5%〈n=2〉）。
  実現ROI が安定して 100% を超える θ は存在しない。182R 全体の bootstrap 95% CI は 56.6〜83.2% で
  上端でも 100% に届かない。
- 回答: **確定。(a) も (b) も測定に支持されない。**
  (a) は「実現 100% に相当する判定ROI 値」を要求するが、そんな値が無い。
  (b) の写像は単調な関係を前提とするが Spearman ≈ 0＝関係が無いので、写像しても水準を化粧するだけで
  順位付けの力は生まれない（しかも定数倍で 1−控除率 を再導出するに等しい）。
- 反映先: ADR 0076 / betting-rule-history.md 棄却記録⑪

## Q6: では (c)「現行のまま＝滅多に発火しないのは仕様」でよいか

- 観測/根拠: 839 スイープ / 182 レースでゲート通過 0 件、判定ROI の最大は 76.8%。
  ADR 0055 決定 4 は「predict-watch は自動の張る/見送り判定を出さなくなる」としており、
  ゲートを選別器として使わない方向は既に決まっている。一方 CLAUDE.md / REQ-D01-001 は
  「ROI ≥ 100% のレースだけ張る」を運用の前提として書いたままになっている。
- 回答: **確定。(c) をそのまま採るのは不誠実。** 「滅多に発火しない」ではなく「構造的に到達不能」で、
  運用指示としては満たしようがない。ADR 0076 は事実（現行定義の参考ROIはレース選別器として使えない）を
  記録し、REQ-D01-001 の表現を実測に合わせる。**ゲートの実装変更は別 issue。**
- 反映先: ADR 0076 / product-goals.md REQ-D01-001

## Q7: この窓に「張るべきレース」はあったのか

- 観測/根拠: 無ゲート全体の実現ROI 69.5%（上位 5 鞍を除くと 60.7%）。市場整合ROI は 77.0%。
  両者の差は bootstrap CI の中で、この窓のポートフォリオは**市場から控除率ぶん負けるだけの
  ふつうの賭け**と区別がつかない。ADR 0044 の 71R 窓（無ゲート 75.5%）と同じ水準。
- 回答: **確定。この窓にモデルの実証エッジは無い。** ゲートを下げて張る本数を増やす方向は
  ADR 0040 で既に棄却済みで、本測定もそれを支持する（θ を下げても実現ROIは 100% に届かない）。
- 反映先: ADR 0076

## Q8: 測定中に見つかった予算執行率 80% と軸フリップ 18% はどうするか

- 観測/根拠: `PortfolioConfig::default().alloc = (1,1,1)` が CLAUDE.md の 3:3:4 と食い違い、
  2 段階の 100 円切り捨てで ¥5,000 予算のうち ¥4,000 しか張られない。
  発走前に 2 スイープ以上あった 154 レースのうち 28 レース（18%）で軸が入れ替わっている。
- 回答: **確定。いずれも #571 の範囲外で、別 issue に切る。** どちらも ROI（比）を動かさないので
  本測定の結論には影響しない。ただし軸フリップは REQ-D01-003（軸ロック）違反、
  予算執行は REQ-D23-003 / CLAUDE.md「予算ちょうどに収める」違反で、放置しない。
- 反映先: 新規 issue 2 本 / ADR 0076 の「影響」
