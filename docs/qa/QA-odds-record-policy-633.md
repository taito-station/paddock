# QA — 未発売の記録方針の非対称をどう解消するか（#633）

一次資料: [#633](https://github.com/taito-station/paddock/issues/633)（転記しない・ADR 0074）。
本文は `gh issue view 633` で取得する。

## Q0: #632（ADR 0089）の後、#633 の A/B 二択はまだ生きているか

- 観測/根拠: #633 起票時の選択肢は「A: snapshots に番兵（または別表現）を積む / B: 既存行も
  掃除する」だった。その後 ADR 0089 が観測表 `race_odds_unpriced_observations` を新設し、
  未発売は**現在状態の観測**として記録され始めた（priced 取得で DELETE・時系列ではない）。
  A が挙げた実利のうち「#632 の判定材料になる」は観測表が既に満たし、「いつ発売されたかが
  読める」だけが未充足。
- 回答: **確定。二択の形は古くなった**。実質の選択は「(1) 現状（過去=生値・今後=観測表）を
  一貫した立場として言語化する / (2) 観測表を append-only 化して時系列も持つ / (3) B（掃除）」
  の三択で、**(1) を採用**（ADR 0090）。時系列の消費者が現れたら (2) を別 ADR で判断する。
- 反映先: ADR 0090

## Q1: 「過去は残す・今後は積まない」は立場の混在か

- 観測/根拠: ADR 0086 決定 3 の理由は「番兵も『その時点で未発売だった』という事実の記録」。
  ADR 0089 の観測表も「未発売と確認できた」事実の記録である。残っている差は**記録の表現**
  （オッズ列に番兵を混ぜる / 専用表で券種単位に持つ）と**時間軸**（履歴 / 現在状態）だけ。
- 回答: **確定。混在ではなく「記録に値する」で一貫している**。変わったのは表現と時間軸であって
  立場ではない。層の境界は「ADR 0086（2026-08-16 マージ）以前 = snapshots の生値 /
  ADR 0089（2026-08-19 マージ）以後 = 観測表」で機械的に引ける（マージ日は近似・実効は
  ビルド/migrate 適用時点。間の空白帯のうち開催と重なるのは 8/16(日) 夕方の薄暮開催分のみで、
  残る 8/17〜19 は非開催——実データの欠落はあっても僅か）。この読み方を確定知層
  （netkeiba-datasource.md）へ写して非対称に見える余地を消す。
- 反映先: ADR 0090 / `docs/specifications/netkeiba-datasource.md`「未発売の番兵値」

## Q2: B（既存番兵行の掃除）を再検討する価値はあるか

- 観測/根拠: `race_odds_snapshots` は 15 分毎の live オッズを積んだ**再取得不能資産**（#232）。
  番兵行は読み出し（ADR 0088 の券種スコープ判定）と分析（`odds_guard`）の双方で無害化済みで、
  残しておく実害が無い。掃除で得るものは容量程度で、失うもの（未発売だった事実の履歴）が上回る。
- 回答: **確定。採らない**。#621 QA の Q4（DELETE しない・ユーザー確認済み）を維持する。
- 反映先: ADR 0090「却下した案」
