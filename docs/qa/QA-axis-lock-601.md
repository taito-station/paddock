# QA — predict-watch の買い目選定の固定（#601）

一次資料: [docs/docs-original/601-axis-flip-in-predict-watch.md](../docs-original/601-axis-flip-in-predict-watch.md)

## Q1: 固定する軸はどこから取るか

- 観測/根拠: `board.rs`（#388）は人手予想 pad の ◎（`recorded_axis_of`）に軸を固定している。
  一方 `predictions` は **2026-06-21 を最後に空**、`predict_bets` は **0 行**で、
  #601 の測定窓（2026-07-11〜08-09）に人手予想の記録は 1 件も無い。
  つまり「記録◎のみ」を採用するとフリップは 1 件も止まらない。
- 回答: **確定。記録◎優先 ＋ 無ければその日の初回スイープ。** 記録◎は人手のハンデ精査
  （ADR 0055 がエッジと位置づけるもの）の産物なので、機械が初回スイープで選んだ軸より優先する。
  ただし pad は相手を持たないので、記録◎があるときも相手・混戦は初回スイープの値を使う。
- 反映先: ADR 0078 / `watch.rs:resolve_pinned`

## Q2: 固定を in-memory で持つか、DB から読み戻すか

- 観測/根拠: `predict-watch` は `--once`（cron）でも回るうえ、スリープ・再起動を跨ぐ運用がある
  （#568 / ADR 0072）。in-memory の HashMap ではプロセスが変わるたびに固定がリセットされ、
  その時点の市場で軸が決まり直す。
- 回答: **確定。DB から読み戻す。** 既にアーカイブしている `live_ev_snapshots` の最古行を
  `find_live_ev_pins_by_date` で引く。**マイグレーション不要**で、今日までに記録済みのレースにも
  そのまま効く。書き込みは best-effort なので、初回スイープの保存に失敗した日は次のスイープが
  固定の基準になる（＝縮退するだけで壊れない）。
- 反映先: ADR 0078 / `find_live_ev_pins_by_date.rs`

## Q3: 固定するのは軸だけでよいか

- 観測/根拠: 発走前に 2 スイープ以上あった 154R のうち、軸が動いたのは 28R（18%）だが
  **相手集合は 62R（40%）**動いており、**軸不変で相手だけ動いたレースが 51R（33%）**ある。
  混戦判定も 3R で反転している（反転すると券種配分が 3 レイヤー ↔ 4 レイヤーで変わる）。
- 回答: **確定。軸・相手・混戦判定の 3 つとも固定する。** 軸だけ固定すると 51R が取りこぼされ、
  「買い目構造を固定した」とは言えない。CLAUDE.md 軸ロックも「軸**と基本の買い目構造**」と書いている。
- 反映先: ADR 0078 / `PortfolioConfig.forced_partners` / `forced_konsen_band`

## Q4: 固定した相手が取消（非出走）になったらどうするか

- 観測/根拠: CLAUDE.md 軸ロックは「**点数（相手）は増やさない**」「相手は各券種の既定幅のまま」。
  一方、取消は同 ルールが軸の見直しを認める「新情報」にあたる。
- 回答: **確定。落とすが、ライブ順位で補充しない**（点数が 5→4 に減る）。補充すると
  「オッズで選ばれた別の馬」が買い目に入り、固定した意味が消える。点数が減るのは
  「増やさない」に反しないし、取消馬に張り続けるより正しい。ログに明示する。
  なお**軸**が取消のときは既存挙動どおりライブ首位へフォールバックする（軸不在では買い目が組めない）。
- 反映先: ADR 0078 / `rank_axis_partners`

## Q5: 固定すると EV/ROI まで凍らないか

- 観測/根拠: 固定するのは**選定**（どの組番を買うか）だけで、EV は `ev_probs`（純モデル）×
  その時点のオッズで毎回計算し直す。配分金額も `race_budget` から毎回組み直す。
- 回答: **確定。凍らない。** これは ADR 0060 の「発走直前オッズの用途は"ズレ増額"のみ」そのもの
  ——同じ買い目の値付けだけが動く。**恒真でないことを domain のテストで固定した**
  （`pinned_selection_survives_market_movement_while_roi_moves`: 選定は一致し ROI は動く）。
- 反映先: ADR 0078

## Q6: 盤面（board）の相手も固定するか

- 観測/根拠: `board.rs` も相手を `rank_probs` から毎回選び直しており、
  コメント「買い目は既存経路（相手 top5 不変）」は事実に反していた。ただし盤面は on-demand の
  再計算ビューで、`predict-watch` のような「その日の初回スイープ」に相当する基準を持たない。
- 回答: **保留（本 issue では挙動を変えない）。** 誤ったコメントだけ実態に合わせた。
  盤面に固定を入れるなら「何を基準に固定するか」を別途決める必要がある（記録◎があるレースは
  軸だけ固定されている現状で、相手まで固定する材料が無い）。
- 反映先: `board.rs` のコメント / 必要なら別 issue

## Q7: 修正できたことをどう確かめるか

- 観測/根拠: 2026-08-12（水）は非開催で、`predict-watch` を実地に回せない。
  `classify` は post_time と現在時刻で Due を判定するため、過去日を指定しても対象レースが出ない。
- 回答: **確定。機械検査は単体・統合テストで張り、実地確認は次の開催日に回す。**
  - domain: オッズを差し替えた 2 スイープで選定が一致し ROI は動くこと（＋固定しなければ動くこと）
  - rdb-gateway: `#[sqlx::test]` で 3 スイープ書き込み、**最古**が返ること
  - 実地: 次の開催日に `gate_calibration.py` の「軸（◎）の安定性」節が `0/N` になること
- 反映先: ADR 0078 / PR の Test plan
