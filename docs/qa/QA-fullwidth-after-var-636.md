# QA — 変数直後の全角文字を機械検査で禁じる（#636）

一次資料: [docs/original-docs/636-fullwidth-after-var.md](../original-docs/636-fullwidth-after-var.md)

## Q1: 実行時の挙動を見るテストにするか、字面の静的検査にするか

- 観測/根拠: 挙動は**ロケール依存**で、`LC_ALL=C` では正常・UTF-8 ロケールでは `unbound variable`。
  さらに Linux / glibc での再現有無が未確認（colima の VM が I/O エラーで測れなかった）。
  実挙動をアサートするテストは、macOS と CI（ubuntu）で結果が割れて flaky になる。
- 回答: **確定。静的検査にする。** `$var` の直後の非 ASCII を字面で禁じ、回帰テストも字面判定だけで
  完結させる。**実行環境の差に結論を依存させない**。副次的に、glibc で再現しない場合でも
  「CI 緑のまま macOS だけ壊れる」経路を塞げる。
- 反映先: `scripts/check-shell-var-nonascii.sh` / `scripts/test-check-shell-var-nonascii.sh`

## Q2: 検査はコメント行を除外するか

- 観測/根拠: 走査で当たった 12 箇所のうち 3 箇所は展開されない
  （行頭コメント 2 / クォート付きヒアドキュメント 1）。とくに
  `scripts/test-check-adr-numbers.sh:102` は**この罠を説明するコメントで、`$label（` を悪い例として
  意図的に書いている**。文脈を見ない検査にすると、罠の説明そのものが検査に引っかかる。
- 回答: **確定（ユーザー承認済み）。行頭（空白のみ先行）が `#` の行はスキップする。**
  正規表現 1 行の追加で済み、状態機械は要らない。これで悪い例を書けるようになる。
  **行末コメントは追わない**——シェルの字句解析が必要になるうえ、コメントでもブレースを付けて
  損は無いので**検出側に倒す**。この非対称は回帰テストで固定した。
- 反映先: `scripts/check-shell-var-nonascii.sh` の判定 / 同回帰テストの「行末コメントは検出側に倒す」ケース
- **再確認（PR #641 のセルフレビュー 2 巡目・4 巡目）**: 「フィクスチャ側は例外を作らず書く側で回避したのに、
  コメントだけ検査側に例外を置くのは非対称」という指摘が繰り返し出た。代案は (a) クォート無し
  ヒアドキュメントだけ追う状態管理を足す / (b) 除外を撤廃して悪い例 3 箇所を書き換える、の 2 つ。
  **確定: 現状維持（ユーザー判断）。** この検査の価値は「単純で壊れないこと」にあり、
  穴は 4 箇所（ヘッダ・一次資料・本 QA・knowledge）に明記したうえでリポジトリ内の該当箇所も
  先回りで潰してあるため、実質的な露出は無い。**この論点は決着済みなので再提案しない。**
- **後日判明した副作用（レビュー指摘）**: この除外は**展開される複数行文脈の `#` 行**（クォート無し
  ヒアドキュメント本文・複数行ダブルクォート文字列の継続行・`$(...)` の中）にも効いてしまう。本文は展開されるので実際には落ちるのに検出されない＝Q2 で「検出側に倒す」と決めた
  方針が、ここだけ局所的に反転している。追跡実装は見送り、**既知の穴として検査スクリプトのヘッダと
  一次資料に明記**したうえで、リポジトリ内の該当箇所（`test-check-adr-numbers.sh` の `write_adr()`）は
  先回りしてブレース化した

## Q3: クォート付きヒアドキュメント（`<<'EOF'`）内も直すか

- 観測/根拠: `scripts/seed-db.sh:22` は `cat <<'EOF'` の中にあり、クォート付きなので展開されない＝無害。
  ただしヒアドキュメントの追跡には状態機械が要り、検査が複雑になる。**複雑な検査ほど、壊れても
  本番データが正常だと無言で緑になる**（ADR 0073 が `adr` ジョブで潰した失敗の形）。
- 回答: **確定。追跡せず、検出されたらブレース化する。** 無害な箇所を直すコストは 1 文字で、
  検査を単純に保つ価値のほうが大きい。
- 反映先: `scripts/seed-db.sh:22`

## Q4: ADR を起票するか

- 観測/根拠: バグ修正と、それを固定する機械検査の追加。アーキテクチャや運用方針の決定を伴わない。
  検査を「回帰テスト → 本番検査」の順で CI と pre-push に載せるのは ADR 0073 で決着済みの型に従うだけ。
- 回答: **確定。ADR は起票しない。** 判断の根拠は一次資料と検査スクリプトのヘッダに残す。
- **この決定には「検査に例外・逃げ道を持たせない」運用方針も含む。** インライン除外マーカー
  （`# nonascii-var-ok` 等）は 2 巡目のレビューで提案されたが、必要になった時点で改めて判断する
  （現時点で逃げ道が要る箇所は 0 件）。
- 反映先: 一次資料「対策の形」/ `scripts/check-shell-var-nonascii.sh` のヘッダコメント
