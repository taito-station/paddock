## 棄却記録

### ① 混戦判定にオッズ条件を追加（棄却 / 2026-06-20 / ADR 0028）

「◎の単勝が X 倍以上なら混戦扱いにする」案。混戦判定にオッズ条件を足すと回収が改善するかを検証した。

- 検証: 71R（2026-05-30, 05-31, 06-13, 06-14）を `scripts/predict-check/konsen_backtest.py` で評価。
- 結果: **box-off（混戦なし）84.0% ≧ baseline（band≥4）83.9%**。オッズ条件は baseline を上回る閾値が一つも無かった。
- 追加発動した閾値（odds≥3.0/3.5 × band≥2/3）はいずれも回収を悪化させ **79.5〜81.5%**。唯一 odds≥4.0 は葵S（◎3.8倍）が閾値未満で追加発動 0 件 → **baseline 83.9% に退化（改善なし）**。band≥2 まで緩めると 13〜20R を混戦化し −3〜4pt。動機だった葵S は band=2 でボックスが組成不能（3頭未満）となり ¥1,500 が空振り。
- **結論**: オッズ条件は入れない。現行の `band≥4`（model 勝率 0.70 倍以上が ◎含め 4 頭以上）を維持。エンハンスは「回収を改善する証拠」が出てから入れる。
- 詳細: docs/original-docs/0028-konsen-odds-trigger-rejected.md（関連 Issue: #180）

### ② 混戦時の 3連複の相手拡大（top5 → top7/全頭）（棄却 / 2026-06-20 / ADR 0030）

混戦時に 3連複の相手を top5 より広げる案。函館10R（2026-06-20）で ◎④1着・▲⑥2着・3着⑤（model 7番手/25倍）を取り逃したのが動機。

- 検証: 105R（うち混戦 90R）。
- 結果: 的中率は 14%→22〜26% に向上するが、**回収率は全設定で低下**。
  - 混戦 ROI: 61.0% → 54.8〜57.5%
  - 全体 ROI: 87.7% → 82.4〜84.7%
- 均等重みでも改善せず。広げるほど外れ目に資金が分散し、当たり 1 点が薄くなる（典型的な「高的中・低配当」）。
- **結論**: 現行 top5 を維持。単発の取りこぼしで恒久ルール化しない。
- 詳細: docs/original-docs/0030-konsen-trio-partner-width-rejected.md

### ③ 条件付き単勝（単勝EV≥閾値の馬だけ）の追加（棄却 / 2026-06-21 / ADR 0033）

「`model_win_prob × 単勝オッズ ≥ EV 閾値`（100%/110%/120%）を満たす馬の単勝を¥500 追加/捻出する」案。

- 検証: 71R（2026-05-30, 05-31, 06-13, 06-14）を `scripts/predict-check/win_backtest.py` で評価。
- 結果: **全閾値・全予算モードで baseline を下回った**。

  | variant | 回収率 | 差分 | 単勝発動 |
  |---|---|---|---|
  | baseline | 79.5% | — | — |
  | +win≥100%/add | 76.0% | −3.5pt | 344 回 |
  | +win≥100%/split | 74.5% | −5.0pt | 344 回 |
  | +win≥110%/add | 76.0% | −3.5pt | 340 回 |
  | +win≥110%/split | 74.5% | −5.0pt | 340 回 |
  | +win≥120%/add | 76.0% | −3.5pt | 327 回 |
  | +win≥120%/split | 74.5% | −5.0pt | 327 回 |

- **結論**: 単勝は追加しない。発動頻度が高すぎ（71R で平均 4.6〜4.9 頭）、閾値上げても改善なし。単勝市場はモデルの win prob と高相関でエッジが出なかった。
- 詳細: docs/original-docs/0033-conditional-win-bet-rejected.md（関連 Issue: #208）

### ④ 上位近接時の2軸フォーメーション（棄却 / 2026-06-27 / ADR 0039）

上位2頭（◎=最大勝率・○=2番手）のモデル勝率が近接した局面で、◎1頭軸ながしを2軸フォーメーションに差し替える案。◎がコケても○×穴で拾えて回収率・的中率が改善するかを検証した（動機: 2026-06-27 福島R7 ③20.7%/⑤19.4%）。発動条件 `prob(○) ≥ θ × prob(◎)` を θ=0.80/0.85/0.90 で掃引。

- 検証: 127R（2026-05-30, 05-31, 06-13, 06-14, 06-20, 06-21、win オッズ・結果が揃う全レース）を `scripts/predict-check/formation_backtest.py` で評価（α=0.2・m=10）。
- 結果: 2 variant とも baseline を上回らなかった。
  - **pair2（◎○両方必須・AND）は全閾値で壊滅**（発動部分集合 ROI 31〜39%・的中 11〜15%）。近接＝拮抗ほど両崩れしやすく、AND 集中は最悪。
  - **union2（◎脚∪○脚に予算折半・OR）は回収率が改善せず**。部分集合 ROI は θ=0.80 で +3.4pt（65.7→69.1）だが θ=0.85 で −5.3pt・θ=0.90 でフラットと符号反転（小標本ノイズ）。的中率は 42%→72〜89% に激増・分散は半減するが、回収が伴わない典型的な「高的中・低配当」。動機の福島R7 が属する θ=0.90 帯でも baseline とフラット。
- **結論**: フォーメーションは採用しない。現行の ◎1頭軸ながしを維持。的中率・分散の改善は回収率を伴わなければ無価値（ADR 0030「相手拡大」棄却と同型）。
- 詳細: docs/original-docs/0039-formation-2axis-rejected.md（関連 Issue: #241）

### ⑤ EV ゲート閾値（ROI≥100%）の引き下げ（棄却 / 2026-06-27 / ADR 0040）

「+EV の買い目が全然来ない＝閾値が厳しすぎるのでは」という不安を起点に、2026 年の +EV レース数を調査し、ゲート閾値 ROI≥100% の妥当性を再検証した。

- 検証: DB 保存オッズ＋ `live_ev.py`（全3券種の期待 ROI）で再評価。ワイド込みで厳密評価できたのは 06-21・06-27 の **69R**（+EV **0本**・最高 ROI 97%・**平均 ROI 73.1%**）。α=0.2/0.3 とも +EV 0本。
- 結果: **ROI 100% が損益分岐・>100% が +EV** で、下げる＝−EV を承知で買う＝長期で負け。平均 ROI 73.1% は本戦略が使う券種の JRA 控除率（ワイド・馬連 22.5%／3連複 25%）由来のフェア ROI ≈ 75〜77.5% を数 pt 下回り（やや負側）、モデルに平均的なエッジは無い（=市場とほぼ等価＝フェア値をやや下回る。予測 vs 実現の真の較正は別問題で未検証）。+EV は控除率を食い破る稀な歪みだけで構造的に稀＝買い目が来ないのは仕様どおり。閾値直下に「買うべきレース」が溜まる兆候は無し（結果のある 71R の実現 ROI も baseline 83.9%／box-off 84.0%＝ADR 0028 で 100% 未満）。
- **結論**: ROI≥100% を維持。閾値引き下げは不採用。唯一意味のある検証＝推定 ROI の較正（予測 vs 実現）は本検証に足る標本がまだ無い（DB 単一ストアではワイドと結果が同居せず、06-21 の 35R のみ結果を netkeiba 取得すれば予備的に可能だが単日・小標本・非確定オッズで確証不足）→ #248 のデータ蓄積後に #249 で実施（保留）。
- 詳細: docs/original-docs/0040-ev-gate-threshold-lowering-rejected.md（関連 Issue: #248 / #249）

### ⑥ 馬連特化（馬連 EV≥閾値）買い目戦略（棄却 / 2026-06-27 / ADR 0041）

「ROI≥100% で張れる鞍が極端に少ない」課題への対策として、+EV が集中する馬連に券種を絞り、◎1頭軸ながしの相手のうち馬連 model EV≥θ（θ=1.0/1.2/1.5）の点だけを買う案。配分（flat/weighted）・オッズ上限（cap=∞/50/30/20）も掃引した（動機: 2026-06-27 の手作業で「フルポートフォリオ ROI≥100% は 2 鞍だが濃い +EV 馬連は約 14 鞍」）。

- 検証: 71R（2026-05-30, 05-31, 06-13, 06-14、馬連・三連複の盤面オッズと結果が揃う全レース）を `scripts/predict-check/umaren_backtest.py` で評価（α=0.2・m=10）。**EV フィルタ＝DB 盤面オッズ／清算＝実払戻**に分離し循環を回避。baseline は wide 抜き（履歴オッズ欠落だが #250 の主張上むしろ強い対照）。
- 結果: **frequency は 1→71 鞍に激増するが realized ROI が崩壊**。
  - 馬連特化 cap∞: θ=1.0 ROI 43.7%/的中 4%、θ=1.2 ROI 49.9%/的中 1%、θ=1.5 ROI 0%/的中 0%（張鞍 71・71・68）。
  - **逆予測の切り分け（apples-to-apples）**: universe（全頭）と配分（flat・¥5,000）を揃え EV フィルタの有無だけ変えると **無フィルタ 66.4%（的中 52%）→ EV≥1.0 フィルタ 43.7%（的中 4%）**。相手範囲拡大ではなく **model EV ランキング自体が逆予測的**。堅めの ◎軸 top5 無フィルタ（79.0%・的中 42%）がどの馬連特化より良い。
  - オッズ上限で穴を除外しても ROI≥100% を意味ある鞍数で満たす構成なし（cap30/θ1.0 が最良で 13 鞍・93.1%。cap20/θ1.0 は 242% だが 5 鞍の小標本ノイズ）。
- 原因: EV フィルタは全鞍で極端な穴（オッズ 76〜720 倍・モデル勝率 0.6〜2%）を選抜する。モデルの穴過大評価（#246）で「偽の +EV」が量産され、張れる鞍が増えても −EV ノイズを買っているだけ。
- **結論**: 馬連特化は採用しない。現行3券種ポートフォリオを維持。frequency 課題は券種選択ではなく**モデル較正（#246）に依存**することが定量的に裏付けられた。#246 完了後に再検討する。
- 詳細: docs/original-docs/0041-umaren-only-strategy-rejected.md（関連 Issue: #250, #241, #246）

### ⑦ 較正後 model-EV ROI≥100% ゲートの精度検証（知見・ルール変更は保留 / 2026-06-27 / ADR 0044）

#252 の副次発見。較正（ADR 0042）後、baseline_pf（馬連+三連複 ◎軸 top5）の **model ROI≥100% ゲート**通過が 1→13 鞍に増えるが実 ROI は 24.5% に崩壊。この model-EV ゲートは CLAUDE.md「ROI≥100% のレースだけ張る」と同一計算のため、ゲート自体の精度を 71R（2026-05-30〜06-14・α=0.2）で検証した（#263）。

- 検証: `umaren_backtest.py` を拡張（`compute_baseline_pf` で計算と発動判定を分離。`--gate-grid` / `--odds-floor-grid` / `--winodds`）。循環回避は ADR 0041 同様（ゲート＝DB 盤面オッズ／清算＝実払戻）。
- 結果（**同一ポートフォリオで発動判定だけ変更**）: 無ゲート全鞍 **75.5%**（71鞍）→ gate≥100% **24.5%**（13鞍）→ gate≥110% **0%**（5鞍）→ gate≥120% 0%（1鞍）。**ゲートを課すほど実 ROI が単調に悪化＝逆予測的**。◎単勝オッズ下限でも回復せず（gate≥100% ◎O≥3 で 5鞍・36.7%）。無フィルタ馬連 top5（78.7%）がゲート版より一貫して良い。
- 診断: 通過 13 鞍・非通過 58 鞍とも ◎平均人気 1.0（α=0.2 の帰結で model の ◎ はほぼ全て市場最上位）＝**人気度は通過を分けない**。較正で ◎ アンカーのポートフォリオ model EV が水増しされ、実配当を伴わないまま 100% を超えるのが実態。なお無ゲート universe 自体が 75.5%＜100% の赤字窓のため、本件は赤字 universe 内の相対比較＝#248 蓄積後の追検証が前提。
- **結論（知見）**: 較正後 model-EV ゲートを「+EV レース選別器」として信頼するのは妥当でない。根本原因はゲート閾値でなく EV 入力の較正（ADR 0042）。**CLAUDE.md の実ルールは本件では変更せず**、EV 再校正（別 issue）と #248 蓄積後の追検証を経て判断する。ADR 0040（ゲート閾値の引き下げ棄却）と関連。
- 詳細: docs/original-docs/0044-calibrated-ev-gate-anti-predictive.md（関連 Issue: #263, #252, #246）

### ⑧ 馬単（exacta）特化・順序プレミアム（棄却 / 2026-06-27 / ADR 0043 / #271 で revert 済み）

馬単は ADR 0043 で `pick_pair_leg`（軸-相手ペアで馬単 model EV 優位なら馬連→馬単に置換）としてライブ採用済みだが、採用根拠は 2026-06-27 福島R7 の 1 鞍の逸話のみで 71R 未検証だった。#262 で `umaren_backtest.py` に馬単評価を対称追加し、較正後モデル（#246・α=0.2）で 71R（2026-05-30〜06-14）に展開して検証。

- **`pick_pair_leg` 直接検証で置換は純損**: 馬連 top5 ◎軸ながし（土台）78.7%/的中 42% → model EV 優位ペアを馬単へ置換（58 脚）すると **70.1%/的中 38% に悪化**。順序プレミアムを取りに行くほど回収率が下がる。
- **順序プレミアムは単独でもエッジにならない**: 無フィルタでも馬単 ≤ 馬連（top5 67.6% < 78.7% / 全頭 60.9% < 66.4%）。両方向買いは外れ向きが必ず死に、着順固定配当でも倍化カバレッジを賄えない。
- **馬単 EV フィルタは逆予測**（馬連 ⑥ と同型・より顕著）: 無フィルタ 60.9% → EV≥θ フィルタ最良 33.3%。⑥ が小標本で見せた >100% アーティファクトすら皆無。
- **結論**: 順序プレミアムは #246 較正後の 71R では model EV シグナル経由で取り出せない。馬連→馬単の置換は無効化すべき → **#271 で `pick_pair_leg` を撤去し連系ペアを常に馬連へ revert 済み（ADR 0043 棄却）**。馬単オッズ取得・診断表示の下地は将来の再検証用に温存。
- 詳細: docs/original-docs/0043-exacta-in-portfolio-rejected.md「71R 検証（#262）」（関連 Issue: #262, #252, #246, #271）

### ⑨ 配分の確率重み化＋脚ごと最低¥100撤廃（棄却 / 2026-06-28 / ADR 0046）

#272 の買い方見直しで「券種内配分を真の的中確率で重み付けし、脚ごとの最低¥100（薄い相手への spread）を撤廃して薄い脚は¥0にする」案を検証。動機は会話初期に「薄い相手も最低¥100」を EV 希釈の主因と疑ったこと＋「¥100 は額面単位であって脚ごとの下限ではない」という解釈。総賭金は方式に依らず一定なので、差は「どの脚に厚く張るか」だけに由来する。

- 検証: 71R（2026-05-30〜06-14, /tmp/bt252, α=0.2）を baseline ポートフォリオ（馬連top5¥1500+三連複top5¥2000・wide除外）で全鞍機械買い・ゲート無し。
- 結果: **現行（proxy重み+最低¥100）75.5% / 均等割り（現行コード実挙動）75.5% に対し、真確率重み+最低¥100撤廃は 66.3% に悪化**（−9pt）。最低¥100 撤廃だけで −9pt、重み基準を真確率にするだけで −4pt。的中率は全方式 48% で不変。
- 原因: 三連複の薄い穴目への ¥100 ずつが「たまの高配当を拾うミニボックス」として効く。本命集中（低配当寄せ）に変えると一発を取り逃す。**解釈の正しさと回収率が逆を向く**。
- **結論**: 配分は現状の均等割りを維持。確率重み化＋最低¥100撤廃は採用しない。#272 では各買い目の的中確率 `hit_prob` を**表示**する（判断材料）のみ追加し、配分は不変。
- 詳細: docs/original-docs/0046-allocation-prob-weight-no-floor-rejected.md（関連 Issue: #272）

### ⑩ ワイド相手を top3 に絞る（不採用＝top5 に統一 / 2026-07-06 / ADR 0065）

CLAUDE.md は「ワイドは相手 top3」と定めていたが、本番 `build_portfolio` は全券種 top5（ワイドも top5）で、doc とコードが乖離していた。「ワイド top3」の出所は ADR 0030 baseline スクリプトの実装都合（`wp=parts[:3]`）で、production 買い方構造での top3 vs top5 直接比較根拠は無かった。measurement-first で計測。

- 検証: `strategy_eval.py` に `--wide-partners` を追加し、馬連・三連複 top5 固定・ワイドだけ top3/top5 を比較（予測確率不変＝相対比較はリーク中立）。窓 A=71R / 窓 B=262R（12 開催日）を開催日ごとに集計。
- 結果: **有意差なし**。窓 A（71R）は top3 +4.0pt だが単勝 ROI 594% の幸運な小標本で、窓 B（262R）に広げると **符号反転して top5 +3.9pt**。日別では **top5 ≥ top3 が 6/12 日・top3 > top5 が 6/12 日＝五分**で、B 集計の top5 優位は単一外れ日（2026-06-27 Δ−32pt）が牽引。どちらの優位も標本ノイズ。
- **結論**: 有意差が無いので最小変更を採る。`build_portfolio` は無変更（既に top5）、CLAUDE.md を「3 券種とも top5」に修正。「ワイド top3」の縛りは撤去（＝top3 に絞る案は再提案しない）。top5 は ADR 0030 の上限内で矛盾なし。なお計測中に **2 つ目の買い目エンジン `live_ev.py`（ライブ伝票）もワイド top3** だったと判明し、これも top5 に統一（両エンジン＋doc が top5 で一致）。
- 詳細: docs/original-docs/0065-wide-partners-top5-alignment.md（関連 Issue: #347）

### ⑪ EV 層分離後の参考ROIをゲート指標として使う（知見・ルール変更は保留 / 2026-08-12 / ADR 0076）

⑦（ADR 0044）は**分離前**の EV 定義（blended α=0.2・ワイド抜き・確率重み配分）を測ったもの。ADR 0055 で EV は pure（α=1.0）× 市場オッズに変わったが、その定義での較正は未測定のままゲートだけ 100% に据え置かれていた（#571。#249 の予測ROI vs 実現ROI バケット較正を本件に統合）。

- 検証: `gate_calibration.py`（新規）で `live_ev_snapshots` の**記録済み判定ROIと買い目伝票**（182R / 839 スイープ / 8 開催日・2026-07-11〜08-09）を netkeiba 確定払戻で精算。伝票は Rust `build_portfolio` の出力そのもので、Python で組み直していない（second source を作らない・ADR 0064）。循環回避は ⑦ 同様（判定＝盤面オッズ／清算＝実払戻）。
- 結果: **ゲート通過 0 件**（判定ROI 平均 23.2% / 最大 76.8%）。無ゲート実現ROI **69.5%**（bootstrap 95% CI 56.6〜83.2%・上位 5 鞍を除くと 60.7%）。**判定ROI ÷ 市場整合ROI(=1−控除率 77.0%) = 0.30**。**Spearman(判定ROI, 実現ROI) = +0.002**。閾値表は非単調で、実現ROIが安定して 100% を超える θ は存在しない（θ=30% で 37 鞍・80.7% が最良）。
- 診断: 買い目の脚は blended（市場優位）で選ぶのに EV は市場情報を捨てた pure 確率で値付けするため、選ばれた脚が構造的に低く出る＝**閾値のズレではなく定義の不整合**。⑦ の分離前定義（Spearman −0.167＝逆予測的）と違い、分離後は**無情報**（EV 層分離は病理を消したが選別力は与えていない）。無ゲート 69.5% は市場整合 77.0% と CI 内で区別がつかず、この窓にモデルの実証エッジは無い（⑦ の 71R 窓 75.5% と同水準）。
- **結論（知見）**: #571 要件の (a) 閾値較正・(b) 較正済みROI 併記はいずれも測定に支持されない（該当する θ が無い／Spearman ≈ 0 で写像の前提が無い）。(c) 現行維持も「滅多に発火しない」ではなく「構造的に到達不能」なので不誠実。**CLAUDE.md と `predict-watch` の実装は本件では変更せず**、ゲートの実変更は別 issue。ADR 0040（閾値引き下げの棄却）は本測定でも支持される（θ を下げても実現ROIは 100% に届かない）。
- 付随して判明した別件（ROI＝比を動かさないので本結論には影響しない・別 issue）: **予算執行率 80%**（`PortfolioConfig::default().alloc=(1,1,1)` が本書の 3:3:4 と乖離＋2 段階の 100 円切り捨てで ¥5,000 中 ¥4,000 しか張らない）と、**軸フリップ 18%**（発走前 2 スイープ以上の 154R 中 28R で軸が入れ替わる＝REQ-D01-003 軸ロック違反。#388 は盤面側のみ `forced_axis` で対処済み）。
- 詳細: docs/original-docs/0076-roi-gate-uncalibrated-under-ev-layer-separation.md / 生資料 [571-roi-gate-calibration.md](../original-docs/571-roi-gate-calibration.md)（関連 Issue: #571, #249, #248）

### ⑫ 既定の券種配分を円建て 1500:1500:2000 へ（採用 / 2026-08-12 / ADR 0080）

⑪（ADR 0076）の較正測定の副産物として、**¥5,000 の予算に対し実賭金が ¥4,000 しか無い**ことが判明した（#600。839 スイープ中 835 本）。原因は既定 `alloc=(1,1,1)` と 2 段の 100 円 floor（`5000/3=1666→1600` と `1600/10=160→100`）で、毎レース ¥1,000 が不執行。一方 CLAUDE.md / REQ-D23-003 は 3:3:4 と書いており doc↔実装が乖離していた。**ただし ADR 0019 が「既定値 配分 1:1:1」と明記しており、実装は自分の ADR に従っていた**（doc の 3:3:4 に ADR の裏づけは無く、由来は ⑥⑦⑨ のバックテスト baseline 金額）。

- 検証: `gate_calibration.py --compare-alloc`（新規）。**記録済みの脚はそのままに金額だけ再配分**して確定払戻で再精算する（配分は脚の選定に影響しないので正当。脚を組み直さないので second source にもならない）。母集団は ⑪ と同じ 182R。`distribute` は Rust の 2 段 floor を鏡映し、**旧既定 (1,1,1) を渡すと「記録どおり」と完全一致**するので忠実性を実データで自己検証できる。
- 結果（脚は固定・金額のみ入れ替え）:

  | 配分 (馬連,ワイド,3連複) | 賭金 | 払戻 | 実現ROI | 1R平均 |
  |---|---|---|---|---|
  | 記録どおり / 1,1,1 | ¥728,000 | ¥505,690 | **69.5%** | ¥4,000 |
  | **1500,1500,2000** | ¥910,000 | ¥621,440 | **68.3%** | **¥5,000** |

- 診断: 差は 3 連複の重みが倍になるぶんだけ（この窓で 3 連複が最弱 63.6%）。⑪ の bootstrap 95% CI 56.6〜83.2% に収まるノイズ。**決め手は ROI ではなく「100 円単位で予算を割り切れるか」**——相手 5 頭なら脚数 5+5+10 で `1500/5=300`・`2000/10=200` が 100 円単位に乗るのに対し、1:1:1 では `5000/3` が乗らずどう floor しても ¥4,000 にしかならない。
- **結論（採用）**: 既定配分を円建て `(1500,1500,2000)` にし、ADR 0019 の「配分 1:1:1」を supersede する（相手 5 頭は据え置き）。混戦時は `KONSEN_ALLOC` を使うので不変（旧既定との突き合わせで回帰に固定）。**1 レースの賭金が ¥4,000→¥5,000 に増えるため、この窓の水準が続くなら期待損失は ¥1,220→¥1,585 に増える**——賭金水準そのものの見直しは別議論。
- 却下: doc を 1:1:1 に寄せる（¥5,000 の 20% 不執行を仕様として追認することになる）/ 1:1:1 のまま端数を配り切る（**不可能**。100 円単位の解は 3:3:4 に帰着）/ 確率重み配分で吸収（⑨ で棄却済み）。
- 詳細: docs/original-docs/0080-default-allocation-yen-denominated.md（関連 Issue: #600, #571）

### ADR 0028: 混戦判定にオッズ条件を併用しない（バックテストで棄却）(Issue #180) (2026-06-20) — 承認済み

#### コンテキスト
予想の買い方には「混戦」を自動判定して印馬の3連複ボックスを別枠で1枚足す仕組みがある
（買い方ルールはローカルメモリ `feedback_betting_staking` と予想時の手計算で運用。本体コードの
`build_portfolio` には未取り込み）。現行の混戦判定は **◎の model 勝率の 0.70 倍以上の馬が ◎含め
4頭以上**（以下 `band≥4`）で発動する。

2026-05-30 京都11R 葵S（G3）で、◎が1番人気でも単勝 3.8 倍と支持が割れた「実質オープン戦」を
混戦と判定できず取りこぼした（band=2 のため非発動）。そこで **「◎単勝オッズが割れている（弱い
1番人気）なら band が薄くても混戦扱いにする」** 案（#180）が出た。issue では「閾値はバックテストで
決める／過学習に注意」を前提条件にしていた。

そこで再実行可能なバックテストハーネス `scripts/predict-check/konsen_backtest.py` を作り、確定買い方
（¥5,000・ワイド/馬連/3連複を model 確率で重み付け配分・混戦は3連複ボックス追加）を全レースへ機械適用し、
混戦の発動条件を切り替えて回収率を比較した。

測定窓: **2026-05-30 / 05-31 / 06-13 / 06-14 の 71R**（DB に確率表・単勝オッズが揃う全レース）。
回収率の分母は **実際に賭けた額（実消化額）** を用い、ボックスが組成不能で余る予算を損失計上して特定
variant を不当に不利化しないようにした。

#### 決定
1. **混戦判定にオッズ条件は併用しない。現行 `band≥4` を維持する。** オッズ閾値の中で baseline を
   上回るものが一つも無かったため（追加発動した閾値は悪化、唯一発動しない odds≥4.0 は baseline と同値）。
   なお box-off がわずかに上回る点は別途「スコープと限界」で扱う。
2. 検証ハーネス `konsen_backtest.py` は再実行可能な形で残す（将来 days を足して再評価できる）。
3. 判定式（買い方の発動条件）は **単発の成功例で恒久ルール化しない**。スコア/収支挙動を変える改善は
   バックテストで改善が出てから採用する（ローカルメモリ `feedback_measurement_ordering` と整合）。

##### バックテストによる検証（71R, 実消化額ベース）

払戻発生R = 混戦化したレースで、**混戦枠を含む全券種の払戻合計 > 0** となったレース数（ボックス単独の
的中ではなく、そのレースで何か当たったか＝混戦化が収支に寄与したかの粗い指標）。

| variant | 回収率 | 混戦数 | 払戻発生R |
|---|---|---|---|
| box-off（混戦を一切発動しない純◎軸） | **84.0%** | 0 | 0 |
| baseline（band≥4 ボックス, 現行） | 83.9% | 3 | 1 |
| +odds≥3.0 / band≥3 | 81.5% | 7 | 3 |
| +odds≥3.0 / band≥2 | 80.8% | 20 | 10 |
| +odds≥3.5 / band≥3 | 81.5% | 7 | 3 |
| +odds≥3.5 / band≥2 | 79.5% | 13 | 8 |
| +odds≥4.0 / band≥2,3 | 83.9%（baseline に退化） | 3 | 1 |

注: odds≥3.0/band≥3 と odds≥3.5/band≥3 は三値とも同一＝オッズ 3.0〜3.5 帯に該当する ◎ が
band≥3 のレースに居らず発動集合が一致するため。odds≥4.0 は band≥2,3 とも追加発動 0 件（葵S の
◎3.8倍も閾値未満）で baseline に退化するため 1 行に集約した。

**「◎単勝≥X倍で混戦扱い」案は、baseline（83.9%）を上回る閾値が一つも無かった**（実際に追加発動した
閾値はいずれも回収を悪化させ 79.5〜81.5%、唯一発動しない odds≥4.0 は baseline と同値）。band≥2 まで緩めると
13〜20R を混戦化するが回収はむしろ下がる。**動機だった葵S（◎3.8倍・band=2）はオッズ条件のジレンマを示す**:
閾値を 3.5 に緩めれば発動する（3.8≥3.5・band≥2）が **band=2 で3連複ボックスが組成不能（C(2,3)=0）＝空振り**、
閾値を 4.0 に上げれば **発動すらしない（3.8<4.0、追加発動 0 件で baseline に退化）**。どちらでも葵S からは
何も拾えず、オッズ条件で狙ったレースを救う設計がそもそも成立しない（捕捉できても band=2 では箱が空）。

#### 理由
- 動機だった葵S（◎3.8倍）は band=2 で、3連複ボックスが **組成不能（3頭未満で C(band,3)=0）**。混戦化しても
  予算が余るだけで払戻 ¥0。オッズ条件は「拾いたかったレース」をそもそも拾えない。
- band≥2 まで緩めて混戦化する 13〜20R の多くは、model 下位の人気薄が突入する波乱で、ボックスでも当たらない。
  ◎軸に厚く張る（box-off/baseline）方が回収が良い。
- そもそも現行 `band≥4` ボックスの寄与も中立（box-off 84.0% と baseline 83.9% ＝回収 0.1pt・払戻発生 1R 差）。
  白百合S（2026-05-31）でボックスが ◎着外でも当たった好例は、小標本のノイズ寄りだった。
- レビュー指摘を受け回収率の分母を「実消化額」に修正（賭けられない予算を損失計上しない公平な会計）した
  あとも結論は不変。むしろ odds variant の数値は補正後に上がってなお baseline 未満で、結論はより頑健。

#### 影響
- 買い方ルールに変更なし（オッズ条件は入れない）。本体コード（`build_portfolio`）の挙動も変更なし。
- 検証基盤 `konsen_backtest.py` が `scripts/predict-check/` に追加され、混戦・配分まわりの将来の閾値検討を
  再実行可能にした。
- ローカルメモリ `feedback_betting_staking` に「オッズ条件は本バックテストで棄却・単発成功で恒久化しない」を記録。

#### スコープと限界（過大結論を避けるための明記）
- **71R・4 開催日の小標本**。混戦自体が稀（baseline で 3R）で、効果量の小さい比較はサンプル依存。ただし本決定は
  「複雑化（オッズ条件）を入れない」という保守側の結論で、エンハンス側に改善の挙証責任があるところ全閾値で
  改善が出なかったため、追加複雑化を見送る根拠としては十分。
- 本 ADR は「オッズ条件を入れない」までを決める。**band≥4 ボックスそのものの是非**（box-off がわずかに上回る点）は
  小標本のため確定せず、現行維持として別途より大きなサンプルで再評価しうる。
- 買い方ロジックは現状コード化されておらず（手計算 + harness）、本 ADR は本体実装の変更を伴わない方針決定である。

### ADR 0030: 混戦時の3連複「相手頭数」を広げない（バックテストで棄却） (2026-06-20) — 承認済み

#### コンテキスト
予想の買い方では「混戦」を自動判定し（◎の model 勝率の 0.70 倍以上の馬が ◎含め4頭以上 ＝ `band≥4`）、
印馬の3連複ボックスを別枠で足す（ADR 0028）。通常の3連複は **◎1頭軸ながし・相手 top5**（model 勝率
上位5頭）で買う。買い方ルールはローカル運用（手計算 + harness）で、本体コードには未取り込み。

2026-06-20 函館10R で、◎④（1着）・▲⑥（2着）を当てたが、**3着⑤が model 7番手・単勝25倍**で相手 top5 の
外におり、3連複④⑤⑥（5,110円）を取り逃した（PR #190 のレビュー中に顕在化）。そこで
**「混戦では3連複の◎軸ながしの相手を広く（top5→top7→全頭）流せば、人気薄の3着を拾えて回収率が
上がるのではないか」** という仮説が出た。一方、予算固定（混戦の◎軸ながし3連複枠 ¥1,500）では点数増で
1点が薄くなり、確率重み配分だと低 prob 組が資金から外れるトレードオフがある。

再実行可能な形で検証した。`scripts/predict-check/konsen_backtest.py` のパーサ・確定買い方を再利用し、
**混戦レースの◎軸ながし3連複の相手幅と重み付けだけ**を振った（ワイド=top3・馬連=top5・ボックス=
band[:5]・非混戦は固定で全 variant 共通 → 差分は混戦の3連複相手幅に由来）。

- 測定窓: **2026-04-19 / 05-30 / 05-31 / 06-13 / 06-14 / 06-20 の 105R（うち混戦 90R）**（DB に確率表・
  オッズが揃う全レース）。
- 予想は **market ブレンド無し（model-only）** を使用（市場オッズによるリーク回避）。相手幅の比較は
  同一確率順位への流し違いなので、as-of の漏れがあっても **variant 間の相対比較は公平**。
- 的中は netkeiba の確定払戻（組番一致）で判定。
- 回収率（ROI）の分母は **実際に賭けた額（実消化額）**。点数増で消化額が変わるため、賭けられない予算を
  損失計上せず variant 間を公平に比較する（ADR 0028 と同じ会計）。

#### 決定
1. **混戦時の3連複の相手頭数は現行 top5（◎1頭軸ながし）を維持する。広げない。** 相手を top7・全頭に
   広げると **的中率は上がるが回収率は全 variant で下がった**（後掲）。
2. 重み付けを均等（equal）にしても改善しない。
3. 函館10R の取りこぼしは **単発の事象として恒久ルール化しない**（同じ広げ方を 90 レースに適用すると
   トータルで負ける）。買い方を変える改善はバックテストで改善が出てから採用する（ローカルメモリ
   `feedback_measurement_ordering` と整合）。

##### バックテストによる検証（105R / 混戦90R, model-only 予想・確定払戻）

「混戦3連複的中」= 混戦レースで◎軸ながし3連複が1点でも当たった本数。

| variant（混戦の3連複相手幅・重み） | 全体ROI | 混戦ROI | 混戦3連複的中 |
|---|---|---|---|
| **baseline（top5・確率重み, 現行）** | **87.7%** | **61.0%** | 13/90 (14%) |
| top7・確率重み | 84.4% | 57.2% | 22/90 (24%) |
| 全頭・確率重み | 83.0% | 55.5% | 21/90 (23%) |
| top7・均等 | 84.7% | 57.5% | 23/90 (26%) |
| 全頭・均等 | 82.4% | 54.8% | 20/90 (22%) |

※ 上表は model-only 予想・混戦多発条件下での **variant 間の相対比較用**。絶対 ROI は参考値（「スコープと限界」参照）。

**相手を広げると的中率は狙い通り上がる（14%→22〜26%）が、回収率は全設定で下がる**（混戦 61.0%→
54.8〜57.5%、全体 87.7%→82.4〜84.7%）。広げるほど①外れ目に資金が分散し②当たり1点が薄くなるため、
的中率の増加を配当の減少が上回る。これは買い方の指針である「**高的中・低配当は張る価値が薄い／期待値で
取捨する**」（ローカルメモリ `feedback_betting_staking`）そのもので、広げる方向は EV を悪化させる。

#### 理由
- 函館10R で取り逃した 3着⑤は model 7番手の25倍。これを拾うには相手を大幅に広げるか低 prob 組へ均等に
  資金を撒く必要があるが、**それを 90 レースに一律適用すると、たまに当たる穴の配当より、外れる広い目への
  資金流出が大きい**。1レースの結果（広げれば防げた）は、母集団では逆符号になる典型例。
- 予算固定（◎軸ながし3連複 ¥1,500＝最大15点/100円）では、相手 top5 は C(5,2)=10点で枠内に収まるが、
  top7（C(7,2)=21点）以上は枠を超え、確率重みでは低 prob 組が資金配分から外れ、均等にすると本線1点が
  薄くなる。どちらも回収を底上げしない。
- ボックス（band[:5]）と非混戦の買い方は全 variant 共通に固定したため、差は純粋に「◎軸3連複の相手幅」に
  由来する。

#### 影響
- 買い方ルールに変更なし（3連複の相手は top5 を維持）。本体コード（`build_portfolio`）の挙動も変更なし。
- ローカルメモリ `feedback_betting_staking` に「混戦3連複の相手拡大は本バックテストで棄却（的中率↑/ROI↓）」を記録。

#### スコープと限界（過大結論を避けるための明記）
- **model-only 予想は確率が平たく出るため 105R 中 90R が混戦判定**（実運用の市場ブレンド α=0.3 込みより
  混戦は多くなる）。よって **絶対 ROI は参考値**で、信頼すべきは **variant 間の相対順位**（広げる→ROI 低下）。
- 105R・6 開催日の中規模標本。ただし本決定は「複雑化（相手拡大）を入れない」という保守側の結論であり、
  エンハンス側に改善の挙証責任があるところ、全 variant で改善が出なかったため見送る根拠としては十分。
- 検証ハーネスは `konsen_backtest.py` を拡張した使い捨てスクリプトで、本 ADR には結果表を自己完結で
  載せる方針とした（恒久コードとしては残さない）。再評価が必要なら同 harness を同様に拡張して回す。
- 買い方ロジックは現状コード化されておらず（手計算 + harness）、本 ADR は本体実装の変更を伴わない方針決定である。

### ADR 0033: 条件付き単勝（単勝EV≥閾値の馬だけ）を追加しない（バックテストで棄却） (2026-06-21) — 承認済み

#### コンテキスト
現行の買い方は **3券種（ワイド¥1,500/馬連¥1,500/3連複¥2,000）の◎1頭軸ながし**（合計¥5,000）。
単勝は「高的中・低配当」に終わりやすく EV が薄いと判断して対象外にしてきた。

「model の win 確率 × 単勝オッズ ≥ 閾値（＝期待値 EV）を満たす馬だけ単勝を追加買いすれば
プラス EV を拾えるのではないか」という仮説が出た（Issue #208）。具体的には

- 条件: `model_win_prob / 100 × win_odds ≥ EV_threshold`（閾値 = 1.0 / 1.1 / 1.2）
  　`model_win_prob` は %スケール（0〜100）なので /100 で実数化してから `win_odds`（払戻倍率）を掛ける
- 発動馬 1 頭あたり ¥500 の枠を均等分配（最大 5 頭まで）
- 予算モード: **add**（3券種 ¥5,000 に ¥500 を上乗せ）と **split**（3券種を按分縮小して ¥500 を捻出）の 2 種

再実行可能な形で検証した。`scripts/predict-check/gen_win_backtest_data.sh` でデータを準備し、
`scripts/predict-check/win_backtest.py` でバックテストを実施した。

- 測定窓: **2026-05-30 / 05-31 / 06-13 / 06-14 の 71R**（DB に確率表・単勝オッズ・結果が揃うレース全件）
- 予想は **market ブレンド α=0.3**（通常運用と同一設定）。
- 的中は netkeiba の確定払戻で判定。
- 回収率（ROI）の分母は実消化額。

#### 決定

**条件付き単勝は追加しない。現行 3 券種構成を維持する。**

全閾値・全予算モードで baseline（3 券種のみ）を下回った。

##### バックテスト結果（71R / α=0.3 / 確定払戻）

| variant | 回収率 | 差分（対 baseline） | 単勝発動 |
|---|---|---|---|
| baseline（3 券種のみ） | **79.5%** | — | — |
| +win≥100%/add | 76.0% | −3.5pt | 344 回 |
| +win≥100%/split | 74.5% | −5.0pt | 344 回 |
| +win≥110%/add | 76.0% | −3.5pt | 340 回 |
| +win≥110%/split | 74.5% | −5.0pt | 340 回 |
| +win≥120%/add | 76.0% | −3.5pt | 327 回 |
| +win≥120%/split | 74.5% | −5.0pt | 327 回 |

#### 理由

1. **発動頻度が高すぎる**: 71R で 327〜344 回（1レース平均 4.6〜4.9 頭）が閾値を超えた。
   モデルが EV≥100% と判定した単勝が手当たり次第に発動しており、「絞り込みの効果」が出ていない。
2. **単勝市場の効率性**: モデルの win prob は市場の単勝オッズと高度に相関する（ADR 0027 参照）。
   「model × odds ≥ 1.0」を満たすには model が市場より高い win prob を付けた馬を選ぶが、
   この差分は真のエッジを示さず単なるモデル誤差のノイズに過ぎなかった。
3. **split モードの追加悪化**: 3 券種の予算を単勝に振り向けると本線の賭金が薄くなり、
   ワイド・馬連・3連複の当たりが細くなる。add より概ね 1.5pt 悪い（add −3.5pt / split −5.0pt）。
4. **閾値を上げても改善しない**: 100%/110%/120% いずれも同じ回収率（add −3.5pt）で差がない。
   閾値 EV でのスクリーニングはこのモデル・オッズ組合せでは機能しなかった。

#### 影響

- 買い方ルールに変更なし（3 券種構成を維持）。
- ローカルメモリ `feedback_betting_staking` に「単勝 EV≥閾値の条件付き単勝は本バックテストで棄却」を記録。

#### スコープと限界

- 71R（4 開催日）の標本。単勝は払戻分散が大きいため N が小さいが、
  本決定は「追加しない」という保守側の結論であり、全閾値・全モードで改善が出なかったため棄却根拠として十分。
- モデルは win prob を `blend-alpha 0.3`（市場 30% ブレンド）で算出。
  モデルが市場と完全に独立な予測力を持つ場合は異なる結果になりうるが、
  現行モデルの精度（ADR 0027 参照）では確認できなかった。

#### 関連

- Issue: #208
- ハーネス: `scripts/predict-check/gen_win_backtest_data.sh` / `scripts/predict-check/win_backtest.py`
- 参照 ADR: 0027（モデル精度は市場ブレンドで決まる）、0028（混戦オッズ条件棄却）
- ローカルメモリ（リポ外）: `feedback_betting_staking`

### ADR 0039: 上位近接時の2軸フォーメーションの棄却 (2026-06-27) — 棄却

#### コンテキスト

現行の買い方ルール（CLAUDE.md「表記規約」）はフォーメーションを「この PJ では基本不使用」とし、
買い目は ◎1頭軸ながし or ボックスを基本とする。しかし上位人気・上位モデル評価が近接（co-favorite）
したレースでは、◎を1頭に固定すると「◎がコケたら全滅」というもろさがある。モデル勝率が拮抗した
2頭を2軸にした方が、どちらが勝っても拾えて期待回収率・的中率とも改善する可能性がある（#241）。

動機の実例（2026-06-27 福島R7）: モデル ③20.7% / ⑤19.4% がほぼ並び（市場でも単 3.3 / 3.5 の
1・2番人気）。③単軸だと③が飛んだ時に総崩れだが、③⑤2軸なら⑤×穴で拾える、という仮説。

発動条件 `prob(○) ≥ θ × prob(◎)`（θ を 0.80/0.85/0.90 で掃引、混戦判定の 0.70 より厳しめ）を
満たす近接レースに限り、baseline（◎1頭軸ながし）を以下の2軸 variant に差し替えてバックテスト比較した。
`scripts/predict-check/formation_backtest.py` を新設し、確定買い方（¥5,000・ワイド/馬連/3連複）に
機械適用した。

- **union2**（OR 意味論 / Issue の狙いに直結）: 各券種を ◎脚 / ○脚に予算折半。ワイド・馬連は
  ◎-相手 ∪ ○-相手、3連複は ◎軸ながし ∪ ○軸ながし。◎が飛んでも ○×穴で拾う。◎○両方を含む目は
  ◎脚に寄せ二重計上を避ける。
- **pair2**（AND 意味論 / 表記規約のフォーメーション定義に厳密準拠）: 全券種で ◎○両方必須。
  ワイド・馬連は ◎-○ に集中、3連複は ◎○2頭軸ながし（◎-○-相手）。

#### 決定

2軸フォーメーションは採用しない。現行の **◎1頭軸ながし** を維持する。`formation_backtest.py` は
将来の再評価のために残す。

#### バックテスト結果（2026-05-30〜06-21 の win オッズ・結果が揃う 127R, α=0.2, m=10）

##### 発動部分集合（近接レースのみ）での比較

| θ | 発動R | variant | 回収率 | 的中率 | σ(1レースROI) |
|---|---|---|---|---|---|
| 0.80 | 40 | baseline | 65.7% | 42% | 100.9 |
|      |    | union2   | **69.1%** | 72% | 61.8 |
|      |    | pair2    | 39.2% | 15% | 102.9 |
| 0.85 | 31 | baseline | 74.9% | 48% | 107.4 |
|      |    | union2   | 69.6% | 77% | 59.7 |
|      |    | pair2    | 31.5% | 13% | 90.3 |
| 0.90 | 19 | baseline | 78.2% | 53% | 108.3 |
|      |    | union2   | 78.0% | 89% | 59.4 |
|      |    | pair2    | 33.0% | 11% | 98.6 |

##### 全 127R 通し（非発動=baseline・発動時のみ差替え）の総回収率

| θ | strategy | 回収率 | 的中率 |
|---|---|---|---|
| 0.80 | baseline | 76.1% | 54% |
|      | union2   | 77.3% | 63% |
|      | pair2    | 67.8% | 45% |
| 0.85 | union2   | 74.9% | 61% |
| 0.90 | union2   | 76.1% | 59% |

（baseline は θ 非依存で全体 76.1%。pair2 は θ=0.85/0.90 でも 65.5% / 69.4% と一貫して悪化。）

#### 理由

- **pair2 は全閾値で壊滅的に悪化**（部分集合 ROI 31〜39%・的中 11〜15%）。◎○の両方が上位に来ないと
  全券種が空振りする構造で、近接＝拮抗（どちらかが負けやすい）局面ほど両崩れ確率が高く、AND 集中は
  最悪の組み方だった。表記規約どおりの「フォーメーション基本不使用」を裏付ける結果。
- **union2 は回収率の改善が確認できなかった**。部分集合 ROI は θ=0.80 で +3.4pt（65.7→69.1）だが、
  隣接する θ=0.85 で −5.3pt（74.9→69.6）、θ=0.90 でフラット（78.2→78.0）と**符号が反転**する。
  全体回収率でも θ=0.80 で +1.2pt・θ=0.85 で −1.2pt・θ=0.90 でフラットと、閾値を少し動かすだけで
  優劣が入れ替わる。これは安定したエッジではなく**標本ノイズ**（発動 19〜40R と小標本）の兆候。
- union2 は的中率を 42%→72〜89% に激増させ分散をほぼ半減させるが、**回収率が伴わない**。これは
  CLAUDE.md「レース選択基準」が無価値と断ずる典型的な「高的中・低配当」。◎○を両軸に広げると当たり
  やすくなるが、当たる目が低配当の本命決着に偏り、外れ目（◎-穴 / ○-穴）に資金が分散して期待値は
  伸びない。EV/回収率を判定基準とする本 PJ の方針では採用根拠にならない。
- 動機だった福島R7（③20.7/⑤19.4, θ≈0.94）が属する最も近接した帯（θ=0.90）でも union2 は
  baseline とフラット。**動機ケースの帯でもエッジは出なかった**。

これは ADR 0030（混戦時の3連複相手拡大の棄却）と同型である。買い目を広げて的中率を上げても、
分散した資金が低配当の当たりにしか乗らず回収率が改善しない、という同じ構造。

#### 検証上の留保（結論には影響しない）

- **baseline は混戦ボックスを含まない簡略対照**。本バックテストの baseline は純粋な「◎1頭軸ながし」配分で、
  CLAUDE.md の本番ルールが近接（≒混戦: ◎勝率 0.70 倍以上が 4 頭以上）局面で自動付与する3連複ボックス保険を
  含まない。よって発動帯（θ=0.80〜0.90）の絶対 ROI は本番挙動を過小評価しうる。ただし本 ADR は「2軸 vs ◎1軸」
  の単一変数比較であり、混戦ボックスは両 variant に等しく欠くため**相対比較（フォーメーション棄却）は揺るがない**。
- **union2 の実張額は脚別の 100 円丸めで baseline よりわずかに小さい**（各券種を 2 脚に折半する際 `750 // 100 = 7` 口で
  ¥700/脚となり、ワイド・馬連で計 ¥200/レース未消化）。回収率の分母は実張額（賭けられない予算は計上しない）なので
  per-yen の比較は公平だが、絶対エクスポージャは variant 間で完全対称ではない。これも結論（union2 が回収で勝てない）を
  変えない。

#### 影響

- CLAUDE.md の買い方ルールは変更しない（「フォーメーション基本不使用」「相手 top5・◎1頭軸ながし」を維持）。
- `scripts/predict-check/formation_backtest.py` を新設し残す（再評価用）。
- `scripts/predict-check/gen_win_backtest_data.sh` に対象期間・α・analyze バイナリパスの
  環境変数オーバーライド（`PADDOCK_BT_FROM` / `PADDOCK_BT_TO` / `PADDOCK_BT_ALPHA` /
  `PADDOCK_ANALYZE_BIN`）を追加。既定値は従来どおりで後方互換。
- θ 軸は 0.80/0.85/0.90 を評価。0.80 未満（混戦帯 0.70 へ接近）は混戦ボックスと役割が重複し、
  本 ADR の射程外とする。シグナル定義（券種ごとの配分比・相手幅）を変える場合は再スイープ余地を残す。

win オッズ・結果が揃う期間でデータを生成し（analyze は別 worktree のビルドも流用可）、


### ADR 0040: EV ゲート閾値（ROI≥100%）引き下げの棄却と較正検証の保留 (2026-06-27) — 棄却

#### ステータス

棄却（閾値引き下げ）／較正検証は #249（要 #248 のデータ）で保留

#### コンテキスト

「+EV(ROI≥100%) の買い目が全然来ない。方針が合っているのか不安」という問題提起を起点に、
2026 年に +EV レースが実際どれくらいあったかを調査した（2026-06-27 の調査セッション）。

DB に保存済みのオッズと `scripts/predict-check/live_ev.py`（買い目＝ワイド・馬連・3連複の3券種
ROI = 期待回収率）で、保存データから再評価した。+EV 判定は結果を使わず、発走前オッズ × モデル
勝率（Plackett-Luce）の **期待 ROI** で行うため、オッズと予想確率さえあれば事後に再計算できる。

DB の在庫は 2026 年で実質 8 開催日・161R。うち**4券種オッズ（単勝＝α ブレンド入力／ワイド・馬連・
3連複＝買い目）が揃って厳密に EV 評価できたのは 2026-06-21・06-27 の 69R のみ**だった
（ワイドは `race_odds` 最新値に直近2開催しか残らず、
時系列 `race_odds_snapshots` も 06-27 分しか無い。データ保持の課題は #248）。

この調査結果を受けて、買い方ルールの EV ゲート閾値（CLAUDE.md「レース選択基準」の ROI≥100%）が
厳しすぎないか＝閾値の妥当性を再検証した。

#### 決定

**EV ゲート閾値 ROI≥100% を維持する。閾値の引き下げは採用しない。**
推定 ROI の較正検証（予測 ROI が実現 ROI の偏りのない推定か）は、検証に必要なデータが現状 DB に
無いため実施できず、#248（最終オッズの snapshot 保存）でデータが揃ってから #249 で行う。

#### 理由

- **ROI 100% が損益分岐、>100% が +EV**。ROI = 期待払戻 ÷ 賭金 で、「ROI≥100% のレースだけ張る」は
  期待値が非負の局面だけを取る運用。閾値を 90% 等に下げる＝**期待値マイナス（ROI<100%）のレースを
  承知で買う**ことで、長期では必ず負ける。閾値は自由に動かせるツマミではなく、エッジの有無を分ける境界そのもの。
- **平均 ROI が券種フェア値とほぼ同水準（やや負側）＝モデルに平均的なエッジは無い**（ここでの
  「較正」は「市場と平均的にほぼ等価」の意味であり、予測 ROI が実現 ROI の偏りのない推定かという
  真の較正＝下記の #249 は別問題で未検証）。厳密評価できた 69R の予測平均 ROI は **73.1%**。本戦略が
  使う券種の JRA 控除率（ワイド・馬連 22.5%／3連複 25%）が示すフェア ROI ≈ **75〜77.5%** を
  数 pt 下回り、平均的なエッジは無い（やや負側）。+EV は控除率を食い破るほど
  市場が歪んだ稀なレースだけに出る。**構造的に稀**であり、買い目が来ないのは機能不全ではなく
  ゲートが正しく −EV を弾いている証拠。
- **ゲートが過剰に弾いている兆候は無い**。
  - 予測側: 厳密評価 69R（ワイド込み, α=0.2）の ROI 分布は 平均 73.1% ／ 最高 97% ／ +EV(≥100%) 0本
    （90〜99% が 4本、80〜89% が 17本、70〜79% が 22本、70% 未満が 26本）。α=0.3 でも +EV 0本で変わらず。
  - 実現側: 結果のある 71R の実現 ROI は `konsen_backtest.py` baseline で **83.9%**（box-off variant は 84.0%、ADR 0028）。
    この baseline は予測側 `live_ev` と同一構造（ワイド・馬連・3連複＋混戦時の3連複ボックス追加）で、
    ワイド配当も netkeiba result.html の払戻から算入済み（ワイド込み）。なお ADR 0039 の formation baseline
    76.1%（127R）は**混戦ボックス非追加の簡略対照**（0039 の留保参照）で構造が異なるため、ここでの比較対象には採らない。
  - 予測・実現とも 100% を割っており、閾値直下に「本来買うべきレース」が溜まっている形跡は無い。
  - 弱い示唆として、フェア値（同構成で ≈76.5%）に対し実現 83.9% は上回り・予測 73.1% は下回ると**逆符号**。
    ただし符号は買い目構造・標本に依存し（ボックス非追加の 0039 baseline 76.1% は概ねフェア同水準）、
    かつ両者は**別レース群**（実現=05-30〜06-14 ／ 予測=06-21・06-27）で同一レースのペア比較ができて
    いないため、推定の偏り（較正）は確定できない → 較正の宿題（#249）。
- **較正の本検証に足る標本がまだ無い**。較正を厳密に測るにはワイド込みオッズと結果が同居するレースが
  必要だが、**DB 単一ストアでは同居しない**——`race_odds` でワイドがあるのは 06-21・06-27 のみで、
  この2日は DB `results` 表が空（古い 05-30〜06-14 は DB に結果があるがワイドが無い）。
  ただし結果自体は netkeiba から取得できる（ADR 0039 / #247 の 127R backtest が実際にそうしている）ため、
  **06-21 の 35R（ワイド=DB＋結果=netkeiba 取得可）だけは予備的な較正が技術的には可能**（06-27 も
  ワイドはあるが調査時点（2026-06-27）で当日開催ゆえ確定結果が未生成のため対象外）。しかし単日・35R の小標本で、しかも 06-21 の
  オッズは午後取得＝ほぼライブだが発走前の最終確定ではないため、ゲート位置を動かす確証には足りない。
  確証ある較正は #248 で全開催の最終オッズ snapshot を積んでから #249 で行う。本 ADR では数字を確定させない。

#### 検証上の留保（結論には影響しない）

- **保存オッズの鮮度**: 06-27 のオッズは当日（2026-06-27）朝（09〜12時 JST）取得で確定前、06-21 は午後取得で
  ほぼライブ。発走直前の最終オッズではないため、最終的な +EV 本数は厳密値ではない（より確定に近い
  オッズで僅かに変動しうる）。最終オッズの定常保存は #248。
- **過去ライブ +EV は再現不可**: 古い開催の保存オッズは当時のライブ値と一致しない。例えば
  2026-06-20 函館12R は履歴ログでは ◎④1.7倍 / model 35% / ROI≈125%（当時のライブで +EV 判定）だが、
  DB は ◎④2.7倍 / model 25% で再現できない。よって「2026 年の年間 +EV 本数」を保存データから
  厳密集計することは現状できず、記録に残るライブ +EV は 06-20 の1本のみ。

#### 影響

- CLAUDE.md「買い方ルール／レース選択基準」の **ROI≥100% は変更しない**。
- 較正検証（予測 ROI バケット × 実現 ROI）は **#249** で実施。前提データは **#248** が供給する
  （ブロッカー: #248）。
- 本調査の再評価スクリプト・中間データは再現用に保持（リポジトリ未コミット）。`live_ev.py` を
  そのまま過去 snapshot に当てれば、#248 蓄積後に年間 +EV 発生率を厳密に出せる。

#### 再現方法

保存済みオッズ（再 fetch なし）に `analyze predict` と `live_ev.py` を当てて全3券種 ROI を出す:

```sh

# （netkeiba 再 fetch はしない＝保存済み race_odds のみを使用）

```

ワイドが揃うのは現状 06-21・06-27 のみ。それ以外の日はワイド欠落で ROI が過小評価される
（買い目の一部に配当が無く分子に寄与しないため）。

### ADR 0041: 馬連特化（馬連 EV≥閾値）買い目戦略の棄却 (2026-06-27) — 棄却

#### ステータス

棄却（#252・#246 較正後に再評価し棄却維持。末尾「再評価（#252・#246 較正後）」節を参照）

#### コンテキスト

現行の買い方ルール（CLAUDE.md「買い方ルール」）はワイド+馬連+三連複の3券種ポートフォリオ
（◎1頭軸ながし）。だが運用上 **「ROI≥100% で張れる鞍が極端に少ない」** という課題がある。
2026-06-27（3場36鞍）の手作業実測で、フルポートフォリオで ROI≥100% はわずか2鞍だった一方、
「濃い +EV 馬連（EV≥1.2）」を1点以上持つ鞍は約14鞍あった。

仮説（#250）: **+EV は馬連に集中しているのに、ワイド（構造的低EV）と三連複（高分散）が全体EVを
希薄化し、張れる鞍を潰している**。馬連に絞れば −EV 閾値を下げずに張れる局面（frequency）を
増やせるのではないか。

ただし #250 自身が「+EV 馬連の多くは穴絡みの高オッズ・低的中で、モデルEVが過大に出やすいゾーン
（#246）。額面EVでの単発買いはノイズを掴むリスクがある」と警告しており、feel で採用せず
バックテストで検証することを条件としていた。本タスクのスコープは**馬連のみ**（馬単は #246 の
較正後に別途。穴の馬単 EV はノイズ掴みリスクが高いため）。

`scripts/predict-check/umaren_backtest.py` を新設し、◎1頭軸ながし（軸=◎の1頭固定, #241 準拠。
相手は CLAUDE.md の top5 に限らず**全頭**から抽出する。+EV は穴に偏り top5 では捕れないため）のうち
馬連 model EV（`p_top2_set(◎,相手) × 馬連オッズ`）が閾値 θ 以上の点のみを買う戦略を、
配分（flat=均等 / weighted=馬連的中確率重み）・閾値（θ=1.0/1.2/1.5）・オッズ上限（cap=∞/50/30/20）で
掃引して比較した。

##### 検証設計上の核心2点

- **EV フィルタと払戻清算でオッズ源を分離した（循環回避）**。EV≥θ のフィルタに使う DB 盤面オッズ
  （`race_odds`）と、的中時の払戻を同じオッズで清算すると「EV≥θ の点は当たれば必ず θ 倍返る」
  恒真化で本戦略が不当有利になる。よって **フィルタ＝DB 盤面オッズ／清算＝実払戻（netkeiba
  result.html の実配当）** と分離した。これによりモデル確率の較正不良（穴過大評価, #246）が
  実 ROI に正しく反映される。
- **対照 baseline_pf は wide を含まない**。馬連・三連複の盤面オッズは結果ありレースで全 71R 揃うが、
  wide オッズは履歴欠落（fetch_wide.py が直近ライブ用に取った別レース群にしか無く、結果ありレースと
  交差ゼロ）。#250 の主張は「wide が EV を希薄化」なので、wide 抜き baseline はむしろ**強い対照
  （steel-man）**。新戦略が wide 抜き baseline すら上回れなければ結論は頑健。

#### 決定

馬連特化（馬連 EV≥閾値）戦略は採用しない。現行の3券種ポートフォリオ（◎1頭軸ながし）を維持する。
`umaren_backtest.py` は将来の再評価（特に #246 較正後）のために残す。

#### バックテスト結果（2026-05-30〜06-14 の 71R, α=0.2・m=10）

発動部分集合（＝実際に賭けた鞍）のみで集計。回収率の分母は実張額。判定は ROI / 的中 / σ（スケール
不変）で行う。maxDD(円) は戦略間で予算が異なる（baseline_pf ¥3,500 / top5 ¥1,500 / 全頭 flat・umaren
¥5,000）ためスケール非不変＝直接比較不可（参考列）。

| 戦略 | 張鞍/71 | ROI | 的中率 | σ(1R ROI) | maxDD(円,参考) |
|---|---|---|---|---|---|
| baseline_pf（馬連+三連複−wide, model ROI≥100% ゲート）| **1** | 196.6% | 100%(n=1) | 0.0 | 0 |
| 参考: 馬連 ◎軸 top5 ながし（無フィルタ・¥1,500）| 71 | **79.0%** | 42% | 107.2 | 23,590 |
| 参考: 馬連 ◎軸 全頭ながし（無フィルタ・flat・¥5,000）| 71 | **66.4%** | 52% | 125.1 | 119,310 |
| 馬連特化 θ=1.0 cap∞（#250 素案）| 71 | 43.7% | 4% | 255.9 | 224,470 |
| 馬連特化 θ=1.2 cap∞ | 71 | 49.9% | 1% | 417.3 | 260,000 |
| 馬連特化 θ=1.5 cap∞ | 68 | 0.0% | 0% | 0.0 | 340,000 |
| 馬連特化 θ=1.0 cap50 | 28 | 43.2% | 4% | 224.5 | 80,000 |
| 馬連特化 θ=1.0 cap30（規律版で最良）| 13 | 93.1% | 8% | 322.4 | 35,000 |
| 馬連特化 θ=1.0 cap20 | 5 | 242.0% | 20% | 484.0 | 15,000 |
| 馬連特化 θ=1.2 cap30 | 4 | 0.0% | 0% | — | 20,000 |

（flat と weighted はほぼ同値。cap∞ weighted は θ=1.2 で 57.5% と最高だが的中 1%で実態は同じ。
cap20/θ=1.0 の 242% は 5 鞍のみの小標本ノイズ。全行は `umaren_backtest.py --cap-grid inf,50,30,20` の
出力を参照。）

#### 理由

- **馬連特化は frequency を 1→71 鞍に激増させるが、それは見せかけ**。EV フィルタは全レースで
  極端な穴（馬連オッズ 76〜720 倍・モデル勝率 0.6〜2%）を選抜する。`0.6% × 720倍 = EV4.0` のように、
  モデルが穴の勝率を過大評価しているため（#246）ほぼ全鞍で「偽の +EV」が量産される。張れる鞍が
  増えるのは −EV ノイズを買っているだけで、realized ROI は 44〜58%（θ=1.5 では 68 鞍で的中 0・ROI 0%）
  に崩壊する。**「張れる鞍を増やす」目的は達成されるが無価値**（CLAUDE.md「高的中・低配当は無価値」の
  逆パターン＝低的中・偽高配当期待）。
- **EV フィルタは無フィルタより realized ROI を悪化させる＝逆予測的**。これを交絡なく示すため、
  universe（全頭）と配分（flat・¥5,000）を umaren_only と完全に揃え、**EV フィルタの有無だけ**を変えた
  apples-to-apples 対照「馬連 全頭ながし 無フィルタ flat」を置いた。結果は **無フィルタ 66.4%（的中 52%）
  → EV≥1.0 フィルタ 43.7%（的中 4%）** と、フィルタを入れるほど悪化する。つまり「相手範囲を top5→全頭に
  広げたこと」ではなく **model EV ランキングそのものが逆予測的**（高 EV と判定した点ほど当たらない）。
  さらに堅めの ◎軸 top5 無フィルタ（¥1,500）は 79.0%・的中 42% で、どの馬連特化構成よりも良い。
  閾値を上げる（θ=1.5）ほど純粋に穴の尾だけが残り的中 0% になる。
- **オッズ上限で穴を除外しても ROI≥100% を意味ある鞍数で満たす構成は無い**。cap30/θ=1.0 が
  最良（13 鞍・ROI 93.1%）だが 100% に届かず、cap20/θ=1.0 は 242% だが 5 鞍の小標本ノイズ。
  cap を絞るほど発動鞍が減り、#250 の主目的（frequency 増）と両立しない。
- **根本原因は券種選択ではなくモデルの較正不良（#246）**。+EV が馬連に「集中して見える」のは穴の
  勝率過大評価の副作用であり、馬連に絞っても較正不良の上に張るだけ。frequency 問題は #246 の較正を
  先に解決しない限り、券種ポートフォリオの組み替えでは解けない。

これは ADR 0033（条件付き単勝の棄却: 単勝市場がモデル win prob と高相関でエッジが出ず）と同型で、
「額面 model EV の閾値抽出は較正不良ゾーンでノイズを掴む」という同じ構造である。

#### 検証上の留保（結論には影響しない）

- **baseline_pf の発動 1 鞍は n=1**。ROI 196.6%・的中 100% は単一の偶然で統計的意味はない。
  ここで示したいのは「現行ルールの ROI≥100% ゲートが 71R で 1 鞍しか通さない」という frequency 課題の
  再現であり、その絶対 ROI ではない。
- **wide を baseline から除外**（履歴オッズ欠落）。ただし #250 の主張に照らせば wide 抜きは強い対照で
  あり、馬連特化が勝てない結論は揺るがない（むしろ wide を足せば baseline はさらに張れなくなる方向）。
- **2026-06-27（仮説を生んだ当日）は母集団に含めない**（look-ahead / 過学習回避）。
- **フィルタ源と清算源の独立性は「盤面スナップショット→締切までのオッズドリフト分」に限る**。馬連は
  パリミュチュエルで盤面オッズと最終配当がほぼ一致するため、循環は完全には消えない。ただし残存する
  相関は本戦略を**実際より良く見せる方向**であり、それでも崩壊する以上、棄却結論はより頑健になる。
- **馬単はスコープ外**（#246 較正後に別途検証）。本 ADR の棄却は馬連特化に限る。

#### 影響

- CLAUDE.md の買い方ルールは変更しない（3券種ポートフォリオ・◎1頭軸ながし・相手 top5 を維持）。
- `scripts/predict-check/umaren_backtest.py` を新設し残す（再評価用。馬単対応や #246 較正後の再走に流用）。
- frequency 課題（張れる鞍が少ない）は #246（穴の1着過大評価の較正）に依存することが定量的に裏付けられた。
  券種選択での解決は #246 完了後に再検討する。

#### 再評価（#252・#246 較正後）

ステータスは **棄却を維持**する。

本 ADR は棄却の根本原因を「モデルの穴1着過大評価（#246）で馬連 model EV が逆予測的」と特定し、
「#246 較正後に再走する」ことを条件としていた。#246（穴1着確率の冪変換較正・ADR 0042）が merged
（PR #256）されたため、**同一窓（2026-05-30〜06-14 の 71R）・同一設計**で較正後モデルを再ビルドして
再走した（#252）。較正が効いていることは、**model EV に依存するセル**が較正前テーブルと変化したこと
（baseline_pf 196.6%@1R→24.5%@13R、umaren θ=1.0 cap∞ 43.7%→29.1% 等）で確認した。一方、「馬連 全頭
ながし 無フィルタ flat」行は 66.4%/的中 52%/σ125.1 と**較正前後で不変**だった。これは相手配分が均等
（flat・全頭）で model 勝率に非依存、かつ軸◎が較正前後で不変（冪変換は単調で argmax を保存）だったため
当然で、較正が清算機構や selection 非依存の賭けを壊していないことのサニティチェックになっている。

##### 較正後バックテスト結果（71R, α=0.2・m=10。flat。weighted もほぼ同値）

| 戦略 | 張鞍/71 | ROI | 的中率 | σ(1R ROI) |
|---|---|---|---|---|
| baseline_pf（馬連+三連複−wide, model ROI≥100% ゲート）| 13 | 24.5% | 15% | 58.2 |
| 参考: 馬連 ◎軸 top5 ながし（無フィルタ・¥1,500）| 71 | **78.7%** | 42% | 104.7 |

##### 棄却を維持する理由

- **逆予測は較正後も解消していない**。universe（全頭）と配分（flat）を揃え EV フィルタの
  有無だけを変えた apples-to-apples 対照で、**無フィルタ 66.4% → EV≥1.0 フィルタ 29.1%** と
  フィルタを入れるほど悪化する（無フィルタ 71 鞍／フィルタ 70 鞍。較正で 1 鞍が EV≥1.0 を満たす点を失い
  脱落したぶんのズレ。較正前は 71 vs 71 で完全一致だった）。較正前（66.4%→43.7%）より**むしろ悪化**して
  おり、model EV ランキングが高 EV と判定した点ほど当たらない構造は #246 較正では解消しなかった。この
  結論は単一比較の有意性ではなく、**θ=1.0 系が全 cap で無フィルタ（66.4%）を下回り**、66.4% を超えるのは
  θ=1.2 capped 系（張鞍 6〜14・的中各1鞍のアーティファクト＝第2項参照）に限られる、という分布全体の
  形に基づく。
  **本 ADR が当初想定した「#246 較正で逆予測（frequency 課題の根因）が解ける」という仮説は、本窓では
  支持されなかった**（券種選択ではなく model EV ゲートの校正そのものが課題＝後述の副次的発見・#263）。
- **>100% を満たすのは小標本・cap 限定アーティファクトのみ**。θ=1.2 cap30（10鞍 121.0%・的中 10%・
  σ363）・cap20（6鞍 201.7%・σ451）が 100% を超えるが、いずれも的中わずか 1 鞍の高分散小標本。較正前に θ=1.0 で
  出ていた同型アーティファクト（cap30 13鞍 93.1% / cap20 5鞍 242%）が θ=1.2 へスライドしただけで、
  「frequency（張鞍）× ROI」を両立する頑健な構成は無い。cap を絞るほど発動鞍が減る制約も不変。
- **堅め対照に勝てない**。◎軸 馬連 top5 無フィルタ（71鞍 78.7%）を意味ある鞍数で上回る馬連特化構成は
  無い（θ=1.0 は最多発動の cap∞ で 29.1%、capped 系でも 52〜61%）。EV フィルタは依然として無フィルタ・
  無作為より劣る。

→ #250 の主目的「−EV 閾値を下げず張鞍を増やす」は較正後も無価値（低的中・偽高配当）であり、券種を
馬連に絞る戦略は採用しない。現行 3 券種ポートフォリオ（◎1頭軸ながし・相手 top5）を維持する。

##### 副次的発見（本 ADR の射程外・要フォロー）

較正後、baseline_pf の発動が **1鞍/196.6% → 13鞍/24.5%** に激変した。較正（穴縮約＝人気馬確率の上昇・
再正規化, ADR 0042）で**人気馬偏重のポートフォリオが model ROI≥100% ゲートを多く通過するが、実 ROI は
24.5%**（無フィルタ top5 の 78.7% を大きく下回る）。すなわち較正後の model EV ゲートは「低オッズ人気馬で
EV≥100% に見えるが実配当が伴わない鞍」を通しやすい。これは **CLAUDE.md のライブ ROI≥100% ゲートの
含意**であり、馬連特化の可否（本 ADR）とは別問題として切り出し、**#263** で検討する。

なお #252 のもう一つのスコープ外項目「馬単（exacta）特化の 71R バックテスト検証」（順序プレミアムが
実エッジか。馬単は ADR 0043 でライブ採用済みだが 71R 未検証）は **#262** に分離した。

##### 再走コマンド（#252）

較正後バイナリを worktree でビルドし、上記「再現方法」と同手順で `/tmp/bt252` に生成して再走した
（`PADDOCK_ANALYZE_BIN` に worktree の release バイナリを指定。「再現方法」節のコマンド内の `/tmp/bt250` は
すべて `/tmp/bt252` に読み替える）。

### ADR 0042: win_prob 冪変換による穴馬1着過大評価の校正 (2026-06-27) — 採用

#### ステータス

採用（γ=1.25）

#### コンテキスト

確率推定は win スコアをレース内で合計 1.0 に正規化し、Harville モデルで連系・着順確率を導出する
（softmax/temperature なし）。Harville は IIA 的性質から人気薄馬の「1着」確率を過大評価しがちで、
これが穴を絡めた**馬連（着順不問）の EV を馬単（着順固定）より高く**見せる一因になる（#246）。

backtest の人気帯別校正（baseline）でも、この偏りが定量的に確認できた（4891R, α=0.2・m=10）:

| 人気帯 | 平均予測 | 実測勝率 | 偏り |
|---|---|---|---|
| 1番人気 | 26.3% | 28.2% | 過小 |
| 2-3番人気 | 13.9% | 15.0% | 過小 |
| 4-6番人気 | 7.2% | 6.8% | やや過大 |
| 7-9番人気 | 3.7% | 2.9% | 過大 |
| 10番人気以下 | 1.9% | 0.8% | 過大 |

人気馬で過小・穴馬で過大という典型的な favorite-longshot バイアス。

#### 決定

ブレンド後の最終 win に冪変換 `win'_i ∝ win_i^γ`（合計 1.0 へ再正規化）を掛け、人気馬を相対強調して
穴の 1 着を縮約する（`apply_win_power`, `EstimationConfig.win_power`）。backtest sweep で **γ=1.25 を採用**。
`analyze backtest --win-power <γ>` で sweep でき、`production()` は γ=1.25 を既定にする。

冪変換は単調なのでトップ選好馬（argmax）は不変＝単勝的中率・想定回収率は全 γ で同一（31.2% / 75.3%）。
変わるのは確率の大きさ（校正）と、それに依存する EV ベースの買い目選択。穴の 1 着が縮約されるほど
本命→穴の馬単（`harville_exacta`）が馬連より相対的に有利化するため、#246(B) の馬単選択（ADR 0043）と連動する。

#### バックテスト結果（2025-01-01〜2026-06-30 / 4891R, α=0.2・m=10）

##### 単勝校正（全頭エントリ）

| γ | Brier | LogLoss |
|---|---|---|
| 1.0 (baseline) | 0.0544 | 0.1974 |
| **1.25** | **0.0543** | **0.1954** |
| 1.5 | 0.0551 | 0.1969 |
| 2.0 | 0.0581 | 0.2081 |

γ=1.25 が LogLoss 最良（0.1974→0.1954）・Brier も最良タイ。γ≥1.5 は悪化。

##### 人気帯別校正（平均予測 / 実測勝率）

| 人気帯 | 実測 | γ=1.0 | γ=1.25 | γ=1.5 | γ=2.0 |
|---|---|---|---|---|---|
| 1番人気 | 28.2% | 26.3 | 32.1 | 37.5 | 46.7 |
| 2-3番人気 | 15.0% | 13.9 | 14.7 | 15.1 | 14.9 |
| 4-6番人気 | 6.8% | 7.2 | 6.5 | 5.8 | 4.4 |
| 7-9番人気 | 2.9% | 3.7 | **2.9** | 2.2 | 1.2 |
| 10番人気以下 | 0.8% | 1.9 | 1.3 | 0.8 | 0.4 |

γ=1.25 は穴帯（4-6・7-9・10+）の過大評価を縮小（7-9 はほぼ一致、10+ は gap 1.1→0.5）。

#### 理由

- **γ=1.25 が単勝 LogLoss を最良化**し（baseline 比 0.1974→0.1954）、Brier も非劣化。本 issue の核心である
  穴帯の 1 着過大評価を縮小する（10番人気以下 1.9→1.3 / 7-9番 3.7→2.9 で実測一致）。
- **トップ選好・回収率は不変**（単調変換）。校正のみ改善する低リスクな変更。
- **γ≥1.5 は棄却**: 単勝 LogLoss/Brier が悪化し、人気馬を過剰補正する（1番人気 予測 37.5%/46.7% vs 実測
  28.2%）。γ=2.0 では win_prob 肥大で単勝の EV ゲートを誤通過する買い目が急増し過信が顕著。
- 代償として γ=1.25 は 1番人気を過小（-1.9pt）から過大（+3.9pt）へ振らせるが、これは穴帯の改善
  （多数の穴馬が母数を占める）と引き換えで、集計 LogLoss は純改善。買い目側は #246(B) が「馬単は
  EV が馬連を strict に上回るときだけ・tie は馬連」という保守ゲートで過剰な馬単化を防ぐ。

#### 影響

- `EstimationConfig.win_power: Option<f64>` を追加。`Default` は `None`（後方互換 no-op）、`production()` は
  `RECOMMENDED_WIN_POWER = 1.25`。predict / backtest 両経路がブレンド後に `apply_win_power` を適用。
- `analyze backtest --win-power <γ>` を追加（未指定 no-op、再 sweep 用）。`analyze predict` は production 固定。
- 回帰ガード `production_config_is_shrinkage_m10_and_recency_off` に win_power=1.25 の固定を追加。
- 仕様書 `docs/specifications/probability-estimation.md` にステップ 5 を追記。

#### 再現方法

```sh
BIN=./target/release/paddock-analyze
for g in 1.0 1.25 1.5 2.0; do
  PADDOCK_LOG=warn "$BIN" backtest --from 2025-01-01 --to 2026-06-30 \
    --blend-alpha 0.2 --shrinkage-m 10 --win-power $g
done
# 単勝 Brier/LogLoss と「人気帯別（単勝校正）」を比較する。
```

### ADR 0043: 買い目ポートフォリオへの馬単（exacta）導入 (2026-06-27) — 棄却

#### ステータス

**棄却**（#271 で `pick_pair_leg` を撤去し、連系ペアは**常に馬連**へ revert した）。

当初は採用（2026-06-27 福島R7 の 1 鞍を動機に置換ロジックを導入）したが、#262 の 71R バックテストで
順序プレミアムは実エッジでないと判明した（置換は ROI 78.7%→70.1% の純損、馬単 EV シグナルは逆予測。
下記「71R 検証（#262）」参照）。下地（`BetCombination::Exacta`・`RaceOdds.exacta` 取得・`harville_exacta`・
馬単表示・診断 `pair_ev_diagnostics`）は将来の再検証用に温存する。

以下「コンテキスト」「決定」は導入当時の記録（historical）。実装の現状は #271 の revert が正。

#### コンテキスト

predict 本番の買い目生成器 `build_portfolio`（`src/domain/src/portfolio/mod.rs`）は、軸＝本命を
相手に流す「馬連＋ワイド＋三連複」だけを生成し、**馬単（exacta）を候補に出していなかった**（#246）。

Harville モデルは IIA 的性質から人気薄馬の「1着」確率を過大評価しがちで、その結果、穴を絡めた
**馬連（着順不問）の EV が馬単（着順固定）より高く**算出される傾向がある。しかし実戦では「人気薄は
2〜3着はあっても1着は薄い」ケースが多く、本命→穴の馬単に切り替えると配当プレミアムが取れる局面がある
（動機: 2026-06-27 福島R7。馬連 192.1 倍 → 馬単 253.6 倍）。馬単を候補に出せないことでこのエッジを
取りこぼしていた。

下地はすでに揃っていた: `BetCombination::Exacta(OrderedPair)`、`RaceOdds.exacta`（odds scraper /
DB gateway とも populate 済み）、`harville_exacta`、predict の馬単表示（`format_combination`）。

#### 決定

> **#271 で撤回**: 下記の置換ロジックは #262 の 71R 検証（後述「71R 検証（#262）」）で純損と確定したため、
> `pick_pair_leg` を撤去し連系ペアは**常に馬連**へ revert した。以下は導入当時の設計記録（historical）。

`build_portfolio` の「馬連バケット」を**連系ペアバケット**と再解釈し、軸-相手の各ペアで
`Quinella(軸,相手)` と `Exacta(軸→相手)` の実効 EV（`leg_ev` = 的中確率 × オッズ、収支シミュレータ
`simulate` 委譲）を比較して、**EV が高い方を 1 脚だけ採用する**（`pick_pair_leg`）。

- 採用は **両券種のオッズが揃い、馬単が strict に馬連を上回るときだけ**。tie・どちらか欠落は着順不問の
  馬連を維持する（"常に馬単優先とはしない" の担保。issue 補足の方針）。
- 穴の 1 着確率が縮約されるほど `harville_exacta(軸→穴)` が相対的に有利化するため、この選択は #246(A)
  の win_prob 冪変換（ADR 0042）と連動して機能する。

##### 4要素 alloc 化を退けた理由

`PortfolioConfig.alloc:(u32,u32,u32)` を `(馬連, ワイド, 三連複)` から4要素化して馬単を独立バケットに
する案は採らない。理由:

- 馬連と馬単を**並列に**買うと 1 レースの券種が増え、固定予算（既定 ¥5,000）が薄まる。issue の意図は
  並列追加ではなく「同組合せの馬連より優位なら馬単に**置き換える**」。
- 既存テスト（`alloc:(1,1,1)` リテラル多数）と `session.rs` の `PortfolioConfig::default()` 利用を
  壊さずに済む。第1要素を「連系ペア」と読み替えるだけで予算配分・点数・100 円単位ロジックは無改修。

#### CLAUDE.md 買い方ルールとの関係

CLAUDE.md は 3 券種（ワイド/馬連/三連複）を既定とし、馬連を「◎が飛んでも拾える着順不問の保険」と
位置づける。本変更は馬連を**ペア単位で馬単に置換しうる**ため、置換されたペアでは着順不問の保険性が
一部弱まる（issue 承知のトレードオフ）。これを次で緩和している:

- 置換は EV が strict に優位なペアのみ。tie・欠落は馬連維持。
- 三連複ながし・ワイドの保険脚は不変。
- 馬単化は (A) の校正で「穴は1着になりにくい」と根拠づけられたときに発火する設計（恣意的な馬単優先を
  しない）。

将来、置換ではなく併買や発火条件の調整を検討する余地は残す。

#### 影響

- `build_portfolio`: ペア脚生成を `pick_pair_leg` 経由に変更。`PortfolioConfig.alloc` の第1要素は
  「連系ペア（馬連/馬単のうち EV 優位な方）」の意味になる（型・既定値は不変、後方互換）。
- 既存 `build_portfolio` テストは `sample()` が exacta オッズを持たないため全 quinella 採用で無改修通過。
  馬単 swap の新規テストを追加。
- 診断のため `pair_ev_diagnostics`（馬連 vs 馬単 両方向 EV）も同 module に追加（#246-C, ADR 不要の表示）。

#### 再現・検証

```sh
cargo test -p paddock-domain portfolio
# exacta_chosen_when_ev_beats_quinella / quinella_kept_when_exacta_lower_ev /
# exacta_swap_preserves_budget_and_units で swap 挙動と予算・100 円単位の維持を確認。
```

#### 71R 検証（#262）

本 ADR の採用根拠は **2026-06-27 福島R7 の 1 鞍の逸話のみ**（馬連 192.1 倍 → 馬単 253.6 倍）で、
順序プレミアム（model が着順固定配当を正しく EV 化できているか）は 71R 未検証だった。#252 で馬連特化の
EV フィルタが #246 較正後も逆予測（無フィルタ 66.4% → フィルタ 29.1%）と確定したのを受け、同一モデルの
馬単 EV シグナルを `scripts/predict-check/umaren_backtest.py`（馬連特化基盤に exacta を対称追加）で
**71R（窓 2026-05-30〜06-14・較正後バイナリ・α=0.2）** に展開して検証した。EV 判定は DB 盤面オッズ、
清算は result.html 実配当で分離（循環回避）。対象 71R すべてに馬連・三連複・**馬単の盤面オッズが
揃っている（exacta 盤面 71/71）**ため、馬単特化の張鞍数は盤面カバレッジでなく EV フィルタの効果を
純粋に反映する。

##### 結果（較正後モデル）

| 戦略 | 張鞍 | ROI | 的中 |
|---|---:|---:|---:|
| 馬連 top5 ◎軸ながし（無フィルタ・土台） | 71 | **78.7%** | 42% |
| └ うち model EV 優位ペアを馬単(◎→相手)へ置換（58 脚置換） | 71 | **70.1%** | 38% |
| 馬単 top5 両方向 ◎軸ながし（無フィルタ） | 71 | 67.6% | 42% |
| 馬連 全頭 ◎軸ながし（無フィルタ flat） | 71 | 66.4% | 52% |
| 馬単 全頭両方向 ◎軸ながし（無フィルタ flat） | 71 | 60.9% | 52% |
| 馬単特化 EV≥θ（全 θ×cap×flat/weighted の最良）= θ1.0 cap30 flat | 44 | 33.3% | 5% |

##### 判定: 順序プレミアムは実エッジでない

- **`pick_pair_leg` の直接検証で置換は純損**。本 ADR の発火条件（両オッズ present・馬単 model EV が
  馬連を strict に上回るペアのみ ◎→相手へ置換）をそのまま 71R に適用すると、58 脚が置換され
  **ROI 78.7% → 70.1%・的中 42% → 38% と悪化**した。「model 馬単 EV 優位」のシグナルは当たらない側を
  選んでおり、順序プレミアムを取りに行くほど回収率を下げる。福島R7 の 1 鞍は per-window の外れ値で一般化しない。
- **順序プレミアムは単独でもエッジにならない**。EV フィルタ無しでも馬単は馬連を下回る
  （top5: 67.6% < 78.7% / 全頭: 60.9% < 66.4%）。両方向を買うと外れ向きが必ず死に、着順固定配当でも
  倍化したカバレッジを賄えない。的中率は馬連と同値（同一の上位2着条件）なのに ROI だけ劣化する。
  なお top5 比較は重み基底が非対称（馬連=単勝確率 `probs[p]` / 馬単=順序確率 `p_exacta`）なので厳密な
  weight-matched ではない。**重み・配分を完全に揃えた decisive な対照は flat の全頭比較（60.9% < 66.4%）と
  下記 `pick_pair_leg` 直接置換検証**であり、いずれも馬単劣位で結論は揺るがない。
- **馬単 EV フィルタは逆予測（#252 の馬連と同型・より顕著）**。apples-to-apples の無フィルタ 60.9% に対し、
  EV≥θ フィルタはどの θ×cap でも下回り最良でも 33.3%（θ1.0 cap30 flat・44鞍・的中 5%）。θ1.0 系の
  的中は 4〜6% に留まり、**θ≥1.2 の cap 系は的中ほぼ 0**。馬連特化が小標本で見せた >100% アーティファクト
  （θ1.2 cap30 で 121%）すら馬単では一切出ない。

→ 本 ADR が依拠した「穴は1着になりにくい → 本命→穴の馬単に配当プレミアムがある」という仮説は、#246
較正後の 71R では **model EV シグナル経由では取り出せない**。`pick_pair_leg` による馬連→馬単の置換は
**無効化（馬連を常に維持）すべき**。検証は本 issue（#262）で完了し、挙動変更（Rust）は **#271 で
`pick_pair_leg` を撤去し連系ペアを常に馬連へ revert した**（本 ADR はステータス棄却）。

### ADR 0044: 較正後 model-EV ROI≥100% ゲートの精度検証（71R で逆予測的・ルール変更は保留） (2026-06-27) — 知見

#### ステータス

知見（CLAUDE.md ライブ買い方ルールの変更は本 ADR では行わず、推奨と follow-up を記録する。
実ルール変更はユーザー承認＋追検証〔#248 の年間データ蓄積後〕を前提とする）

#### コンテキスト

#252 の馬連再評価（ADR 0041 再評価節）で、#246 較正（ADR 0042: 穴1着の縮約＝人気馬確率の上昇・
再正規化）の副次影響が判明した。現行 3 券種ポートフォリオ−wide（馬連 ◎軸ながし top5 ¥1500 +
三連複 ◎軸ながし top5 ¥2000、確率重み）の **発動ゲート = ポートフォリオ model ROI ≥ 100%** が、
較正前は 71R 中 1 鞍しか通さなかったのに対し、**較正後は 13 鞍に増え、その実 ROI は 24.5%**
（的中 15%）に崩壊する。無フィルタ馬連 top5（78.7%）を大きく下回る。

この model-EV ゲートは **CLAUDE.md レース選択基準「ROI≥100% のレースだけ張る」と同一の計算**
（model 確率 × 市場オッズの期待回収率）であり、較正後にゲートが +EV を誤判定しているなら、
ライブで人気馬偏重の −EV 鞍を量産しうる。本 ADR はゲートの精度を 71R で定量検証する（#263）。

#### 検証設計

`scripts/predict-check/umaren_backtest.py` を拡張（#263）：

- `compute_baseline_pf` で計算（model ROI = 期待回収率）と発動判定を分離し、ゲート閾値・◎単勝
  オッズ下限を掃引可能にした。
- **循環回避**: model ROI（ゲート指標）は DB 盤面オッズ、清算は netkeiba 実払戻（ADR 0041 と同方針）。
- ゲート診断: 通過鞍の ◎（model 1 番手）の市場人気・単勝オッズ・model ROI・実 ROI・的中を出力。
- 掃引: ゲート閾値 {0(無ゲート), 100, 110, 120, 130}% × ◎単勝オッズ下限 {なし, 2, 3, 5} 倍。
- 母集団: 2026-05-30〜06-14 の 71R（馬連・三連複の盤面オッズと結果が揃う全レース、α=0.2・m=10、
  #252 較正後の再生成入力）。2026-06-27 は look-ahead 回避で除外。

#### バックテスト結果（同一 baseline_pf ポートフォリオ・71R）

ゲート閾値だけを変えた apples-to-apples（universe・配分・予算は固定、発動判定のみ変更）：

| 発動条件 | 張鞍/71 | 実 ROI | 的中率 |
|---|---|---|---|
| gate≥0%（無ゲート・全鞍）| 71 | **75.5%** | 48% |
| gate≥100%（現行ルール）| 13 | **24.5%** | 15% |
| gate≥110% | 5 | **0.0%** | 0% |
| gate≥120% | 1 | 0.0% | 0% |
| gate≥130% | 0 | — | — |

◎単勝オッズ下限の付与（断然人気の除外）でも回復しない：

| 発動条件 | 張鞍 | 実 ROI | 的中率 |
|---|---|---|---|
| gate≥100% ◎O≥2 | 10 | 18.3% | 10% |
| gate≥100% ◎O≥3 | 5 | 36.7% | 20% |
| gate≥100% ◎O≥5 | 0 | — | — |
| gate≥0% ◎O≥3（参考）| 22 | 71.1% | 36% |

対照（無フィルタ・全鞍機械買い）: 馬連 ◎軸 top5 ¥1500 = **78.7%**（的中 42%）/ 馬連 全頭 flat ¥5000 = 66.4%（的中 52%）。

##### ゲート診断（通過 13 鞍の内訳）

- 通過 13 鞍は **◎平均単勝 2.72 倍**、非通過 58 鞍は **◎平均単勝 2.50 倍**。◎平均人気はいずれも 1.0
  （α=0.2 ブレンドの結果 model の ◎ は 71R のほぼ全てで市場最上位）。→ **「人気度」は通過/非通過を
  分けない**。当初仮説の「人気馬偏重で通過」は字義どおりには成立せず、より正確には **較正で ◎ アンカーの
  ポートフォリオ model EV が水増しされ、それが実配当を伴わない**。
- 通過 13 鞍のうち的中はわずか 2 鞍（実 ROI 135% と 183%）。残り 11 鞍は的中 0。model ROI は
  100〜127% に分布するが実 ROI 24.5%。

#### 決定（知見）

**較正後の model-EV ROI≥100% ゲートを「+EV レースの選別器」として信頼するのは妥当でない。**
71R では逆予測的で、閾値引き上げ・◎オッズ下限のいずれでも実エッジを回復できない。ただし
CLAUDE.md の実ルール変更は本 ADR では行わず（資金直結・要追検証）、推奨と follow-up に留める。

#### 理由

- **ゲートは同一ポートフォリオの実 ROI を 75.5%→24.5% に半減させ、閾値を上げるほど単調に悪化
  （110% で 0%、120% で 0%）**。「model EV が高い鞍ほど当たらない」＝逆予測的。これは ADR 0041
  （馬連 model EV フィルタが逆予測的）・ADR 0033（条件付き単勝のエッジ消失）と同型で、
  「額面 model EV の閾値抽出は較正不良ゾーンでノイズを掴む」という同じ構造。
- **根本原因はゲート閾値やオッズ条件ではなく EV 入力の較正**。#246/ADR 0042 の縮約で人気馬確率が
  上がり、◎ アンカーのポートフォリオ model EV が realized を伴わずに 100% を超えるようになった。
  ゲートはその水増し EV を拾っているだけで、閾値・オッズ条件の調整では救済できない。
- **無ゲート 75.5% も 100% 未満＝この窓ではモデルに実証されたエッジが無い**。したがって正しい含意は
  「ゲートを外して全部張れ」ではなく「model-EV ゲートを +EV の証として用いるな」。

#### 推奨（CLAUDE.md・実ルールへの含意。変更は別途承認）

- CLAUDE.md レース選択基準「ROI≥100% のレースだけ張る」の **model-EV ゲートを単独の +EV 判定に
  使わない**。較正後はむしろ −EV の人気馬鞍を選別する方向に働く。
- 本質対策は **EV 入力（較正の EV 反映, ADR 0042）の再校正**＝別 issue。朝 EV が直前で剥がれる既知傾向
  （morning EV is illusory）とは別軸の、ゲート自体の校正不良。
- 71R 単一窓・発動小標本（13/5/1）のため、**#248 の年間スナップショット蓄積後に追検証**してから
  実ルールを変更する。

#### 検証上の留保（結論の向きには影響しない）

- **単一 71R 窓・発動小標本**。gate≥100% は 13 鞍、≥110% は 5 鞍、≥120% は 1 鞍で的中率はノイジー。
  ただし「閾値を上げるほど実 ROI が単調に 0% へ向かう」方向と「無ゲート > ゲート」の大小は頑健。
- **model の ◎ が 71R ほぼ全てで市場 1 番人気**（α=0.2 ブレンドの帰結）。よって本検証は
  「人気か否か」ではなく「ゲート通過が実エッジを選べているか」を測っている。
- **盤面オッズ→締切ドリフトの残存相関**はゲートを実際より良く見せる方向。それでも崩壊する以上、
  逆予測の結論はより頑健。
- **無ゲート universe 自体が赤字（75.5% < 100%）**＝この窓にモデルの実証エッジが無い。本検証の「逆予測的」
  は赤字 universe 内での部分集合比較（ゲート通過部分集合 < 母平均）であり、エッジのある母集団での
  挙動は別問題。実ルール変更の前に #248 の年間蓄積で正の母集団も含めた追検証が必須。
- baseline は wide 抜き（履歴オッズ欠落。ADR 0041 と同じく steel-man 対照）。

#### 影響

- CLAUDE.md は変更しない（推奨の記録のみ）。`scripts/predict-check/umaren_backtest.py` にゲート診断・
  閾値/◎オッズ掃引を追加（`--gate-grid` / `--odds-floor-grid` / `--winodds`）。
- EV 入力の再校正（ADR 0042 再設計）と #248 蓄積後の追検証を follow-up とする。

> follow-up: ADR 0045（#270）で本逆予測性を純 Python で再現し、α×γ 同時再検証フレームワークを整備（暫定知見）。

### ADR 0046: 配分の確率重み化＋脚ごと最低¥100撤廃（71R で実 ROI 悪化・棄却） (2026-06-28) — 棄却

#### ステータス

棄却（CLAUDE.md・コードの配分は現状の均等割りを維持。確率重み化＋最低¥100撤廃は採用しない）

#### コンテキスト

#272 の買い方見直しで、配分（券種内の各脚への賭け金の振り分け）の解釈が論点になった。

- ユーザー指摘: CLAUDE.md「各点の金額は組合せの確率で重み付け」「薄い相手も最低 ¥100 置いて取りこぼしを
  防ぐ」のうち、**「¥100 は馬券の額面単位であって、薄い脚に必ず ¥100 を置けという意味ではない」**。
  会話初期にはこの「薄い相手も最低¥100」の spread が **EV 希釈の主因**ではないかとも疑われていた。
- 現状の乖離: 実装コードの券種内配分は**均等割り**（`distribute`）で、CLAUDE.md が謳う「確率重み＋最大剰余」
  とも一致していない（どちらも実 ROI は後述のとおり同等）。

そこで「券種内配分を**真の的中確率で重み付け**し、**脚ごとの最低¥100（spread）を撤廃**して薄い脚は ¥0
（買わない）にする」案を検証した。総賭金は方式に依らず一定（券種予算ちょうど）なので、差は純粋に
「どの脚に厚く張るか」だけに由来する。

#### 検証設計

`umaren_backtest.py` の baseline ポートフォリオ（馬連 ◎軸ながし top5 ¥1500 + 三連複 ◎軸ながし top5
¥2000、wide 除外）を土台に、券種内配分方式だけを変えて 71R（2026-05-30〜06-14, /tmp/bt252,
α=0.2・m=10）の実 ROI を比較した。全鞍機械買い・ゲート無し（配分効果の分離）。清算は netkeiba 実払戻。

- 重み基準: `proxy`（勝率: 馬連=probs[p] / 三連複=probs[a]*probs[b]）vs `true`（真の的中確率:
  馬連=P(軸·相手が上位2着) / 三連複=P(3頭が上位3着), simulate 由来）vs `equal`（均等）。
- 最低口数 `minu`: 1（脚ごと最低¥100）vs 0（撤廃・薄い脚は¥0）。

#### バックテスト結果（同一ポートフォリオ・総賭金一定・71R）

| 配分方式 | 実 ROI | 的中率 |
|---|---|---|
| proxy 重み + minu=1（**現行ルール相当**）| **75.5%** | 48% |
| equal 均等 + minu=0（**現行コード実挙動**）| **75.5%** | 48% |
| true 的中確率重み + minu=1 | 71.1% | 48% |
| proxy 重み + minu=0（最低¥100 撤廃のみ）| 66.4% | 48% |
| true 的中確率重み + minu=0（**検討した変更**）| **66.3%** | 48% |

- 最低¥100 の撤廃だけで **−9pt**（75.5→66.4）、重み基準を真確率にするだけで **−4pt**（75.5→71.1）。
  両方やった検討案が最悪（66.3%）。的中率は全方式 48% で不変（総賭金一定・賭ける鞍も同一のため）。

#### 決定

**配分は現状（均等割り）を維持し、確率重み化＋脚ごと最低¥100撤廃は採用しない。**

#### 理由

- **薄い脚への少額 spread は実 ROI を上げている**。三連複の薄い穴目への ¥100 ずつが「たまに来る高配当を
  拾うミニボックス」として機能し、本命集中（低配当寄せ）に変えると一発を取り逃す。ADR 0030（相手拡大で
  回収悪化）の裏返しで、こちらは「薄い脚を削ると回収悪化」。
- 「¥100 は額面単位であって脚ごとの下限ではない」という**解釈は正しい**が、それを「薄い脚は¥0」と実装
  すると**この窓では負ける**。解釈の正しさと回収率が逆を向く。
- 現行コードの均等割り（75.5%）と CLAUDE.md の確率重み＋¥100（75.5% 相当）は実 ROI 同等。**変える動機が
  回収率側に無い**。

#### 影響

- コード: `src/domain/src/portfolio/mod.rs` の券種内配分は均等割り（`distribute`）を維持。本 #272 では
  各買い目の**的中確率 `hit_prob` を算出・表示**する（判断材料）のみ追加し、配分は不変。
- CLAUDE.md: 配分ルールは変更しない。
- `docs/specifications/betting-rule-history.md` に棄却記録として追記。

#### 検証上の留保（結論の向きには影響しない）

- **単一 71R 窓**。ただし「集中（minu=0）にするほど実 ROI が下がる」方向は proxy/true 両基準で一貫。
- wide 除外（履歴オッズ欠落。ADR 0041 と同じ steel-man 対照）。
- 無ゲート universe 自体が 75.5% < 100%＝この窓にモデルの実証エッジは無い（ADR 0044 と同様）。本件は
  その universe 内での配分方式の相対比較。

#### 再現方法

```sh

python3 scripts/predict-check/alloc_compare.py
# 期待出力: proxy+minu1=75.5% / equal+minu0=75.5% / true+minu1=71.1% / proxy+minu0=66.4% / true+minu0=66.3%
```

### ADR 0054: fractional Kelly 配分による買い方最適化の棄却（#316 / #272 配下） (2026-06-30) — 棄却

#### ステータス

棄却（production の配分は現行ヒューリスティック＝最大剰余法・固定予算・最低¥100 を維持。
CLAUDE.md「買い方ルール」不変）

#### コンテキスト

#272（予測フロー再設計）配下で、確率モデルのレバーが枯渇した（ADR 0052/0053）後に残る別軸
「賭け方（staking）」を検証した。現行の買い目配分は経験則（券種固定予算・確率重み・最低¥100 確保の
最大剰余法）で、確率とオッズに対する理論最適配分（fractional Kelly）になっていない。#316 は
「同じ確率でも配分を Kelly 最適化すれば長期 ROI を底上げできる」仮説を、リーク無し walk-forward で
現行ヒューリスティックと比較し、採否を本 ADR に残す（#309/0052/0053 と同じ棄却規律）。

Kelly 式は本番 Rust `src/domain/src/betting/kelly.rs`（ADR 0003、net odds `b=gross-1`,
`f=(p·b−q)/b`, clamp）に実装済みだが、**本番の買い目配分では未使用**（live_ev.py / predict-check は
ヒューリスティック）。本 ADR はこの Kelly を実際の配分に使った場合の損益を測る。

#### 検証（71R / `/tmp/bt252` walk-forward・`scripts/predict-check/kelly_compare.py`）

候補ユニバースを現行 baseline_pf（馬連◎軸ながし top5 + 三連複◎軸ながし top5）に固定し、配分方式だけを
変えて比較した。EV/Kelly 判定は DB 盤面オッズ、清算は result.html 実配当で分離（循環回避、umaren_backtest と同方針）。

**(A) 定額土俵**（総賭金を現行と同額 ¥3,500/R に固定し、券種内の重みだけ確率重み→Kelly 比率に置換）:

| 配分方式 | 実ROI | 的中 | σ(per-race ROI) |
|---|---|---|---|
| 現行（確率重み） | **75.5%** | 48% | **92.5** |
| Kelly 重み | 65.9% | 48% | 123.8 |

**(B) bankroll 土俵**（開始 ¥100,000・71R 時系列・実払戻清算。現行=固定¥3,500/R flat 張り vs
fractional Kelly λ=λ·Σf_leg·bankroll）:

| 戦略 | 最終資金倍率 | 実ROI(per-yen) | 的中 | maxDD | 近似破産率 |
|---|---|---|---|---|---|
| 現行（flat ¥3,500） | 0.39x | 75.5% | 48% | 61.1% | 1.5% |
| Kelly λ=0.25 | 0.57x | 40.6% | 9% | 46.9% | 0.0% |
| Kelly λ=0.5 | 0.33x | 39.9% | 10% | 71.4% | 0.1% |
| Kelly λ=1（full） | 0.08x | 31.8% | 11% | 93.9% | **100%** |

（最終資金倍率・実 ROI・的中・maxDD は実時系列 1 経路の実現値。破産率＝レース順 2000 本の
順列リサンプル〔permutation・非復元。統計的ブートストラップ＝復元抽出ではない〕で残高が
開始×0.2 以下に到達した経路の割合で、順序による経路リスクの近似。）

**観察**:

- **定額土俵では Kelly 重みが現行に劣る**（ROI 65.9% < 75.5%、σ も 123.8 > 92.5 と悪化）。同一総額・同一
  候補・同一オッズで「どの脚に厚く張るか」だけを変えた apples-to-apples 比較で、Kelly 重みは回収率・分散とも負け。
- **full Kelly（λ=1）はほぼ確実に破産**（破産率 100%・最終 0.08x・maxDD 93.9%）。issue 補足「確率推定に
  系統誤差があると過剰張りで破産を早める」を実証。モデルの favorite-longshot ミスキャリブレーション
  （#246・ADR 0047/0050）が Kelly の edge 推定を歪め、過大張りに直結する。
- **fractional（λ=0.25）の最終資金 0.57x > flat 0.39x は配分改善ではない**。per-yen ROI は 40.6% と
  flat 75.5% より**悪く**、的中も 9%。これは Kelly が +EV と判定した脚だけを bankroll 比で**極小額**張る
  ため、控除率（馬連 22.5%・三連複 25.0%）による資金流出が単に遅いだけ＝実質「ほとんど見送り」。edge を
  取って増やしたのではなく「賭ける額を絞って損を遅らせた」結果で、value 捕捉の証拠ではない。

#### 決定

**fractional Kelly による配分最適化は棄却**する。production は現行ヒューリスティック配分（券種固定予算・
確率重み・最低¥100 の最大剰余法、CLAUDE.md「買い方ルール」）を維持し、変更しない。Rust `betting/kelly.rs`
は EV 候補選抜のための curation（min_kelly）用途に留め、賭け額配分には用いない（現状どおり）。

#### 理由

- 同一土俵（定額）で Kelly 重みは現行に ROI・分散とも劣る。Kelly が理論最適となる前提「確率推定が正しい」が
  本 PJ では成立せず（モデルは単勝市場に勝てない＝ADR 0053、かつ favorite-longshot 較正不良）、誤った確率に
  Kelly を適用すると過大張り（full で破産）か過小張り（fractional で実質見送り）に振れるだけで、配分の質は上がらない。
- bankroll 土俵で λ=0.25 が資金を残すのは「賭けない方向に縮む」効果で、これは既に CLAUDE.md の
  「ROI≥100% のレースだけ張る／−EV は見送る」ゲートが担っている規律と同じ。Kelly を新たに入れる便益がない。
- 既存の配分棄却履歴（相手拡大=105R 悪化 / 配分 floor 除去=71R 悪化、`betting-rule-history.md`・memory
  `project_alloc_floor_finding`）と整合的に、「経験則配分を理論配分で置換しても回収率は改善しない」を再確認した。

#### 影響 / 留保

- production・既存挙動とも不変。本 ADR は「現行配分維持」の根拠を数値で固定する記録。
- **リーク（common-mode）**: bt_pred の確率は `analyze predict` 由来で過去走較正にリークの可能性
  （memory `alpha_sign_and_predict_leak`）。ただし全配分方式が同一 probs を共有するため、相対比較
  （Kelly vs 現行）にはキャンセルして影響しない。確率の絶対精度ではなく配分方式の優劣を測る本 ADR では妥当。
- **単一窓・71R（約 8 開催日）で検出力は限定的**。ただし (1) 定額土俵で Kelly が現行に明確に劣り、(2) full
  Kelly が破産する向きは確率較正不良から理論的にも予期され、(3) 既存の配分棄却知見と整合するため、棄却の
  向きは頑健と判断する。確定的な配分再設計には複数窓を要するが、本 ADR の主張は「Kelly 置換の棄却」に限定。
- **ゲートの注記**: bankroll 土俵の flat は全鞍機械買い（ROI≥100% ゲート無し）で、61% の資金流出は「毎レース
  −EV を張ると負ける」事実を反映する。実運用はゲートで −EV を見送るため flat より良い。Kelly の自己縮小も
  同じ −EV 回避に帰着し、ゲート済み運用に対する追加便益は無い。
- **同時 Kelly の近似（破産方向に保守的）**: bankroll 土俵の Kelly は脚ごとの分数 f_leg を単純加算する
  （Σf_leg）。同一レースの馬連・三連複は ◎を共有し結果が相互排他/相関するため、真の同時 Kelly はこれより
  小さい。素朴加算は過大張り側に振れ full Kelly の破産規模を増幅しうるが、これは「Kelly は危険」という棄却
  結論に対して保守的な向き（実際の同時最適でも改善には至らない）。相関考慮版は follow-up（issue 補足どおり）。
- **定額土俵の +EV 脚ゼロ鞍**: (A) は毎レース ¥3,500 を必ず張る枠組みのため、+EV 脚が 1 本も無い鞍では
  Kelly 重みが全 0 になり一様配分へ縮退する（Kelly 本来の「張らない」挙動とは乖離）。Kelly の自己縮小を
  忠実に測るのは (B) bankroll 土俵で、両土俵が揃って棄却を支持する。
- value シグナル自体（穴の高オッズ的中由来の ROI）の真偽は #305/#314 系に委ね、本 ADR は配分方式の優劣に限定。

### ADR 0065: ワイド相手頭数を top5 に統一（doc↔実装の乖離解消 — top3/top5 は有意差なし） (2026-07-06) — 採用

#### ステータス

採用（accept）。`build_portfolio` は無変更（既に全券種 top5）。CLAUDE.md の買い方ルールを「ワイドは相手 top3」から「3 券種とも top5」へ修正し、doc を実装＝実測結果に一致させた。

#### コンテキスト

CLAUDE.md 買い方ルールは「**ワイドは相手 top3 / 馬連・3連複は相手 top5**」と定めていた。一方、本番の
`build_portfolio`（`src/domain/src/portfolio/mod.rs`）は単一の `PortfolioConfig.partners`(=5) を全券種へ適用し、
**ワイドも相手 top5** で組んでいた。券種別の相手頭数フィールドは実装に存在せず、**doc とコードが乖離**していた。

「ワイド top3」の出所は ADR 0030 の混戦バックテスト（`konsen_backtest.py`）の baseline 実装が偶々 `wp=parts[:3]`
だっただけで、production の買い方構造（軸流し・券種別予算配分）で **ワイド top3 vs top5 を直接比較した根拠は
リポジトリ内に存在しなかった**。つまり乖離しているのは build_portfolio 側だが、それが検証済み構成から外れて
いるのか、doc の top3 が過剰な思い込みなのかが未確定だった（#347）。

安易にどちらかへ寄せず、**先に計測して決める（measurement-first）**方針を採った。

#### 検証方法

- **ハーネス**: `scripts/predict-check/strategy_eval.py`。買い方（軸選定・券種別予算 `budget*w//total_w//100*100`・
  点数・1点¥100 丸め distribute・組番形式）は `build_portfolio` と等価であることを確認済み → ROI を production
  挙動の忠実な代理として使える。本 ADR 用に券種別相手頭数フラグ `--wide-partners`（ワイドだけ別 K・既定は
  `--partners` に追従）と、多日集計用の `--json` 出力を追加した。
- **リーク中立性**: ワイド top3 vs top5 は**予測確率不変・相手の絞りのみ変化**。preds はオッズブレンド由来の
  リーク（`analyze predict` は all-time 統計＝未来込み。単勝 ROI が 189〜594% と非現実的なのはこのため）を含むが、
  両条件に等しく効くため**相対比較（どちらが上か）はリーク中立**。ROI 絶対値は信用せず、差分と符号の安定性で判断。
- **突合キー**: strategy_eval は `(venue, race_num)` で突合し日付を含まないため、複数開催日を 1 run に混ぜると
  同一 venue+race_num が衝突する。**開催日ごとに run して合算**した（`agg347.py` / `perday347.py`）。
- **データ**: `gen_win_backtest_data.sh`（production 既定 α=0.2・m=10）で生成。窓は 2 段階。

#### 結果

##### 窓 A（71R / 4 開催日 2026-05-30〜06-14）

| 戦略 | wide=5 | wide=3 | Δ(3−5) |
|---|---|---|---|
| 本命軸 馬連+ワイド流し | 114.0% | 118.0% | **+4.0pt**（top3 有利） |
| 本命軸 馬連+ワイド+三連複流し | 93.4% | 96.5% | +3.1pt |

top3 が僅かに上に見えたが、この窓は単勝 ROI 594% の**幸運な小標本**だった。事前合意「差が微妙なら窓を
広げる」に従い N を拡大。

##### 窓 B（262R 実測 / 290R 延べ / 12 開催日 2026-03-15〜07-05）

| 戦略 | wide=5 | wide=3 | Δ(3−5) |
|---|---|---|---|
| 本命軸 馬連+ワイド流し | 82.6% | 78.8% | **−3.9pt**（top5 有利） |
| 本命軸 馬連+ワイド+三連複流し | 75.4% | 72.5% | −2.9pt |

（各セルは独立に小数第1位へ丸めた表示値。Δ は丸め前の生 ROI 差から算出しているため、表示値どうしの
引き算とは末尾 0.1pt 程度ずれうる。例: 78.8−82.6=−3.8 だが生値差は −3.9。）

**N を増やすと符号が反転**した（A の top3 優位はノイズ）。さらに日別で見ると:

- **top5 ≥ top3 は 6/12 日、top3 > top5 は 6/12 日＝完全に五分**。
- 日別 Δ(3−5): +21 +4 −18 +3 +4 +8 +10 −14 **−32** −6 −4 −1（符号バラバラ）。
- B 窓集計の top5 優位（−3.9pt）は実質**単一の外れ日 2026-06-27（Δ−32pt / 34R）が牽引**しており、
  これを除けばほぼゼロ。

#### 決定

**ワイド top3 vs top5 に安定した有意差は無い**（ノイズ支配・符号は標本と単一外れ日に依存）。有意差が無い以上、
**最小変更**を選ぶ:

- `build_portfolio` は**無変更**（既に全券種 top5）。ビュー表示（軸込み 6 頭のワイド）も現状維持。
- CLAUDE.md を「**3 券種とも相手 top5**」へ修正し、doc を実装＝実測に一致させる。「ワイド top3」という
  未検証の縛りは撤去。
- 買い方の広さは **top5 が上限**（ADR 0030「相手を top5 より広げると悪化」は不変）。ワイドを top5 にするのは
  上限に合わせるだけで、これと矛盾しない。むしろ CLAUDE.md「印を打った馬は必ず買い目に絡める」「保険構造」
  とも整合する（ワイドも印馬を広く拾える）。

なお AI の買い目提案は相手 top5 に絞るが、レース盤ビューは軸込み 6 頭を提示し、**最終判断（張る/見送り/増額）は
人間**に委ねる decision-support（ADR 0055/0060 の軸ロック運用と整合）。

### ADR 0076: EV 層分離後の参考ROIは ROI ゲート 100% の判定指標として使えない（182R 実測・知見） (2026-08-12) — 知見

#### ステータス

知見（CLAUDE.md のライブ買い方ルールと `predict-watch` の実装は本 ADR では変更しない。
資金直結のため、ゲートの実変更は追検証とユーザー承認を前提に別 issue で行う。ADR 0044 / 0045 と同じ扱い）

#### コンテキスト

ADR 0055（EV 層分離・循環断ち）以降、`predict-watch` / `predict --overview` の参考ROIは
**軸/相手は blended（α=0.2）で選び、EV は pure（α=1.0）× 市場オッズで評価する** 2 系統構成になった。
これは市場オッズと独立な確率で EV を coherent に計算するための意図的な設計で、その点は妥当。

問題は、**その指標に対して張る/見送りのゲートが 100% に置かれたまま**で、現行定義での較正が
一度も測られていないことだった（#571）。ADR 0044 / 0045 の 71R 検証は**分離前**の EV 定義
（blended α=0.2 の確率・ワイド抜き・確率重み配分）を測ったもので、現行定義には適用できない。

`live_ev_snapshots`（`predict-watch` が各スイープで記録した判定ROIと買い目伝票）を確認すると、
疑いは #571 本文より強い形で裏づけられた: **182 レース / 839 スイープ / 8 開催日のすべてで ROI < 100%**
（範囲 7.5〜82.1%）。記録が始まって以来ゲートは一度も発火していない。

#### 検証設計

`scripts/predict-check/gate_calibration.py`（新規）:

- **母集団**: `live_ev_snapshots` の 182 レース（2026-07-11〜08-09・8 開催日）。この窓は EV 層分離
  （`4b93679` 2026-06-30）と混戦ボックス（`c6ec8d0` 2026-07-07）の後で、全期間が現行ロジック。
- **代表スイープ**: 発走前の最終（`captured_at ≤ post_time`）。182/182 で採れた。
- **買い目**: Rust `build_portfolio` が組んだ伝票（`slip`）そのもの。Python で組み直さない
  （ADR 0064 が警告する買い方ロジックの second source を作らない）。
- **循環回避**: 判定に使った盤面オッズと、清算に使う netkeiba 確定払戻を分離する（ADR 0041 / 0044 と同方針）。
- **市場整合ROI**: 各券種の全組オッズから `q_i = (1/O_i) × W / Σ_j(1/O_j)`（W = 的中組数。
  馬連/3連複=1・ワイド=3）で market-implied 確率を作り、**同じ伝票**を評価する。この正規化なら
  どんな買い方でも `W/Σ(1/O)` ＝ 1−控除率 に一致するので、`判定ROI ÷ 市場整合ROI` が
  「pure モデルが選ばれた脚を市場の何倍で値付けしているか」を直接与える。
  実データで馬連 77.2% / ワイド 77.5% / 3連複 74.9% と JRA 公称控除率を再現しており、測定器自体が検算できている。
- **判定基準**: ADR 0045 の定義を踏襲。逆予測性の解消 = `Spearman(判定, 実現) ≥ 0` かつ
  上位帯の実現ROI ≥ 全体平均。

#### 測定結果（182R・生データは [571-roi-gate-calibration.md](571-roi-gate-calibration.md)）

| 指標 | 値 |
|---|---|
| 実現ROI（無ゲート全体） | **69.5%**（bootstrap 95% CI 56.6〜83.2%）／上位 5 鞍を除くと 60.7% |
| 判定ROI 平均 | 23.2%（最小 7.5% / 最大 76.8%・**100% 到達 0 件**） |
| 市場整合ROI（＝1−控除率） | 77.0% |
| **判定ROI ÷ 市場整合ROI** | **0.30** |
| Spearman(判定ROI, 実現ROI) | **+0.002** |

較正バケット:

| 判定ROI 帯 | n | 判定ROI | 実現ROI | 的中率 |
|---|---|---|---|---|
| <20% | 98 | 15.3% | 72.4% | 61% |
| 20–40% | 66 | 27.0% | 65.3% | 53% |
| 40–60% | 14 | 46.7% | 56.4% | 50% |
| 60–80% | 4 | 70.1% | 111.2% | 100% |
| ≥80% | 0 | — | — | — |

判定ROI ≥ θ で絞ったときの実現ROI（**非単調**）:

| θ | 0% | 20% | 30% | 40% | 50% | 60% | 70% | 80% |
|---|---|---|---|---|---|---|---|---|
| n | 182 | 84 | 37 | 18 | 7 | 4 | 2 | 0 |
| 実現ROI | 69.5% | 66.0% | 80.7% | 68.6% | 63.6% | 111.2% | 78.5% | — |

##### 代表スイープの取り方に対する頑健性

本測定は発走前の**最終**スイープを代表に採る（CLAUDE.md「EV/ROI 判定は発走直前のフレッシュなオッズで行う」に従う）。
「都合の悪いスイープを選んだのでは」を潰すため、各レースの**全スイープ中で最も判定ROIが高い**行を採る
`--ever` でも測った（＝モデルに最も有利な読み方）。結論は変わらない:

| 代表スイープ | 判定ROI 平均 / 最大 | ゲート通過 | 実現ROI | Spearman | 判定 ÷ 市場整合 |
|---|---|---|---|---|---|
| final（本測定） | 23.2% / 76.8% | 0 件 | 69.5% | +0.002 | 0.30 |
| ever（最も有利） | 26.5% / **82.1%** | **0 件** | 74.8% | +0.012 | 0.34 |

ever でも 100% には届かず、Spearman はゼロ近傍のまま、実現ROIは市場整合 77.0% に張り付く。

#### 決定（知見）

**現行定義の参考ROIは、レースを選別するゲート指標として使えない。**

1. **スケールのズレは閾値のズレではなく定義の不整合**。判定ROI は市場整合ROI の 0.30 倍。
   買い目の脚は blended（市場優位）で選ばれるのに、EV は市場情報を捨てた pure 確率で値付けされる。
   pure は本命をフラットにしか出せない（ADR 0058 / 0059）ので、**選ばれた脚が構造的に低く出る**。
2. **#571 要件の (a) 閾値較正は成立しない**。「実現 100% に相当する判定ROI 値」が存在しない。
   θ を下げても実現ROIは 100% に届かず（θ=30% で 37 鞍・80.7% が最良）、閾値表は非単調。
   n が小さい帯（θ≥60% で n=4、θ≥70% で n=2）が 100% を超えるのはノイズ。
3. **(b) 較正済みROI の併記も支持されない**。写像は単調な関係を前提とするが `Spearman = +0.002`＝
   関係が無い。定数倍で水準だけ合わせても順位付けの力は生まれず、実質 1−控除率 を再導出するに等しい。
4. **(c)「現行のまま＝滅多に発火しないのは仕様」も採らない**。「滅多に」ではなく**構造的に到達不能**で、
   CLAUDE.md / REQ-D01-001 の「ROI ≥ 100% のレースだけ張る」は現状**満たしようのない運用指示**になっている。

**この窓にモデルの実証エッジは無い**。無ゲート 69.5% は市場整合 77.0% と bootstrap CI 内で区別がつかず、
ポートフォリオは「市場から控除率ぶん負けるだけのふつうの賭け」と同じ挙動をしている
（ADR 0044 の 71R 窓の無ゲート 75.5% と同水準）。

#### 理由

- **逆予測ではなく無情報**。ADR 0044 / 0045（分離前定義）は Spearman −0.167 で**逆予測的**だった。
  分離後は +0.002 で、判定ROIは実現ROIを正しくも誤ってもランク付けしない。EV 層分離は
  「高い EV ほど当たらない」病理は取り除いたが、**選別力を与えてはいない**。
- **控除率の壁**。ゲート 100% は「市場を 30% 上回る」ことを要求する。純モデルの resolution は
  天井に達しており（ADR 0058 / 0059・`project_resolution_data_ceiling`）、市場の動的情報も
  クロージングに吸収される（ADR 0067）。この要求を満たす材料は現時点で存在しない。
- **ゲートを下げる方向は既に棄却済み**（ADR 0040）。本測定も θ を下げて張る本数を増やす方向を支持しない。
- 結論は ADR 0055 決定 4（predict-watch を decision-support 化＝自動の張る/見送り判定を出さない）と
  ADR 0060（エッジは "当てる精度" でなく買い方＝執行の規律に置く）と整合する。本 ADR はその方針を
  **実測で裏づけた**ものであり、新しい方向を提案するものではない。

#### 却下した案

- **ゲート閾値を実現 100% 相当へ較正する（#571 (a)）** — 該当する判定ROI 値が存在しない。
- **較正済みROI を併記しゲートをそちらに掛ける（#571 (b)）** — Spearman ≈ 0 で写像の前提が無い。
- **ゲートを下げて張る本数を増やす** — ADR 0040 で棄却済み。本測定でも θ=30% で 80.7%（<100%）。
- **母集団を 467R（連系 3 券種のオッズが揃う全レース）へ広げてから判断する** — 判定ROIが記録されていない
  レースは `build_portfolio` をリークなしに再生成する経路（`analyze backtest` への新設）が要る。
  182R で符号と大きさが明確に出たため、本 ADR では 182R で結論を出し、拡張は必要が生じたときの follow-up とする。

#### 検証上の留保

- **単一窓 n=182**（2026-07-11〜08-09・夏開催）。ADR 0045 が 71R に付けた過学習の留保は緩むが消えない。
  ただし「判定ROIが 100% に一度も届かない」「判定ROI ÷ 市場整合ROI ≈ 0.30」は分散でなく構造の話で、
  標本数に対して頑健。
- **実現ROI は外れ値に強く依存する**。上位 5 鞍を除くと 69.5% → 60.7%。点推定だけを読まない。
- **8 開催日のうち 07-26 は n=2** と極端に薄い（監視が短時間しか回っていない日）。日別の解釈に使わない。
- 本測定は `predict-watch` の記録に基づくので、**監視が回らなかったレースは母集団に入らない**。
  スリープ等で記録が飛んだ区間（#568）は測れていない。

### ADR 0080: 既定の券種配分を円建て 1500:1500:2000 にする（ADR 0019 の 1:1:1 を supersede・採用） (2026-08-12) — 採用

#### ステータス

採用（`PortfolioConfig::default().alloc` を変更する。**[ADR 0019](0019-portfolio-generator.md) の
「既定値（相手 5 頭・配分 1:1:1）」のうち配分だけを supersede する**。相手 5 頭は変えない）

#### コンテキスト

ADR 0076（#571）の較正測定の副産物として、**¥5,000 の予算に対し実賭金が ¥4,000 しか無い**ことが
判明した（#600）。`live_ev_snapshots` の 839 スイープ中 **835 本が ¥4,000**（残り 4 本は ¥4,200）。

原因は既定配分 `(1, 1, 1)` と 2 段の 100 円 floor:

| 段 | 計算 | 損失 |
|---|---|---|
| 券種予算 | `5000 × 1/3 = 1666 → 1600`（×3 券種） | ¥200 |
| 馬連・ワイドの脚単価 | `1600 / 5 = 320 → 300`（×5 点） | ¥100 × 2 |
| 3 連複の脚単価 | `1600 / 10 = 160 → 100`（×10 点） | ¥600 |
| | **合計** | **¥1,000** |

一方 `CLAUDE.md`「予算・配分（既定）」と REQ-D23-003 は **ワイド ¥1,500 / 馬連 ¥1,500 /
3 連複 ¥2,000**（= 3:3:4）と書いており、doc と実装が食い違っていた。

**ただし「doc が正しい」と単純には言えない。** ADR 0019 は
「既定値（相手 5 頭・**配分 1:1:1**）は固定だが、PR1 の `strategy_eval.py` で相手頭数・配分の
感度を…」と明記しており、**実装は自分の ADR に従っていた**。CLAUDE.md の 3:3:4 に ADR の裏づけは
無く、由来はバックテスト baseline の金額（馬連 ¥1,500 ＋ 3 連複 ¥2,000・ワイド除外。ADR 0041 /
0044 / 0046 の検証土俵）。つまり doc↔ADR↔実装の三つ巴だった。

#### 検証設計

`scripts/predict-check/gate_calibration.py` に `--compare-alloc` を追加した。
**記録済みの脚（どの組番を買ったか）はそのままに、金額だけ再配分**して確定払戻で再精算する。
配分は脚の選定に影響しないので、この再計算は正当（脚を組み直さないので
ADR 0064 の警告する買い方ロジックの second source にもならない）。

`distribute` は Rust `portfolio::distribute` の 2 段 floor を鏡映する。**旧既定 `(1,1,1)` を
渡すと「記録どおり」と完全一致する**ので、鏡映の忠実性は実データで自己検証できる。

母集団は ADR 0076 と同じ 182 レース（2026-07-11〜08-09）。混戦レースは `KONSEN_ALLOC`（4 レイヤー）で
組まれており 3 要素の alloc では再現できないため対象外（当該窓の発走前最終スイープには混戦 0 件）。

#### 測定結果（182R・脚は固定・金額のみ入れ替え）

| 配分 (馬連,ワイド,3連複) | 賭金 | 払戻 | 実現ROI | 1R 平均 |
|---|---|---|---|---|
| 記録どおり | ¥728,000 | ¥505,690 | **69.5%** | ¥4,000 |
| 1,1,1（旧既定） | ¥728,000 | ¥505,690 | 69.5% | ¥4,000 |
| **1500,1500,2000** | ¥910,000 | ¥621,440 | **68.3%** | **¥5,000** |

差は 3 連複の重みが倍（¥1,000 → ¥2,000）になるぶんだけで、この窓では 3 連複が最弱（63.6%）
なので 1.2pt 下がる。ADR 0076 の bootstrap 95% CI は 56.6〜83.2% なのでノイズの範囲。

#### 決定

**既定配分を円建ての `(1500, 1500, 2000)` にする**（`(連系ペア, ワイド, 三連複)` の順）。
`race_budget` にスケールする相対重みなので、¥5,000 では CLAUDE.md の金額にそのまま一致する。

#### 理由

- **¥5,000 を 100 円単位で割り切れる配分は 3:3:4 だけ。** 相手 5 頭なら脚数は 5 + 5 + 10 = 20 で、
  `1500/5 = 300`・`2000/10 = 200` はいずれも 100 円単位に乗る。1:1:1 では
  `5000/3` が 100 円単位に乗らず、どう floor しても ¥4,000 にしかならない
  ——**「予算ちょうどに収める」（CLAUDE.md 表記規約）は 3:3:4 でしか成立しない**。
- **ROI 差 1.2pt は判断材料にならない。** ADR 0076 が測ったとおりこの窓にエッジは無く
  （無ゲート 69.5% vs 市場整合 77.0%）、両方とも 100% を大きく下回る負け配分同士の比較。
  ノイズで優劣を決めるより、**運用者が読む正本（CLAUDE.md）と実装を一致させる**ほうが価値が高い。
- **ADR 0019 の 1:1:1 は測定の産物ではない。** 同 ADR 自身が「既定値は…`strategy_eval.py` で
  後追い検証・調整する」と書いており、暫定値であることを認めている。今回それを測った。
- **表現も揃う。** `KONSEN_ALLOC = (1000, 1000, 1500, 1500)` は既に円建てなので、
  非混戦だけ無次元の 1:1:1 という不揃いが解消する。

#### 却下した案

- **doc を実装（1:1:1）に寄せる** — ADR 0065（ワイド top3 → top5）の「有意差が無ければ最小変更で
  実装側に寄せる」先例にはのる。だが**¥5,000 の 20% が不執行という状態を仕様として追認する**ことになり、
  CLAUDE.md の「¥5,000/レース」「予算ちょうどに収める」を両方書き換える必要がある。
  ADR 0065 の対象（相手の頭数）と違い、こちらは**予算の執行という運用の根幹**なので同列に扱わない。
- **1:1:1 のまま端数だけ配り切る** — **不可能**。¥5,000 を 3 券種へ 100 円単位で等分できない
  （`1700/1700/1600` にしても 3 連複が `1600/10 = 160 → 100` で潰れ、やはり ¥4,000）。
  20 点へ ¥5,000 を 100 円単位で配る解は実質 300×5 + 300×5 + 200×10 ＝ 3:3:4 に帰着する。
- **確率重み配分にして端数を吸収する** — ADR 0046 が 71R の実 ROI 悪化で棄却済み。均等割りは維持する。
- **他の窓で測ってから決める** — 両方とも 100% を大きく下回る負け配分同士の比較なので、
  測っても「どちらが良いか」は決まらない見込み（ADR 0076）。決め手は実行可能性（割り切れるか）。

#### 影響

- `src/domain/src/portfolio/mod.rs`: `PortfolioConfig::default().alloc` を `(1500, 1500, 2000)` へ。
  既定を変えるだけで `predict` / `predict-watch` / `board` / `recommend` すべてに効く
  （いずれも `..PortfolioConfig::default()` 経由）。
- **混戦時は不変**。`KONSEN_ALLOC` を使う経路は `config.alloc` を参照しない
  （旧既定との突き合わせで回帰テストに固定した）。
- **1 レースあたりの賭金が ¥4,000 → ¥5,000 に増える**。ADR 0076 のとおり現時点でエッジは無いので、
  **この窓の水準（実現 69.5%）が続くなら 1 レースあたりの期待損失は ¥1,220 → ¥1,585 に増える**。
  これは「¥5,000/レースで張る」というルールを実際に執行する以上避けられない帰結で、
  賭金水準そのものを見直すなら別の議論（本 ADR は doc↔実装の乖離解消のみを扱う）。
- `scripts/predict-check/gate_calibration.py`: `--compare-alloc` を追加。
- REQ-D23-003 と [betting-rule-history.md](../specifications/betting-rule-history.md) を更新。

#### 検証上の留保

- **測定は 182R・単一窓**（2026-07-11〜08-09）。ただし決め手は ROI ではなく
  「100 円単位で予算を割り切れるか」という構造条件なので、窓に依存しない。
- **相手が 5 頭でない盤面では端数が残りうる**。例えば 5 頭立て（相手 4 頭）だと
  馬連 4・ワイド 4・3 連複 6 点で `1500/4 = 375 → 300`、`2000/6 = 333 → 300` となり
  合計 ¥4,200。**「予算ちょうど」が保証されるのは相手 5 頭の標準構成**で、
  少頭数レースでは従来どおり端数が出る（CLAUDE.md も「全点に ¥100 を置けない端数時のみ下回る」と書いている）。
- **実地確認は次の開催日待ち**。`gate_calibration.py` の「予算執行率」が 80.0% → 100% になることを確認する。
